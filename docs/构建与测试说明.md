## 1. 一键构建

Windows 下运行 `source\build.bat`。`build.bat` 直接位于 `source\`，不允许再增加 `source\BladeSwordQOL\` 中间目录。构建脚本优先使用 PATH、`C:\Program Files\LLVM\bin`、Visual Studio 最新实例的 `VC\Tools\Llvm\x64\bin`，不会递归扫描 ARM64 LLVM。

包根长期固定为：

```text
docs\
source\
release\
```

源码工程直接位于 `source\src\`，工具位于 `source\tools\`，配置模板已迁入 `source\config\`，主构建、验证器和独立手柄构建器均已同步。BAT 固定 UTF-8 无 BOM + CRLF；所有有正文的 `REM` 与 `echo` 行末尾必须有两个半角空格；交互构建成功和失败均暂停；传 --no-pause 时跳过暂停，构建失败保留 `source\.build\Main\` 方便诊断。

## 2. 输出

```text
release\BladeSwordQOL.asi
release\BladeSwordQOL.ini
```

以上要求仅针对当前主插件目标：PE32/i386、DLL、非零入口、导出 `InitializeASI`、Import Directory=0；该目标只有 `source\src\Main.c` 拥有 `DllMain/InitializeASI`。

2026-09-27：Controller 基础版通过 `source\build_controller.bat` 独立构建，构建说明统一见 `source\readme.md`。主 `build.bat` 已改为保留 release 其它目标，只检查自己的 ASI/INI。Controller 已完成双基线静态复核、69 项输入规则检查与两版适配回放，但两作实机验收均待完成。详细范围见《手柄模块接档说明.md》，测试步骤见《手柄实机验证说明.md》。

## 3. 构建验证

```text
cd source
python tools\verify_build.py ..\release\BladeSwordQOL.asi
```

该命令只检查主 ASI PE 属性和两份 INI 的 Display／Font／GUI 必需接口，不检查源码、docs、Hook／事件或 QOL 参数；详细能力和限制见《工具说明.md》。

## 4. EXE 深度兼容验证

```text
cd source
python tools\verify_compatibility.py <ComeOn.exe> [更多 EXE...]
```

统一入口先识别 Profile，再调用成熟的本体/外传只读验证器。

配置与机制见《自动拾取与地面物品名称说明.md》。本体／外传分别记录配置、实际覆盖范围和完整日志；旧 Probe 通过不替代当前主 ASI 验收。

1. 名称开关分别为 1／0，确认常显／原版触发，颜色、字体、背景不变。
2. Mode=0 关闭；1 仅金钱；2 加回复；3 加宝石和护身石；4 包含 Other，但仍不提前拾取飞行物。

4. IntervalMs 正数时确认首次等待和扫描节奏，0 时确认每个输入更新帧允许扫描；日志不逐帧刷出不代表未扫描。
5. 独立改变 DropDelayMs，确认每个新生命周期等待及原版落地门同时生效，0 也不绕过落地。
6. 多次掉落、切图和大量掉落下确认重新计时；背包满、距离不足沿用原版。
7. 单独关闭名称／拾取及同时关闭，核对行为与日志；签名／配置路径失败保留停止日志。
