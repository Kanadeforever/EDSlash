# 构建与测试说明

## 0. 固定包结构

本项目所有源码包和测试/编译内容包的根目录都必须严格保持三目录：

```text
docs\
source\
release\
```

`docs\` 只放中文文档；`source\BladeSwordQOL\` 放统一工程、构建脚本、模板和工具；`release\` 只放正式运行文件。包根不得再出现 `src\`、`tools\`、`template\`、`build.bat` 等第四项。验证器会把这条作为硬性结构检查。


## 1. 一键构建

Windows 下运行 `source\BladeSwordQOL\build.bat`。构建脚本优先使用 PATH、`C:\Program Files\LLVM\bin`、Visual Studio 最新实例的 `VC\Tools\Llvm\x64\bin`，不会递归扫描 ARM64 LLVM。

## 2. 输出

```text
release\BladeSwordQOL.asi
release\BladeSwordQOL.ini
```

要求：PE32/i386、DLL、非零入口、导出 `InitializeASI`、Import Directory=0；只有 `source\BladeSwordQOL\src\Main.c` 拥有 `DllMain/InitializeASI`。

## 3. 构建验证

```text
python source\BladeSwordQOL\tools\verify_build.py release\BladeSwordQOL.asi
```

检查 PE 属性、release 内容、docs 位置和编码、Profile 身份、ModuleRegistry/HookManager/EventBus、模块故障隔离与 Hook 声明回滚、两个后端共享事件、AspectRatio 8 像素算法一致性、layer1d 防回归、0x0B/0x0E 原版按压动画 root 校正、外传 Steam 红线和统一 INI/log 文件名。

## 4. EXE 深度兼容验证

```text
python source\BladeSwordQOL\tools\verify_compatibility.py <ComeOn.exe> [更多 EXE...]
```

统一入口先识别 Profile，再调用成熟的本体/外传只读验证器。

## 5. v0.1-dev1 本体实机验收

## 5.1 从旧 DisplayFix 切换到统一版

实机测试统一版时，**不要同时加载旧 `DisplayFix.asi` 和新 `BladeSwordQOL.asi`**。两者会争用同一批已知 Hook，任何“双加载”结果都没有诊断价值。

测试目录应只放统一版：

```text
BladeSwordQOL.asi
BladeSwordQOL.ini
```

旧 `DisplayFix.asi / DisplayFix.ini` 请先移出 `scripts` 或 ASI 加载目录。统一版运行日志改为 `BladeSwordQOL.log`。

1. 日志首部应显示 `BladeSwordQOL v0.1-dev1` 与本体 Profile。
2. `BaseHeight=480 + AspectRatio=16:9` 应得到 `TargetWidth=856`。
3. 最右侧竖条应保持消失。
4. Strategy 进入/退出与标题返回正常。
5. 物品/装备/技能 GUI 位置、层级、鼠标和快捷键正常。
6. HUD 重叠区按钮正常。
7. 左侧装备面板打开后单独关闭物品主窗口，面板仍在 HUD 上方且可操作。
8. 0x0B/0x0E 顶部按钮和世界点击穿透不得回归。
9. **新增重点：**鼠标按下属性/物品两个顶部圆形按钮时，应恢复原版按压/点击动画；功能仍只能切换一次，不能因为原版路径恢复后与旧 fallback 叠加成双重反转。
10. 日志若原 picker 没选 HUD，应限量出现 `主HUD按钮按压root校正`；若原版本来就选对 HUD，不要求一定出现该日志。

## 8. 本轮静态构建结论

当前封包前最终验证结果：

- 单一 `BladeSwordQOL.asi` 成功链接两个 Profile 后端；
- PE32 / i386 / DLL；
- 非零入口；
- 导出 `InitializeASI`；
- Import Directory 为 0；
- `release` 严格只有 ASI + INI；
- 本体/外传 `calculate_target_width()` 逐函数一致；
- `AspectRatio` 的 Auto 与手工比例统一进入 8 像素对齐；
- layer1d、独立面板短生命周期、0x0B/0x0E root 动画校正均由源码验证器锁定；
- ModuleRegistry 故障隔离与 Hook Claim 回滚存在；
- 外传 `ResJM.Lib / CreateWindowExA / EDIT` 红线源码仍在。
