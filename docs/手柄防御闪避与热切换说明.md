## 本轮实际范围

修复 QoL 新模块没有共用日志，以及手柄 Y 与物理鼠标右键交替时连招历史不能交接。新增原生防御 ON/OFF、方向闪避、防御受击扣费、非战斗奔跑免扣费和两个独立 INI 开关。移动前探和现有战斗解析/短缓冲保持原规则。

方案一已由用户选择：将来 LT+十字键切四套连招、LT+ABXY 必杀技两次操作，LT+右摇杆打开原版左键 GUI 的弹出菜单。用户明确原生左键菜单留到最后，本轮不实现菜单；新快捷直接施放、Y 专用套组和必杀技仍属后续布局工作，不把这些记录当成 dev6 发布功能。

## 输入接管

物理鼠标移动、按键或滚轮接管原版输入；物理 Alt/Space 也可接回其原版业务。新的手柄按键、扳机或明确摇杆操作接回手柄。稳定按住旧手柄键不夺回物理鼠标；摇杆慢慢从中立推开以及累积改变方向也能重新接管。BACK+START 仅为手柄虚拟鼠标救援模式，与本次物理鼠标战斗缺陷不同。

手柄路径保留独立历史和目标来源；交接时只同步成功动作的业务历史，不写鼠标坐标、不伪造按钮，不把插件数组装成原版链表。手柄到鼠标使用原版清理/追加历史接口，恢复真实开始/结束时刻及方向，防止交接重复推进共享套组游标，并清掉旧鼠标待重试。鼠标到手柄逐节点导入已成功历史并验证场景和受控角色。历史通知按当前输入来源走对应业务，物理鼠标路径不再被旧手柄所有权长期截获。

## 防御与闪避

LT 读取 Role+0x219 的原版防御状态，经 GuardEligibility 决定原生 opcode16 ON，释放/失焦/来源交接时发 OFF；不直接写字节强开，也不继续用虚拟 Alt。拦截原版 Alt 松开生产点仅为了阻止它覆盖手柄防御，物理来源完整保留。

LT+左摇杆推向方向：通过原版闪避核心的冷却、blocker、当前状态、活动技能和状态资格，再仅对同步的手柄请求旁路近距离 CombatTarget 门，给 state17 安装摇杆方向参考。原版方向/相邻方向尝试、碰撞、位移、成功/失败和瞬态状态继续执行；非手柄闪避完整走原版目标门。每次推杆触发一次，失败有五次有限尝试，持续不回中不无限连闪；回中再推重新触发。方向参考长度暂为 256 世界单位，不把它称作最终落点，实际方向与距离手感待实机。

## 体力开关

在插件旁 EDSlashController.ini 的 [Combat] 节配置，修改后重新启动游戏：

```ini
[Combat]
ChargeGuardOnHit=1
FreeRunOutsideCombat=1
```

ChargeGuardOnHit=1：只取消防御分支的周期扣费，原版确认受击的防御状态处理时扣除一次原周期的“角色消耗值×2”。维持原版钳制、阈值和 OFF 事件；体力耗尽后的受击逻辑仍由原版决定。值为 0 时不做受击额外扣费，并恢复原防御周期扣费。防御中不额外添加恢复机制。

FreeRunOutsideCombat=1：在原版奔跑扣费调用点检查，至少一个存活、合法敌人的原生 CombatTarget 指向受控玩家时仍按战斗扣费。最后一个敌人死亡或放弃玩家目标后免扣费；不使用玩家红圈、鼠标悬停或血条可见性，画面外仍追击的敌人继续计入。异常/损坏角色链保守按原版扣费。值为 0 时总是恢复原版奔跑扣费。只改支出，不移除原奔跑资格或耗尽退出规则。

两项只改当前受控玩家，不改 NPC；加载 Controller 后，对该玩家的手柄和物理输入同样生效。构建只补缺少的两个键，保留玩家已有开关值和其它配置；不反复重写配置。

## QoL 共用日志

新模块向同目录 BladeSwordQOL.log 追加，保留显示修复的私有缓冲和既有日志。启动记录名称常显、拾取模式、扫描间隔、落地等待、签名/安装失败或关闭状态。运行记录区分“尚未定位唯一拾取对象”和“已开始调用原版动作22”，不把调用扫描直接等同于物品已入包。常规扫描不逐帧刷日志。

目标门原字节均为 85 FF 74 6A 57 56。裸钩子非手柄路径重放 test/条件跳转及两个压栈，手柄路径额外保存 EBX 并按四参数 thiscall 安装状态，再返回原版后续。不是把包含相对跳转的原字节直接复制到另一个地址。

每作 37 个函数/局部签名及原调用目标核对通过；研究导出为 16 组函数、9 组完整基本块。参考资料、原 EXE 与用户原日志均只读。提供的修复前日志来自 dev5：Controller 1439 行，有 29 条未匹配通知；BACK+START 的两条记录依用户说明属于进场 GUI，不能作为这次战斗故障依据。QoL 55 行只有显示后端内容，源码也没有 QoL 日志入口。

## 验证与下一步

已通过现有与新增输入检查、8640 组方向组合、双版本游戏适配/战斗/历史交接、扣费开关独立组合、NPC 隔离和耗尽退出回放；裸闪避钩子在自有 32 位进程实执行，检查栈和非手柄路径。Runtime 回滚与共用日志追加 28 项通过；旧 INI 只补缺项、保留值和重复构建不改文件检查通过。主/手柄完整构建及 ASI/SDL 加载通过，均不等同原游戏实机。

实机按顺序测试：

1. 检查新 BladeSwordQOL.log 出现 [QoL] 的初始化及运行/等待信息。
2. 使用右手连招套组，Y 发动几段，再直接操作物理鼠标右键，随后重新按 Y；检查连续几轮均能接管，并查看 [输入来源]/[输入交接]。
3. 无敌人时按住 LT，检查体力不周期减少；松开停止防御。再被敌人连续攻击，逐次扣费，耗尽后行为与原版一致。
4. 无敌人和有敌人时分别 LT+左摇杆闪避，各方向检查；持续推杆不自动连续闪，回中再推可再闪，撞墙保持原版处理。
5. 无敌人追击时跑步，体力不因奔跑扣费；敌人开始追击后恢复原扣费，最后一个死亡/放弃后恢复免费。
6. 两个开关分别设为 0，重启后逐项确认恢复原版规则，不影响另一个开关。

实际攻击类别、多段命中、受击方向、低体力和复杂地形必须继续实机覆盖。方向参考手感未冻结；LT 原生左键弹出菜单、必杀技、快捷直施放/Y 专用套组仍后置。不要用仅离线通过称为双版本全功能实机验收。

## dev7 后续修正（当前优先）

用户确认交接与本体防御；闪避位移失败，暂不修。奔跑改成FreeRun全程免支出，实伤恢复与GuardHitCost/AttackHitRecovery幅度公开。RT/RB直发和Y独立套组已实现。外传真实受击入口为0x422360，对应Getter CALL为0x4224D4，旧表0x422315不在正确受击函数，本轮纠正。dev6参数和未实施项以《手柄快捷施放与体力规则说明.md》为准。


当前源码补充（2026-10-01，尚未发布）：GuardHitCost 与 AttackHitRecovery 的非负配置按角色最大体力百分比解析，范围 0 到 100.00，最多两位小数；12.50 表示 12.50%，最大体力 200 时对应 25 点。-1 保留原周期默认／恢复跟随扣费。每次事件通过角色虚表 +0x80 查询当前最大体力，不按当前剩余体力或原周期倍率计算。本文原 dev7 固定点数描述仅对应已发布历史基线。内部验证包已通过输入 88 项、连续方向 8640 组、双版本宿主 3480 项及 ASI/SDL 加载检查；不代表实机通过，release 仍为验收基线。
