# 手柄战斗衔接机制与故障分析

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 原生历史与衔接规则

解析失败时，若历史已结束，原版清理历史并再尝试；本体0x47546B..0x475473、外传0x483CEB..0x483CF3。缺少该分支会让不匹配历史持续阻挡混合预设首招，直到历史超时。

Runtime结束时同步通知历史：本体0x4699D0→0x475060，外传0x477630→0x4838E0。只在下一帧轮询ActiveRuntime为空会错过同帧结束并续段的窗口。

## 当前请求处理

- 接入两版原生结束通知，保留非手柄来源的原处理。
- 恢复“已结束历史不匹配→清历史→下一次重试”的规则。
- 新按键可替换旧等待请求，按新边沿决定左右手；两键同时保持时延续最后一次新边沿，不在下一帧固定切回 Y；首次尝试不被笼统 busy 门吞掉，但不手工取消 Runtime，原版仍决定是否能衔接。
- 初次尝试后最多五个后续更新周期重试，忙碌也消耗预算；资格暂时不满足时保留剩余次数，不无限积压。
- 去掉统一 100 ms 自动重复门。按住时仅在原版空闲且无待处理请求时再尝试。
- 分开 pending 与 issued 的来源，并用实际选择组匹配动作通知；不匹配的通知只记录，不推进手柄历史/右手预设。

## 验证与诊断

宿主覆盖首招时间条件0、X→Y/Y→X、混合预设循环、同帧结束、迟到通知。固定招式回放不能代替真实角色资源和动作窗口。原日志中的未匹配动作通知用于核对来源，不能直接判断重复执行或某种游戏机制。

本体衔接改善有用户确认，具体阶段日志见更新记录；不得扩成全角色、全技能和外传全部覆盖。保留已认可移动、方向投影和鼠标模式回归；无关改动不进入此模块。
