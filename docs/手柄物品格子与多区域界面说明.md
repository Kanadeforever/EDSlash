# 手柄物品格子与多区域界面说明

## 第一批操作与范围

两作同时接入六类原生面板：背包JM14、储物箱JMB4、商店JM56、合成JM3D、镶嵌JM3E、护身石JM5B。背包/仓库/商品都是10列×5行、50格；后三类分别用原7/12/5个槽控件。按原类型和登记对象识别，不从“乾坤袋”“聚宝盆”等可见名称推测业务。快捷栏十二格已接入；装备独立区域仍待接入；用户已确认镶嵌/乾坤袋等二级菜单与购买可正常操作；未覆盖物品类型和脚本效果仍待实机。

| 操作 | 格子区 | 面板按钮区 |
|---|---|---|
| 十字键／左摇杆 | 按二维相邻方向选格，边缘保持，不串到下一行 | 按实际控件几何选按钮，隐藏按钮不选 |
| A | 原生拿起／放置／交换，原数量、堆叠和资格处理保留 | 原按钮业务；按钮区的格号为-1，不顺带操作旧格 |
| X | 循环聚焦已显示六类面板和十二快捷格，跳过隐藏页；镶嵌会话仅道具箱/镶嵌/快捷格 | 同左；不打开隐藏面板、不使用物品 |
| Y | 切到面板按钮区 | 回到格子区，恢复该面板之前的格号 |
| B／START | 有持有物品时先放回，保持窗口；没有持有物品才原关闭当前面板 | 同左，按当前操作状态取消／关闭 |
| BACK | 道具箱格子区原丢弃当前物品／持有物，空格无动作，其它物品页不丢弃 | 无动作 |
| LB／RB | 仅日志/招式有效；物品页不操作 | 同左；商店买卖通过Y切按钮区再A选择 |

X切焦点与Y切区域按用户确认的方案。原右键使用／自动转移没有绑定到X；当前可用A拿起物品，X切到另一已打开面板，再A放置。切页、切区、确认或取消后先释放输入，旧按键不会泄漏世界攻击／投掷／技能／药品。

面板按钮复用原A：背包15/16/17/5A，储物箱B5/B6，商店57/58/59，合成3F/40，镶嵌48；护身石没有独立按钮区域，Y不会把焦点切进空区。资金数字编辑尚未完成。快捷格空手显示原动态选择框，动作菜单使用同框边缘片段拼接；格子/技能方形图标使用Runtime内框，按钮区/确认项保留原指针；持有物品时取目标格中心，原绘制减半尺寸后大部分落在目标格内。没有新增素材或移动真实鼠标。快捷格A走原HUD主操作，类别由原游戏判断，B不能隐藏HUD；详见《手柄双扳机动作菜单与交互响应说明.md》。

## 原焦点、详情与生命周期

格子几何取当前页+14/+18和原资源第1组属性5/6，加每列／行24像素。背包焦点投影FC，储物箱投影C0；真实按钮投影A8；HUD快捷格不写A8，保存在独立state.id。插件只保存页、区域及局部格号，不保存物品裸指针或修改库存数组。每次方向或A操作都重新核对页面与目标。

原物品详情会先检查BC。原base Tick以物理CJMMng+40路由计算BC，并可能清A8；手柄投影自己聚焦的页BC=1，Tick后重新投影，离开页清回0及原格号-1。全局物理路由、MouseManager坐标、真实光标保持原样。这样原详情读取当前手柄格，而非要求物理鼠标停在菜单内；其它页不同时生成详情。

多个面板按原get_jm登记、精确虚表/ID和显示状态选择；辅助页不必处于普通顶层链，也不以鼠标根属性13作必备门。模态资金、对话、删除/购买确认仍优先，X不穿透模态页。X不调用Show打开隐藏窗口；原来源、生命周期和中立门保持。此前只测了普通链/属性13=1的替身，是切辅助页问题的覆盖缺口，现两作补测。

通用确认框只接受已核对的七类owner（读档及六物品区），A以独立A8选项调用原主操作，B选原取消分支，未知owner继续隔离。原确认/取消关闭时保存并恢复物品页及格/按钮区；原业务重新Show道具箱也不重置其它页焦点。恢复前重查精确登记对象和显示资格，物理来源/失焦/断线仍清除记忆。

辅助物品页的AC/B0是原依附页ID，-1为无依附。原base Tick会因依附页不active而关闭本页；手柄在Tick前采样，因此先只读重查相同关系，过期辅助页不能经顶层链、登记或capture继续挡住场景A。镶嵌的第三个非模态说明页不抢已核对格子页；真实模态确认仍优先。

## 持有物品与分级取消

原Player物品容器的2C4是持有物品编号，-1表示没有持有；它不是场景Role或鼠标坐标。A调用原页面主操作，原47F3A0／48E1B0完成原持有状态和逻辑槽交换。仓库局部格0～49由原业务映射到逻辑槽86～135，插件不自己复制或删除物品。

合成/镶嵌/护身石以真实A8子控件调用原主业务，类型门和装备属性更新保持。B放回这三种原来源也调用原面板主业务，不用普通物品交换绕过类型门；原面板不再显示或原业务拒绝时再尝试背包空位，无合法位置则保留持有和窗口。

商店沿原主操作与原owner回调执行购买/出售、报价、数量、资金与空间检查。商店的原确认类接入A当前选项/B取消，Owner为空的原信息框也可关闭；不会泛调用未知owner。三处商店/镶嵌信息框坐标调用只负责摆放，手柄使用自己焦点/页几何，不读取物理鼠标作为位置来源。

实际持有编号改变时记住本次来源；原堆叠没放完、编号不变时保留来源。B取消先检查同一容器、同一持有编号及原位置是否为空，能回原位置则原交换放回；原位置被填入其它物品或来源无法确认时，调用原背包空位搜索后原交换放置。原位置被占用时不再交换出另一件物品，避免“取消”变成新的拿起。没有空位时保留持有物品和窗口，用户仍可手动选择合法放置位置；不丢弃、不关闭、不直接改库存。

Back在道具箱格子区调用原丢弃；当前不提供新的分堆、快捷使用或自动买卖按钮。原堆叠效果、满包行为、特殊物品和复杂脚本仍需实际游戏验收，宿主替身验证的是请求对象／格号／来源保护与状态衔接。

## 验证、性能与下一步

test_menu还覆盖七类owner中的六物品页确认返回、原格位置保留、镶嵌第三说明页排除、依附页关闭后的A世界事件及菜单内R3。test_menu链接真实生产Menu／Control／Game，覆盖两作二维50格及边缘、空格、原详情BC投影、A拿起／交换、B原位或空位放回、满包取消保护、X切已显示页和跨页持有来源、Y区切、物理／世界输入隔离及52处失败回滚。代码使用有界50格位置，不每帧遍历物品数据、不读磁盘；原Tooltip和Draw仍由游戏执行。离线通过不能代替真实资源、堆叠、物理交接或性能验收。

实机先测背包导航、详情和物品拿起后B放回，再测两个面板都打开后的X切焦点和A跨面板放置，最后测Y按钮区域、B逐级关闭、按住开关页、物理鼠标交接以及HUD居中开关。真实堆叠、类型门、资金和子页脚本分别记录结果与日志，不能用普通物品回放替代。

下一批补装备区域与数字输入；快捷十二格已接入，继续按实机完善六面板的焦点、类型拒绝、属性更新、报价和脚本关闭语义。商店原整组交易不擅自改为数量购买。原始新证据《手柄多区域与持有图样原始证据.txt》，外传截图作为反馈归档；本体与外传的非标题问题同时回归。

全部已接通物品格和技能方形图标现使用Runtime内框，面板按钮和确认项恢复原指针，空手隐藏箭头，持有图标保留原中心显示；原资格/交易/拿放/取消不由框改变。共享服务与四版本生成表详情见《运行时焦点提示服务与格子界面说明.md》，迁移后新GUI实机待验收。
