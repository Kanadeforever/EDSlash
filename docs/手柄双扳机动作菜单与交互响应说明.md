# 手柄双扳机动作菜单与交互响应说明

## 当前输入规则

默认新模式使用双扳机必杀和面键切连招。旧模式兼容开关只改变单LT面键分工；普通战斗、RT技能直发、RB投掷直发、LB药品及双扳机动作菜单保持各自职责。

| 输入 | 默认新模式 | 旧模式兼容开启 |
|---|---|---|
| X | 当前左手动作 | 同左 |
| Y | 右手选中四套连招时沿既有历史推进；普通技能执行该技能；投掷不进入此分支 | 同左 |
| 单RT＋技能键 | 既有十四槽即时请求，原资格和消耗保留 | 同左 |
| RB／LB＋六槽键 | 原投掷直接请求／原药品使用 | 同左 |
| 单LT＋Y/B/A/X | 默认切第1/2/3/4套；配置为dpad时面键不切组 | 必杀首次准备、同键再次新按释放 |
| 单LT＋上/右/下/左 | 配置为dpad才切第1/2/3/4套 | 固定切第1/2/3/4套 |
| LT＋RT＋A/B/X/Y | 第1/2/3/4必杀，首次准备、再次新按释放 | 同左 |
| LT＋RT＋右摇杆 | 拨杆才打开原右手动作菜单，右杆按几何导航；回中保留候选 | 同左 |
| 菜单内R3 | 收起当前侧并重建另一侧候选，不提交浏览过的那侧 | 同左 |
| 菜单松开任一扳机 | 只调用原提交入口确认当前侧、关闭菜单；不直接出招 | 同左 |
| 普通BACK＋START | 保留救援鼠标模式 | 同左 |

单LT继续防御和左杆方向闪避；双扳机非菜单状态保留防御，左杆不兼办单LT闪避。动作菜单展开时保留LT防御，禁止闪避、面键必杀/攻击以及R3小地图。双扳机不代办单RT技能、单LT套组、肩键物品或BACK/START救援；同一新边沿只交一个层。菜单关闭后刚才持有的按钮逐个等释放，两摇杆分别等回中；还按住LT时可继续防御。

```toml
[controller.combat]
single_trigger_ultimate = false
combo_switch_input = "face"
```

single_trigger_ultimate=false为新模式，true恢复单LT面键必杀。combo_switch_input允许face或dpad；新模式二选一，默认face顺时针Y/B/A/X。旧模式忽略此项并固定十字键切套组。手改配置文件需重启；发布构建同步新增键并保留原值、绑定与注释。配置服务支持按face/dpad枚举名或编号保存，未知名拒绝，复用原子保存和帧应用链。

## 原生左右手动作菜单

ActionMenu.c复用原动作选择菜单节点、绘制、Open/Rebuild/Commit。根E8为节点链，C0为候选节点指针，C8为当前侧；节点28为稳定选择码，14/18/1C/20为当前几何。长期左/右手选择分别在HUD128/12C。浏览只更新候选C0，换侧重新生成候选，不修改另一侧长期槽位。松扳机用原Commit，原版按C8调用对应setter并释放UI捕获。

仅按住LT和RT不展开菜单。每次首次拨右杆默认右侧；右杆中立不关闭。所有真实节点在使用时重读并限128项，切图、角色更换或世界未就绪取消候选再沿原关闭入口释放捕获。物理鼠标接管仅取消手柄拥有权，原菜单可继续鼠标操作。Tick/hover包装先登记既有Controller菜单所有者；Draw仍属原版/DisplayFix。动作菜单候选改用同一原动态框，按节点矩形用原边缘片段拼接，隐藏旧箭头。Controller订阅既有UI_DRAW_END追加焦点框，不占HUD Draw槽；共用原HUD第5精灵的动画帧，不写BEC投掷装备字段。

Y新增普通右手来源只改变动作解析，不新增图标覆盖；常驻图标由原装备槽显示。RT/RB临时直发仍使用已验收的Feedback图标直到动作收尾，不改左右手长期选择；切连招和快捷动作实际成功通知继续区分来源、套号和代次。

## 快捷物品格聚焦

X依次循环所有已打开六类物品区域和HUD十二快捷格，不按恢复/投掷类型拆分焦点；隐藏页不打开，真正模态页优先。镶嵌会话只接纳道具箱、镶嵌和快捷格。没有物品窗口时常驻HUD不会挡世界输入。

HUD快捷格确认的关键隔离：原主操作先调用hover，随后按坐标判断快捷格并处理分类/交换；交换结束后仍继续把HUD+A8当主按钮读取+28及+50资源。内嵌快捷格不能写进A8，否则会误入按钮资源解析。手柄state.id保存快捷格焦点，project及hover全过程保持HUD+A8=NULL，原主操作仍处理快捷格坐标业务，但不再附带触发主按钮。动态框和持有图标从独立状态取位置，不依赖A8。

十二槽为HUD13C+i*E4，原CC逻辑格50..61。A把当前格中心交给原HUD主操作，物品类别资格、拿起/放下/交换由游戏处理；插件不复制物品类型判断、不改物品数组。Y在快捷格不切空按钮区；B先按既有来源放回持有物，再回其它已打开面板，不能隐藏HUD。快捷格空手使用原投掷动态选择框，持有物以目标格中心显示并按原交换逻辑更新图标；其它已接通菜单标记仍右下角。内嵌快捷格由HUD直接绘制，不以其64显示标志判断资格。

## 360度近身调查与响应

max_distance默认160、范围16..480世界单位不变。所有合法NPC、掉落、静态物件、换区点在360度近身范围比较，前方距离平方乘0.80，已聚焦目标再乘0.92以减少来回跳选。实际圆半径独立裁剪；很近的身后目标可以优于远处前方目标。原NPC格差、ready、route、对象代数、静态谓词和换区区域门均保留，A仍手动操作，走进区域不自动换区。

原A事件提交后，旧摇杆移动会在后续输入帧覆盖原走近/交互请求，这是可从源码确定的响应干扰。现在A提交时交出插件移动拥有权；仍被原pending保留的19/21/20/23/24请求暂不再发旧方向移动。新方向立即解除保护，原请求结束或拒绝后释放；提交到消费保留80毫秒短窗口，任何保护最多2秒，不能永久锁住角色。保护不是强制等待或加速脚本，不改原距离/资格。

动态候选先以交互标记、距离和格差筛选，再解句柄，减少远处非交互对象的反复查询。静态扫描继续仅局部地图格，同一对象的脚本资格在一次扫描内只问一次，不跨帧缓存旧对象。

QOL首次拾取对象定位原先在同一输入帧遍历最多32768登记槽，并逐槽/候选查询内存。现在每帧最多1024槽，连续块最多6144字节，扫描完整个登记范围确认唯一后才调用原动作22；最大范围需要32个输入帧。已绑定对象每次重查登记指针、代数和manager；场景/登记表变化重新分帧定位。保持原自动过滤、落地门、等待时间和入包业务。这减少首次定位的单帧开销，但不意味着自动拾取首次响应零等待。

读档的世界58未就绪、角色句柄未恢复、脚本动作和菜单关闭中立门不能直接跳过。[控制就绪]只按真实世界58/角色有效性布尔值计时，不能以菜单reason=3当世界等待；记录观察到的世界/角色恢复前等待毫秒数（可能包含前端停留，不等于读档耗时），结合[输入链]门及[性能]拾取/调查分项区分原因。没有当前实机时间线，不能宣称已彻底解决“存档进度越后等待越久”；需要新发行件的完整日志与实机复测。

## 道具箱Back与肩键边界

Back只在道具箱格子区沿原丢弃业务请求：空手取当前格的物品编号，持有时传-1。参数不是格号；本体47F670／外传48E480在玩家脚下生成原地面物并调用原库存更新，原数量/附属记录/持有生命周期保留。空格无操作，持键不连丢，不在仓库/快捷栏/其它物品页丢弃。丢弃与自动拾取独立，用户明确要求由玩家配置取舍，不新增丢弃过滤或自动拾取例外。

LB/RB仅日志分类和招式学习/连招页签有效，其它菜单既不切窗口也不切买卖模式。物品X循环已打开窗口/快捷格，Y切格子/按钮区；连招X切上方编辑/下方招式选择区，Y循环套组，均符合聚焦区域切换语义。商店切模式使用其原57/58按钮区A，原业务不删除。

原矩形裁取绘制本体4F4C10／外传50BAF0有十个栈参数、ret40；原丢弃有一个参数、ret4。四样本独立核对原矩形裁取调用4A9647／4BC1A1与原WorldLeft+70的丢弃CALL，函数头正确不足以代替来源验证。原指令窗口随《手柄动作菜单与快捷格原始证据.txt》保存。

## 动态框源图安全与异常证据

focus_rect_draw本体4F4C10／外传50BAF0是源图矩形裁取，不是缩放。十参数和ret40只能证明栈形状，不能证明函数用途。普通框与原图同尺寸时直接原SpriteDraw；尺寸不同时用四角/四边片段拼接，中间透明不画，每片的sx/sy/w/h严格不超真实源图。目标最大128，复制次数有界，不扩大源图读取范围。

focus_frame_get为4F4D60／50BC40，focus_image_get为4F5CF0／50CD10，均从原调用链独立取得并核对四样本。原32字节动画对象的当前帧/帧数和22字节帧表先验证，再验证资源管理器、登记表及登记对象；取得实际图像宽高、目标缓冲区宽高后才绘制。空帧、越界帧、未登记资源、无效图像/目标拒绝，保留旧箭头临时指示。不假造图像、修改原素材或跳过原加载规则。

Crash.c注册Windows异常观察器，内存/指令/整数除零类首次异常直接追加ASI旁EDSlash崩溃记录.txt，包含异常地址/所属模块偏移、寄存器、输入层和最近手柄阶段。记录不是最终未处理异常或调用栈，阶段不等于异常来源；原异常链继续处理，不恢复游戏、不重启、不附加调试器，不读取完整进程内存。注册失败只记录诊断不可用，普通操控不因此停用。Cursor卸载移除观察器。

17组离线检查包含test_crash文件写入/中文/寄存器/递归保护/原异常链和test_menu真实源尺寸/边界、无效动画/资源、原Draw和边缘拼接。不能据此宣称真实素材和GUI已稳定；用户报告f263b1b3版X切快捷格及双扳机动作菜单都崩溃，共同焦点绘制优先修正，用户已确认不崩溃、功能正常使用；本轮日志对应本体Steam准确样本，不能扩大为两作全部场景。技能框右/下各收2个GUI逻辑像素，上/左保持，视觉微调待验收。A8隔离仍保持，读档短等待本轮不改。

## Runtime焦点提示服务

用户提出之后把已打通的原动态框提炼到Runtime，用于原高亮不明显的聚焦项。现已提炼到Runtime，Controller只提供当前焦点，机制见《运行时焦点提示服务与格子界面说明.md》。当前接口边界如下：

- 各界面模块继续决定当前聚焦对象、导航和确认/取消；只向Runtime提交焦点矩形和样式，不提交鼠标坐标或把输入逻辑搬进绘制器。
- Runtime统一复用原素材、动画/登记验证、源图安全拼接和UI_DRAW_END绘制。矩形使用原GUI逻辑坐标，运行时不重新命中按钮或改变原布局。
- 原生高亮已经清楚的选项可以不请求框；多个窗口以当前输入焦点/模态优先级决定提示，不能把所有打开窗口一起标亮。
- 请求按帧更新；页面隐藏/关闭、切图、来源交接时失效，不跨帧保存未验证对象裸指针。素材未就绪保留合适的原反馈。
- 原矩形裁取/帧/图像接口迁入共享档案时，必须成对维护两作和Steam/非Steam四份准确签名及原调用证据，保持已有业务A8与渲染边界。

安全绘制与资源解析已提炼，并接入已实现格子页/按钮/确认框；未来其它页面按提供者接口扩展，不重写已验收的菜单操控。当前动作框右/下各收2逻辑像素，宽/高与原按钮一致，上/左锚点保持，普通快捷栏框不变。
