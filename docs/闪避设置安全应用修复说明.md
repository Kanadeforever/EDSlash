# 闪避设置安全应用修复说明

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 安全点与确认协议

生产采样桥调用Guard_SyncSettings，原位置仍在SDL采样后、INPUT_SAMPLED事件之前。只有配置候选存在时才查询当前有效玩家并判断按键/扳机释放、无ActiveRuntime、实际状态不为原版闪避17；原版和新方向闪避都被识别。旧dash.active不作为设置忙碌门，避免切图、换角色或中断留下的记录锁死应用。

Guard_ApplySettings返回是否全部接收。普通防御/体力字段保持原帧边界应用；确有方向/距离变化才查询实际角色，闪避中返回false并保留旧运动参数。即使其它调用者提前提交快照，也不会半程改位移。调用方只在返回true时更新applied_generation，拒收时下帧继续确认。没有候选、代数未变的普通帧只读内存，不增加磁盘I/O、重复应用或持续玩家解析。

当前闪避开始→保存新参数→当前动作用旧参数→动作结束→自动应用→下次动作用新参数。没有要求再次保存或重启。运动参数只在角色安全状态接收；旧对象不被补写或继续操控。

## 生产与集成测试接线

ControllerModule.c调用Guard_SyncSettings，Guard.c/h提供真实角色状态查询和完整接收确认。test_guard_settings.c复用32位战斗fixture并真实链接Config/Toml/FileIO；普通test_game通过宏保留配置替身。公共Runtime协议、QOL/DisplayFix、运动/碰撞/免疫规则不由该同步链修改。

集成覆盖闪避期间保存128→256、本次128/下次256，错误提前快照拒收后再接收64，方向开关、原版状态17、中断、切图、换角色、无玩家和无变化帧。实现与离线验证已完成，真实游戏热应用待验证；具体次数/执行结果在更新记录。

## 部署与验证限制

使用新发行或完整版之一，现存UPX未含此修复；已有TOML保留。游戏内设置窗口已接通整批保存与生产安全应用链；手改文件后重启只是启动读取，真实热应用与设备时序仍需实机。
