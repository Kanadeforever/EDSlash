## 2. 闪避有受击免疫窗口

当前Guard.c方向闪避启动调用role_effect(0x66,1,1,0)，8次逻辑更新的第4次结束时清0x66，碰撞提前结束时也立即清除。代码设计的免疫窗口覆盖前半段，不是整个闪避全程免伤；这不是渲染帧计数，未把它换算成固定毫秒。

本轮从实际基线核对了先前资料未正式命名的0x66消费路径：状态字节基址Role+0x1AF，索引0x66对应+0x215；角色受击虚表+0x34在本体419E50/外传422330读取该字节，非0返回1。普通受击入口419E80/422360调用此虚方法，返回非0则在伤害计算前退出。因此可以确认当前闪避开启的是原版普通受击免疫状态。

状态Getter还会检查另一标志0x4000；不能把日志中所有“防御0但HP不变”都归于闪避。治疗/特殊技能类别有不同分支，环境或脚本伤害也未证明都走相同门。尚未用逐帧日志统计实际窗口；本轮是源码+双基线静态证据。新版证据见《闪避受击免疫与界面入口原始证据.txt》。旧资料中“不足以命名0x66”的结论是旧证据边界，本轮增加了明确伤害消费者，不能把旧推测当新结论。

## 3. 需求纠正：自己做MOD配置界面

用户所说的设置菜单是生造用于配置我们MOD的界面，不是向原游戏设置页追加手柄控件。本轮一度把重点放在原版JM0xAA，用户明确指出找偏；原版设置调查仅作为参考保留，不作为用户已经同意的设置架构。

技能绑定放在现INI末尾、单独文件或迁TOML只是讨论选项，尚未决定。当前[SkillKeys] Slot1..14保存的是原版Virtual-Key，用它在HUD+0xC18绑定链里找selector/hand-side，然后直接请求技能；不注入这些键，但依赖原版已有热键绑定。未来自有设置页应允许直接从当前角色原技能列表选择、保存selector及必要施放方式，避免把最终Method或虚拟键码当永久技能标识。按版本/角色区分以免跨角色编号冲突是建议，尚未实现。

文件格式初步建议仍为Controller自己的INI，绑定区可置末尾；主插件INI与Controller配置不必因合并ASI立刻合并。TOML需要新增解析、写入、旧配置迁移及错误处理，暂不作为本轮实施内容。写配置仍须保证UTF-8无BOM+CRLF、保留玩家值和失败安全；不能直接假定Windows写Profile API保留全部注释/编码。

## 4. 原版设置页调查（仅参考）

两作JM0xAA：本体global55A710、vtable529FCC；外传global58BA60、vtable5532E0。Init4A5F20/4B86F0固定注册AB..B2八控件，AB..AD数值0..100，AE/AF互斥，B0/B1互斥，B2关闭。set.ini Save4A5610/4B7D70分别顺序写6/8整数；Load4A5770/4B7F00读取对应格式。普通Close4A5C40/4B8410不等同写盘；vtable+0C lifecycle wrapper4A6010/4B87E0才写盘清理。

关闭时CurrentGameState!=3回标题，等于3回Gameplay；游戏内设置关闭不重新打开JM2D。ShowHide是vtable+1C、4A6030/4B8800，不同于Close。本轮实际读取两作vtable和反汇编复核这些地址，不仅依赖旧MD。当前参考资料未包含完整GUI资源/纹理包，因此正式UI标签和资源化新增子控件不作已完成承诺。自有MOD配置界面无需被此原版页扩展方案限制。

## 5. 游戏界面操控调查与当前缺项

Controller当前Game_Keyboard菜单层仅注入B→Esc和方向键；A刻意不注入Enter，因为世界Enter打开控制台。当前没有通用手柄GUI焦点、原生A确认或完整列表/格子导航模块。不能写界面操控已完成。

标题JM19：本体global559488/vtable529AA0，外传global58A530/vtable552D10。纯业务分派4977E0/4A7A40接收子控件ID（thiscall、ret4）：1F新游戏角色、20设置、21退出、22读档、23滚动信息；外传还有A7额外入口，不凭缺少标签的资料命名它。确认可进入真实业务分派，不需要假鼠标点击/Enter。

游戏内系统菜单JM2D：本体global55AB48/vtable52A188，外传global58BF18/vtable5534AC。release4ACFE0/4BFD90读取root+A8当前子控件：2E关闭、30保存相关状态并迁移游戏阶段、31打开设置；2F该分支无独立动作。需要自己的合法焦点与原版UI反馈，不能盲用当前鼠标悬停对象作为手柄焦点。

确认取消JM98：原Enter最终调用对象虚表+3C，Esc最终ShowHide(0,0)；A/B可直接走同一语义入口，但须限定匹配的页面和签名，不能对所有GUI统一调用+3C。标题/系统/确认框需要原生业务+焦点+边沿/重复门。背包/商店是独立格子/区域模型，键盘方向不足以驱动它们；技能/连招又需要另一套Focus与业务接口。

先前建议推进顺序为标题/系统/确认取消→背包/商店→技能/连招编辑。用户的实际回复是先记录、停下并评估迁入，因此本轮不开始任何菜单实现，也不把该顺序当已实施事项。
