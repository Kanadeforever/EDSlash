# 历史实验与失败路线

## 1. GUI 安全区 test1~test7

早期路线把技能、物品、装备窗口移动到居中的原生 4:3 安全区，随后连续暴露相对位移累计、视觉/命中不同步、键盘路径不同、GetCursorPos 反算假设错误、self+0xA8 补写副作用，以及 `0x4B44F0` 隐式 ESI 调用约定不能由普通 C wrapper 安全包装等问题。

最终结论：**不移动辅助 GUI。** 正确方向是保持原坐标，只调整绘制层级和顶层输入 root。

## 2. layer1a~layer1d

- layer1a：只延后已知菜单 Draw。视觉改善，但 HUD 仍先吃重叠区输入；独立左侧面板不完整。
- layer1b：尝试重排 UI manager 双向顶层链。实机双向链验证失败，整帧回退 layer1a，因此没有解决问题；该路线废弃。
- layer1c：不写链，只覆盖原版顶层 root picker 的单次返回值，并动态纳入独立辅助面板 Draw。用户确认之前按钮、技能关闭和左侧面板问题全部解决。
- layer1d：给已确认独立辅助面板增加短生命周期跟踪，解决“物品主窗口先关闭后面板又掉回 HUD 下方”；用户确认解决。

## 2.1 HUD 顶部按钮点击动画遗漏

layer1d 已经让 `0x0B/0x0E` 两个顶部入口功能正确，但用户在统一工程重构前指出：HUD 居中后这两个按钮没有原版按下动画。该问题不是重新移动按钮，也不能手工改 pressed 字段。正确路线是继续复用已经验证过的顶层 root picker：实时命中这两个 HUD child 时，只校正这一次 root 为 HUD，让原版 `+0x20` 按下事件自己产生动画。该方案已在统一 `BladeSwordQOL v0.1-dev1` 中实机确认正常。test7 曾经直接包装 `0x4B44F0`，实机造成普通地图左键/Alt+F4 等严重回归，因此这一失败路线继续永久禁止。

## 3. 右侧竖条

旧算法 `BaseHeight=480` 下：16:9=854、32:9=1708、8:9=428、40:9=2134 都有竖条；24:9=1280 无。唯一无问题样本恰好 8 像素对齐。

随后把 `AspectRatio` 的所有输出统一改为最近 8 像素倍数。本体 16:9 改为 856 后，用户确认竖条消失。

因此当前统一工程把它视为 AspectRatio 的宽度求值规则，不创建 StripeFix 模块。

## 4. JMM / 生命周期失败

- 初始化阶段直接重放完整 JMM：时序过早；
- 只广播顶层 UI 尺寸：不能产生完整第二阶段布局；
- HUD/world 对象存在性不能准确表示 GAMEPLAY；
- 只改代码 profile、不重建 live Surface：返回前端仍残留宽屏 Surface。

最终使用 Strategy 状态 3 enter/exit + 原版显示模式函数强制重应用闭合。

## 5. 外传 Steam 失败

- 禁 delayed JMM 无法解决裸 `ResJM.Lib`；
- ActiveMovie/DirectShow watchdog 没有命中真正有效实例；
- relocation 绝对地址运行签名在 ASLR 下失配；
- 单纯禁止官方 EDIT WndProc 仍不能解释 OpenGL 崩溃。

最终根因是 ComeOn.dll callback 对合法 `CreateWindowExA` class atom 处理错误。

## 6. 工程踩坑

- 不再依赖整 EXE SHA-256 白名单；
- `source\build.bat` 禁止递归误选 ARM64 clang；有正文的 REM/echo 行末两个半角空格；所有成功/失败出口均 pause，失败保留 `_build`；
- INI 禁止 UTF-8 BOM 紧贴 section；
- 编译通过不等于实机通过；
- 本体通过不能替代外传通过。
