# 手柄迁入主插件评估

> 当前接续（2026-10-02）：统一DisplayFix＋QOL＋Controller、TOML及静态SDL3.4.16；用户确认性能候选1掉帧缓解、功能正常、实机验收通过。build.bat现在一次输出发行EDSlash.asi与debug/EDSlash_debug.asi，优化相同、运行段一致，UPX仅处理发行副本。MOD设置界面后置，未来F12和L3＋R3。最新配置／构建／验收见《统一配置与基础迁移说明.md》《完整接档说明.md》；下文旧阶段保留历史，不扩为所有设备或新产物全部实机。

2026-10-01。本线程评估 QOL 与 Controller 合并为单一 ASI，并将两份 INI 合并迁移为统一 TOML。用户已明确沿用 Castle Reforge 的 TOML 实现，并要求全新迁移、无需任何向下兼容，最终玩家体验保持或改善，不能劣化。本轮只读源码、核对接口并更新评估和接档；没有迁移代码、执行构建或修改发布配置。

## 1. 推荐结论

以 BladeSwordQOL.asi 的 Main＋Runtime＋ModuleRegistry 为基板，保留 DisplayFix、QOL、Controller 三个业务模块，在现有 Runtime 上补共享输入、配置读写、设置应用和界面焦点能力。Controller 的已验收业务迁入自己的模块目录。

不建议以 Controller 的独立 Main.c 为主框架，也不建议从零重写整个基础。需要新增的是公共服务，不是重新实现已验收的战斗、拾取或显示修复。“主插件基板”不是 QOLModule.c；后者不能变成手柄和设置中心总入口。

用户已明确允许抛弃旧实现负担。复用主 Runtime 的有效架构和已验收业务，不要求保留旧入口、私有平台桥、配置键、文件名、双目标构建或旧配置升级代码。实施拆成阶段，交付目标是单一 EDSlash.asi＋EDSlash.toml；所需 SDL3.dll 仍随最终包提供。发布只支持最终结构，不提供旧产物兼容模式。

| 方案 | 可复用内容 | 主要代价 | 评估 |
|---|---|---|---|
| 主插件框架作基板 | 唯一入口、双游戏身份、模块注册、Hook 所有权、场景／绘制事件、Win32桥、X86Detour、显示和拾取业务 | Controller 平台／构建适配；补公共输入、配置写回与设置应用 | 推荐；中等偏高难度 |
| Controller 作基板 | SDL、输入来源交接、战斗状态与诊断 | 反过来搬迁更大的主框架；独立入口与业务紧耦合；也没有配置平台 | 不推荐 |
| 完全新建基础 | 可统一风格 | 启动、两版身份、Hook、显示、输入和拾取全部扩大回归 | 没有必须推倒当前 Runtime 的证据 |

## 2. 当前源码事实与迁移缺口

| 当前事实 | 源码证据 | 迁移处理 |
|---|---|---|
| 唯一主入口进入 Runtime，模块表只注册 DisplayFix／QOL | source/src/Main.c；Runtime/Runtime.c、ModuleRegistry.c | 添加 ControllerModule；合并目标只保留一个 DllMain／InitializeASI |
| Registry逐项保存初始化返回值，失败继续后项 | Runtime/ModuleRegistry.c | 保留返回值隔离；这不是异常隔离，也不证明每个内部patch成功 |
| Controller预留ID=2；9类共享Hook | Runtime/HookManager.h | 按实际共享位置登记；声明回滚不是热卸载 |
| EventBus只有场景进入／退出、UI绘制开始／结束4项 | Runtime/EventBus.h | 补输入分阶段及焦点语义，不靠注册先后碰运气 |
| QOL在input_update原调用返回后自动拾取 | Modules/QOL/QOLModule.c | 公共帧协调上提，QOL消费帧结束事件 |
| Controller键盘IAT采样，resolver CALL原解析后Game_Update，另有async／history／retry／end桥 | Modules/Controller/Main.c | 保持调用顺序和必要物理位置；不把所有Hook强行压到一个地址 |
| 首个游戏输入线程完成完整EXE SHA、配置和SDL，DllMain先装采样桥 | Controller/Main.c、Input.c、Profile.c | 保留Loader锁外运行阶段；标题无玩家也需要输入 |
| 主插件PE身份分派；Controller另验两份精确非Steam SHA及58组局部签名 | Runtime/GameProfile.c；Controller/Profile.c；tools/controller/profiles.json | 身份识别一次，模块兼容分层验证；手柄不支持Steam不拖掉其它模块 |
| 主构建LLVM i686 MSVC target、freestanding、无CRT／零导入；Controller为MinGW GCC、系统／msvcrt导入、GNU裸汇编及数学函数 | source/build.bat；tools/controller/build_controller.py；Controller/Guard.c、Control.c、Combat.c | 选定一套32位工具链并验证ABI／依赖；零导入不作为旧产物兼容要求 |
| 自绘提示依赖DisplayFix的UI_DRAW_END；绘制／场景广播受显示运行条件影响 | DisplayFix两后端；QOL/PickupNotice.c | 设置中心不能依赖宽屏、HUD居中或自动拾取开关 |

输入帧函数、键盘IAT、resolver CALL是不同物理位置，当前双ASI能够共存。统一目标是每处位置只有一个受管理提供者，并明确采样、原解析、手柄动作与后续业务的顺序；“一个输入服务”不等于“只有一个物理输入Hook”。跨入口顺序实施时仍要结合两版调用链与运行日志核对。

UI_DRAW_END发生在原UI manager Draw返回后，之后仍可能有延迟GUI补画，不是最终呈现完成事件。设置页绘制时点必须另行验证。

## 3. Castle Reforge TOML 的复用边界

本轮只读核对的外部项目：C:/Project/GameDecomp/Castle_Remastered/castlereforge-dev。

| 文件 | 已有能力 | 不能直接假定的能力 |
|---|---|---|
| src/RuntimeSDK/include/CastleToml_API.h | 文档打开／关闭，GetBool、GetS32、GetString | 没有Set／Save／通用浮点或数组接口 |
| src/RuntimeSDK/source/runtime_toml.c | UTF-8校验、固定缓冲、表名／键名扫描、范围与缺项默认；单文档65536字节／最多16份 | 配置所需TOML子集，不能宣称完整规范、完整重复定义拒绝 |

推荐复用解析核心、错误语义与原子保存机制，适配为EDSlash内部Runtime服务。不要直接加载Castle_Runtime.dll，不整体搬迁Castle多插件注册、路径体系和游戏服务。必要源码最终纳入EDSlash，并记录出处／许可证，打包后不依赖本机Castle路径。

需要补齐：

1. 值更新与序列化、定点百分比读写；保留玩家在新TOML中的注释和未修改项；重复键／冲突表明确拒绝，未知设置明确诊断，不能静默写错或丢失。
2. 统一路径和同目录临时文件保存；写出统一UTF-8无BOM＋CRLF，不沿用Castle编辑器的保留原BOM策略。
3. 设置描述：类型、默认值、范围、单位、中文说明、模块归属、生效时机。
4. 内存配置快照及模块应用入口；热路径不逐按键读磁盘／反复扫描TOML。
5. 最终schema识别、保存失败与外部编辑冲突处理；不实现旧INI导入、旧键转换或旧schema兼容链。

公共服务采用内部C接口即可，当前不需要把EDSlash改成独立插件SDK。

## 4. 新 TOML 的功能覆盖与数据设计

当前模板共有35项：BladeSwordQOL.ini为10项，EDSlashController.ini为25项。该清单只用于核对功能覆盖和默认行为，不要求照搬旧键或导入旧文件。新配置覆盖DisplayFix、QOL、Controller；显示后端也接统一快照。

| 原区域 | 项数 | 推荐TOML区域 | 保持含义 |
|---|---:|---|---|
| Display／Font／GUI | 6 | display／font／gui | Enable、BaseHeight、AspectRatio、FixDPI、CenterMainHUD、AuxiliaryUIAboveHUD |
| GroundItems／AutoPickup | 4 | qol.ground_items／qol.auto_pickup | 名称常显、拾取模式、扫描周期、掉落等待 |
| Input／Movement／Mouse／Feedback | 4 | controller.input／controller.movement／controller.mouse／controller.feedback | 死区、前探格数、鼠标速度、震动 |
| SkillKeys Slot1..14对应快捷能力 | 14 | controller.bindings，按游戏／角色分组 | 最终以动作／技能selector及必要手侧表达，保留14槽对应操作能力，不保留legacy VK配置层 |
| Combat对应规则 | 7 | gameplay.combat／gameplay.stamina | 受击扣费、全向格挡、FreeRun、扣费／恢复百分比、方向闪避／距离；明确实际影响手柄与物理输入的范围 |

最终产物建议统一为EDSlash.asi、EDSlash.toml、EDSlash.log；实施时一次同步入口、构建、验证器、模板和发布清单。新名字是最终方案，无旧名称别名或回退路径。本轮尚未创建这些产物。

英文表名／键名稳定，模板注释和游戏界面说明使用简体中文。bool改为true／false，普通数值为整数，Auto／16:9等为字符串。Castle当前扫描器允许带点的表名文本，可用于本次配置分组，不代表拥有完整嵌套树操作。

百分比采用最终语义结构：防御消耗模式区分原版值／自定义百分比，攻击恢复模式区分跟随防御消耗／自定义百分比；百分比数值0..100.00、最多两位小数，0仍可表达不扣／不恢复，12.50仍是最大体力12.50%。默认效果与dev9一致，但不再要求把旧-1哨兵或旧键名带入新schema。内部继续用百分之一整数，补定点getter／writer，不经二进制浮点反复往返，也不交付字符串百分比过渡格式。

35项只是现有模板项。拾取文字坐标、队列长度、时长当前硬编码；未来设置页开放它们时也登记到统一schema。

最终技能绑定按游戏版本＋角色类别隔离，保存动作类型、selector和必要施放手侧，不保存最终Method、对象地址、Runtime指针，也不设置旧VK配置兼容层。默认初始化应利用已验证的原游戏角色技能／绑定数据，形成与原快捷操作等价的可用默认，避免要求玩家先手动重新配置才能使用；读取原游戏当前业务数据属于角色适配，不是导入旧MOD配置。未知角色／动作不凭空编造技能编号，明确保留未绑定提示。角色切换、技能学习、原版绑定变化及自定义绑定优先级需在实现前形成明确规则并验证。运行时来源、按住状态、当前动画、临时必杀准备等瞬态不写成永久设置。

## 5. 全新配置与保存规则

- 最终运行时只读取EDSlash.toml。删除旧INI读取、导入、旧键别名、双格式回退、legacy槽位配置和旧版本升级工具路径。
- 全新安装缺少TOML时生成最终默认模板；默认功能与已验收基线等价。生成失败明确报告，不虚报已保存。
- 已有新TOML缺项按最终schema默认处理；类型／范围错误、重复定义和不支持的schema明确诊断，不能覆盖损坏文件。
- schema标识用于识别最终格式，不为旧MOD配置实现兼容链。
- 保存前核对外部文件是否变化，冲突提示重载／重新应用，保留新格式内的玩家设置与中文说明。
- 构建只产出统一主目标和新模板，不再补旧INI或构建旧独立Controller目标。历史dev9仅用于开发对照，不进入新包运行路径。
- 最终包只包含所需新产物／依赖。部署到游戏时清晰提示停用旧ASI，必要冲突检测只防止双Hook，不能借此恢复旧功能分支。本轮不删除历史文件或玩家现有部署。

推荐设置路径：控件待修改值→类型／范围与模块校验→候选快照／配置文本→原子保存→模块安全点应用→显示已生效或待重启。保存成功才能显示“已保存”；应用失败报告实际状态，不把文件值当成游戏已生效。

| 设置类别 | 首版推荐生效时点 |
|---|---|
| 死区、鼠标速度、震动、拾取模式／周期／等待 | 输入帧边界；关闭→开启应正常工作 |
| 防御策略、FreeRun、全向格挡、扣费／恢复幅度 | 下一安全逻辑帧／事件；保留防御交接 |
| 方向闪避开关／距离 | 当前闪避结束后；不能半程改变运动分支 |
| 技能绑定／套组选择 | 按键释放／当前请求安全结束后 |
| 宽屏尺寸、比例、字体／HUD安装及布局参数 | 初版保存后明确提示重启；不能比原版修改配置重启的流程更繁琐 |

这些是最终应用契约，当前代码尚未实现。QOL和Controller现有启动开关决定初始化／安装的耦合应改为基础桥与业务启用分离，保证新设置可安全切换；签名失败仍不安装。

设置中心拥有公共焦点与输入捕获，各模块提供设置数据／应用函数。打开时防止同一键继续触发移动／战斗／技能；关闭、失焦、断线、切图清理持有状态。界面入口与布局后续确定，但不能新增抢焦点、卡顿、输入丢失或关闭后无法恢复的回归。

## 6. 实施阶段及验收门

1. **建立体验基线。** 保留655e0a4／dev9源码、产物、配置、日志及宿主测试作开发对照，不为新版本实现旧文件兼容。已有文档脏区不覆盖、不擅自提交；生产重构前按项目要求询问固化授权。已确认项和待测项分开登记：dev9全向格挡、图标时长、文字下移已有确认；不能扩大为两作所有功能全面验收。LB仍暂假定通过，LT＋右摇杆菜单／完整界面操控仍未实现。
2. **确定最终基础与构建。** 沿用主Runtime模块架构，清理重复入口、平台桥和独立目标；选定一套可移植的32位工具链。优先评估能直接承载现有Controller ABI／裸汇编／数学依赖的Clang或MinGW路线，以构建维护、运行稳定和部署体验选择；主零导入是当前实现事实，不因兼容旧产物而强制延续，也不为了保住它新增大量人工CRT／数学替代。保留实际游戏调用约定与Loader锁外初始化的正确性。
3. **完成最终TOML服务。** 复用Castle必要核心，补写回／定点／错误处理，直接建立最终schema、默认模板和内存快照。验证35项对应能力、默认行为、百分比、重复定义、UTF-8／CRLF、容量、坏文件、保存失败保留正式文件；没有旧INI导入测试和过渡schema。
4. **迁业务与统一输入。** DisplayFix／QOL／Controller接统一快照与公共服务；注册ControllerModule，合并目标唯一入口／日志。保留已验收动作、历史、目标、图标、拾取和显示结果；内部实现可替换／重构，以体验对照验收。公共身份识别一次，必要EXE／局部签名验证保留。统一采样、原解析、动作与帧后业务的时序，标题无玩家也能输入。部署仅主ASI与所需依赖，旧ASI冲突检测仅用于失败安全。
5. **游戏内设置闭环。** 先验证一个开关／滑块，再完成已开放功能设置：操作→保存→安全生效→重启读回；需重启项提示准确。Display关闭、HUD不居中、拾取关闭仍能设置。没有要求玩家先配一遍旧快捷才能恢复基本操作。
6. **两作体验对照验收。** 本体1.05／外传2.01分别对照相同场景和等效参数，覆盖原功能、默认布局、输入响应、运行性能、显示、状态清理、错误恢复和设置持久化。任何已确认功能、手感或性能回归都阻止“迁移完成”，即使编译／宿主测试通过也不能放行。尚未确认项保持待实机，不能靠对照补写成功。

## 7. 玩家体验不劣化的交付标准

| 维度 | 最低验收要求 |
|---|---|
| 功能与默认值 | 当前可用显示／QOL／Controller能力完整；新模板默认效果等价，仍能配置原有可调行为 |
| 操作与手感 | 按键布局、走跑前探、死区、连招衔接、技能／投掷、必杀准备、防御闪避与碰撞至少维持基线；没有额外操作步骤 |
| 混合输入 | 物理鼠标／手柄交接、失焦、断线重连、切图与标题输入不回归；设置页不泄漏战斗动作 |
| 可见反馈 | 图标持续与恢复、拾取提示位置／时长／真实性、字体、宽屏与GUI点击不回归 |
| 性能与稳定 | 热路径只用内存快照，不增加逐帧磁盘I/O、重复采样／Hook；相同场景实测响应及帧时间，不接受可归因的明显卡顿或延迟 |
| 设置与部署 | 一套主插件／一份TOML，中文说明清楚，保存失败保留有效文件；安全即时项可更新，重启项提示准确 |
| 原游戏规则 | 原技能资格、库存／拾取、特殊穿防、低体力门等未要求改变的规则维持；全新迁移不授权绕过游戏资格检查 |

体验要求不等于保留旧内部实现，也不等于自动恢复旧INI自定义值；新结构仍需提供等价可调能力和默认操作。对旧配置文件的不兼容已由用户明确接受。对既有可用功能的回归未被接受。
