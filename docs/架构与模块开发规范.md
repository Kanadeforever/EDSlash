# 架构与模块开发规范

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 统一入口与模块边界

生产链为source/src/Main.c→Runtime→ModuleRegistry，顺序注册DisplayFix、QOL、Controller。只有Main.c定义DllMain/InitializeASI；ControllerModule.c是模块接入层，业务保留在Controller目录。

Runtime只识别一次游戏PE身份，模块取同一GameProfile并执行自身内容签名门。Controller另核对两作准确EXE散列和局部签名；不能用另一作地址兜底。未识别宿主或真实基址不是0x400000时不访问固定地址。主ASI可导入标准Windows DLL，静态SDL和编译器运行库随产物链接。

| PE身份 | 本体 | 外传 |
|---|---|---|
| SizeOfImage | 0x00173000 | 0x001A5000 |
| EntryPoint RVA | 0x0010F0EF | 0x00127BCF |

Registry保存模块初始化返回值并隔离可选模块失败。成功不代表全部补丁成功，也不代表Controller延后初始化完成；查看后端日志。SHA、动作桥和SDL在Loader锁外的游戏输入线程完成。

## Hook与事件所有权

每个公共物理入口只能有一个提供者。共享Hook身份包括Strategy、HUD布局、UI Draw、root picker、世界按下、全局释放、地面物品更新、公共输入帧、拾取入口、Controller键盘、异步输入与resolver，共12项。

Runtime/InputFrame独占原输入刷新。QOL订阅INPUT_FRAME_END，Controller保留原键盘采样和鼠标解析后的业务位置。EventBus有GAMEPLAY_ENTER/EXIT、UI_DRAW_BEGIN/END、INPUT_FRAME_BEGIN/SAMPLED/RESOLVED/END八事件。

BEGIN/END的subject是原输入管理对象，SAMPLED是真实键盘缓冲，RESOLVED是鼠标管理对象。END只代表原input_update返回，不代表世界逻辑帧结束或Controller业务已执行；UI_DRAW_END后还可能有延迟GUI补画。

模块Claim失败时释放尚未安装的owner；已写入口先完整撤销，失败保留owner及网关。HookManager_ReleaseOwned不恢复机器码。RuntimeWin32_WriteCode返回2表示已写入但缓存/保护处理失败，不能当完全成功。只承诺初始化同步回滚，不承诺全模块热卸载。

## 公共服务

配置由Runtime维护TOML描述表、候选、快照和原子保存，业务热路径读内存。保存成功后按普通输入边界、动作结束或重启分类应用。Guard确认完整接收后才消费generation；绑定等按键释放和请求结束。

日志共用持久句柄、有界后台队列和聚合性能摘要。模块不得逐帧读配置或重复采样设备，不建立跨模块私有耦合。需要改公共Runtime能力时先解释原因，模块修改保持在其职责内。

## 显示与平台稳定契约

Strategy状态3进入GAMEPLAY，标题/动画保持FRONTEND原版4:3和mode4；修改profile还须处理live Surface。HUD居中不搬移辅助窗口、不反算鼠标。Steam完整JMM延迟应用、多语言裸资源名兜底、class atom保护与官方EDIT链必须保留。地址及失败机制见[逆向工程知识库](逆向工程知识库.md)和[历史实验与失败路线](历史实验与失败路线.md)。
