## 2026-09-15 stripe1 当前同步（本节优先级最高）

- **当前竖条实验版：本体 `v0.3.4-stripe1` / 外传 `v0.2.3-stripe1`。** 本体 GUI/输入基线 `v0.3.3-layer1d` 已由用户实机确认最后生命周期边界也解决；外传仍不能用本体结果代替独立实机。
- 本轮只处理从早期宽屏阶段就存在的**最右侧竖条纹**，不扩大 GUI/Input Hook。用户在 `BaseHeight=480` 下实测：`16:9 / 32:9 / 8:9 / 40:9` 有竖条，`24:9` 没有。
- 旧宽度算法会得到：`16:9 -> 854 (mod8=6)`、`32:9 -> 1708 (mod8=4)`、`8:9 -> 428 (mod8=4)`、`40:9 -> 2134 (mod8=6)`、`24:9 -> 1280 (mod8=0)`。目前所有有问题样本的实际 `TargetWidth` 都**不是 8 像素倍数**，唯一无问题样本 `1280` 恰好是 8 像素倍数。
- 因此 stripe1 的单一实验变量是：把最终 `TargetWidth` 从“按比例四舍五入后只保证偶数”改成“**选择距离理想比例最近的 8 像素倍数**”。对应上述样本，新宽度为 `856 / 1704 / 424 / 2136 / 1280`。
- 这仍是**待实机验证的根因假设**，目前不能把“8 像素块处理”写成已确认事实。若 stripe1 消除竖条，才可把根因升级为已实机闭合；若竖条仍在，则立即回退，不继续扩大改动。
- `layer1d` 已通过的辅助 GUI HUD 后绘制、顶层 picker 单次返回值覆盖、独立面板短生命周期跟踪、Strategy FRONTEND/GAMEPLAY、Steam delayed JMM、96-DPI、0x0B/0x0E 防穿透全部保持不变。外传 Steam `ResJM.Lib`、ComeOn.dll class-atom 与官方 EDIT WndProc 红线也不变。
- 两套 `verify_build.py` 已新增 stripe1 防回归：要求 `TargetWidth` 使用 8 像素边界算法、旧“只补偶数”运行代码为 0，并继续锁住 layer1d GUI/Input 红线。

- **没有主菜单 active 时绝不发现新的未知对象。** layer1d 只允许继续保留此前已经由合法菜单上下文确认过的独立面板，所以不会因为普通跑图时某个窗口恰好与 HUD 相交就把它错误提升。

## 2026-09-14 ComeOn.dll / OpenGL 新证据与 CreateWindowExA Hook 闭合

### 实机因果边界

用户确认：Steam 安装中删除 `ComeOn.dll` 后 cnc-ddraw OpenGL 可以启动；保留 DLL 时 OpenGL 崩溃。D3D9 路径此前可运行。由此 `ComeOn.dll` 成为当前 OpenGL 冲突的必要条件之一，但 DLL 不能直接永久删除，因为 Steam 版多语言和其它新增职责依赖它。

### ComeOn.dll 初始化中的两条通用 Hook

当前 Steam DLL：SHA-256 `5d5ac2b97d47726b18b42fd3f94c72499b36ac6ccfe569fc8203dd3ef40fd131`，首选 ImageBase `0x10000000`。

初始化区：

- `0x10005310` 附近：Steam/配置初始化主体；
- `0x100054E8~0x100054F9`：读取主 EXE `base+0x1511E4` 的 CreateFileA IAT，调用自带 Hook installer `0x10001500`，callback `0x10003E30`，overwrite=7；这是 `.lib` 多语言 Hook，当前保留；
- `0x100054FE~0x1000550D`：取 DLL IAT 中 `USER32!CreateWindowExA`，调用同一 installer `0x10001500`，callback `0x10002830`，overwrite=12；这是 test1 时的最高嫌疑，现已由实机进一步收缩。

### CreateWindowExA callback

- callback：`RVA 0x2830`；
- `RVA 0x2841`：原函数返回后的窗口后处理起点，原字节 `8B 4E 2C 83 C4 08 89 46 20`；
- 字符串 `"EDIT"`：`RVA 0x15208`；
- `RVA 0x287E`：记录 EDIT HWND 到 `RVA 0x1F6A8`；
- `RVA 0x2896`：`SetWindowLongA(hwnd, GWL_WNDPROC=-4, RVA 0x26A0)`；
- 自定义 WndProc：`RVA 0x26A0`；
- 旧 WndProc：`RVA 0x1F6A4`。

callback 不是替代原 CreateWindowExA；它先经 `0x1540 -> 0x1360` 调用 ComeOn Hook 引擎保存的 original trampoline，然后才做上述 EDIT 检查和子类化。

### ComeOn 自带 Hook 对象布局

从 `RVA 0x10F0` 构造器和 `RVA 0x1360` original-forward helper 已闭合：

```text
object+0x30C = hooked target
object+0x318 = overwrite length
object+0x31C = generated dispatcher
object+0x41C = relocated original-function trampoline
```

`+0x31C` dispatcher 生成形状以 `60 9C 54 68 <self> E8 ...` 开始；`RVA 0x136E` 明确执行 `lea eax,[ebx+0x41C]` 后调用它。

### v0.2-test1 实验实现

1. 扫描 `MEM_PRIVATE + MEM_COMMIT` 可读内存，寻找 `+0x30C == USER32!CreateWindowExA`、`+0x318 == 12` 且 dispatcher 自指针/机器码匹配的 Hook 对象；
2. 将实际 `USER32!CreateWindowExA` 入口改成 `E9 rel32 -> object+0x41C`，后 7 字节 NOP；
3. 同时把 callback `base+0x2841` 的 9 字节改成“清 helper 参数、pop esi/ebp、ret 8”，作为第二层隔离；
4. 如果 `base+0x1F6A8` 已存在有效 EDIT HWND，使用 `base+0x1F6A4` 保存的旧 WndProc 恢复一次；
5. 不修改 CreateFileA 官方 Hook、不卸载 ComeOn.dll、不禁 SteamAPI、不恢复任何 test3~test9 影片实验。

实验解释：完整 `[OK]` 后 OpenGL 成功，则这组全局窗口拦截高度命中；完整 `[OK]` 仍崩，则下一轮把该组降级并调查 ComeOn.dll 其它初始化/内存 patch。只有 callback 透传的 `[WARN]` 不能算完整排除。

### 外部逆向资料边界

用户已实机确认 PlugK 不解决 OpenGL。允许继续利用其逆向文档帮助核对 Steam 2.01 地址、启动链或结构，但所有 OpenGL 根因与补丁结论必须由本项目独立证据和用户实机结果确认。

## 当前阻塞与下一步

OpenGL 根因已经闭环并在 `v0.2.0` 封版：`CreateWindowExA` callback 对合法 class atom 缺少判断，导致将低地址 atom 当作字符串指针读取。用户实机在成功运行中记录到 3 次 guard 命中，最后一次为 `0xC1F2`。

## 2026-09-14 v0.2-test2 失败后：CreateWindowExA class atom 缺陷闭合

### 关键差分

- test1：`RVA 0x2841` 起 post-create callback 整段提前返回，OpenGL 成功；
- test2：只让 `RVA 0x2889` 无条件跳过 SetWindowLongA，OpenGL 仍崩；
- 因而危险代码一定在 `0x2841~0x2888`，而不是必须发生在自定义 WndProc `0x26A0`。

### 原始 callback 机器码

```text
0x2841  8B 4E 2C       mov ecx,[esi+2C]   ; lpClassName
0x2844  83 C4 08       add esp,8
0x2847  89 46 20       mov [esi+20],eax    ; HWND
0x284A  85 C9          test ecx,ecx
0x284C  74 53          je 0x28A1
0x284E  BA 08 52 ...   mov edx,"EDIT"
0x2853  53             push ebx
0x2854  8A 19          mov bl,[ecx]        ; 直接解引用 lpClassName
```

Win32 允许 `CreateWindowExA(lpClassName)` 使用字符串或 `MAKEINTATOM(atom)`。atom 形式高 16 位为 0，因此在 Win32/x86 可用无符号 `< 0x10000` 判定。ComeOn.dll 只判 NULL，不判 atom，随后 `mov bl,[ecx]` 会把合法 atom 当低地址指针读取。

### v0.2-test3 / v0.2.0 最终修复边界

- patch site：ComeOn.dll `RVA 0x2841`，原 6 字节 `8B 4E 2C 83 C4 08`；
- replacement：`E9 rel32` 到 ASI naked guard + `90`；
- guard 重放原指令和 `mov [esi+20],eax`；
- NULL/atom -> `RVA 0x28A1`；
- 正常字符串 -> `RVA 0x284E`；
- `RVA 0x287E` 的 EDIT HWND 记录、`RVA 0x2889` 分支、`RVA 0x26A0` WndProc、SetWindowLongA 全部恢复官方行为。
