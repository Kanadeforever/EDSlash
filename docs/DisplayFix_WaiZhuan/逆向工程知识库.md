# 《刀剑封魔录外传：上古传说》逆向工程知识库

## 目标

本文件累计保存外传已经静态确认的地址、对象、函数关系和失败边界。以后增加模块时优先查这里，避免重复反编译。

## 字体链

- `GetDeviceCaps` IAT `0x00551054`

## 分辨率链

- 显示模式函数 `0x0040BCC0`
- 模式派发 `0x0040BD0A`
- 第一映射 `0x0047F09E`
- 第二映射 `0x00489C1B`
- JMM 选择器 `0x004C69BB`
- 前端 mode 4 应用 `0x0040C339`，CALL `0x0040C345 -> 0x0040BCC0`

显示对象关键字段仍与本传同构：

- `+0x04` 当前 mode ID
- `+0x08` 本轮准备/请求 mode
- `+0x228` live Width
- `+0x22C` live Height
- `+0x280` Strategy 使用的游戏设置 mode

显示模式函数仍存在“mode ID 相同且 force=0 时早退”的逻辑。因此动态改写同一个 mode 对应的宽高后，进入游戏时必须临时 force=1。

## Strategy 状态机

- 外传状态函数主体约 `0x0040B9C0`
- 旧 state=3 离开分支第二 CALL：`0x0040B9E8 -> 0x0040E0A0`
- 新 state=3 BeforeStrategy 真正 enter CALL：`0x0040BA5F -> 0x0040E060`
- enter 内部显示 CALL：`0x0040E06F -> 0x0040BCC0`

外传状态函数比本传多保存 EDI，并在 BeforeStrategy 前多做初始化，所以不能照搬本传 `+0x1E/+0x97` 固定偏移。当前 ASI 改成分别用 enter/exit 语义上下文签名唯一定位。

## JMM / GUI

- JMM/UI 广播函数 `0x004C6970`
- 分辨率应用包装 `0x0040F9C0`
- JMM 资源路径构造 `0x00501DF0`
- 资源根缓冲区 `0x00591880`
- `JMMDL.txt` / `JMMDL800.txt` 字符串均已确认存在

JMM 选择器和本传有一个小差异：1024 比较后的跳转是 `75 44`，不是本传的 `75 42`。

## 历史宽屏 EXE 对照结论

8 个宽屏 EXE 只改变同一组三块区域：

- `0x40BDxx`：隐藏/扩展模式宽高
- `0x47F0xx`：第一处分辨率映射
- `0x489Cxx`：第二处分辨率映射

没有看到额外代码注入。这说明旧宽屏方案本质是静态替换扩展分支宽高，而不是完整生命周期插件。

## Steam 待办

外传 Steam EXE 额外加载 `ComeOn.dll`。用户实机确认 cnc-ddraw D3D9 可用，OpenGL 在开场动画结束后闪退。test1 顺带验证显示：Steam 版上标题 4:3、进入宽屏、HUD 居中、高 DPI 字体和右侧 6 个按钮等大部分功能正常；成熟 HUD 阶段会 late-detect `ComeOn.dll` 并执行 delayed JMM。该路径暂不改动，OpenGL 闪退最后单独调查。


## v0.1-test1 / test2 新增运行结论

### 生命周期实机闭合

- FRONTEND：640×480；
- Strategy state=3 enter：`force=1` 后 live=854×480（BaseHeight=480 / 16:9）；
- Strategy state=3 exit：恢复 FRONTEND profile 后，mode 4 / force=1 使 live 回到 640×480。

这证明 Strategy gate、同-mode force 语义和前端 mode 4 恢复链在外传同样成立。

### 字体

96 DPI 机器码方案已经实机通过。

### 配置开关边界

v0.1-test1 初始化顺序存在配置层 bug：`Display.Enable=0` 会在字体补丁前提前返回，使 `Font.FixDPI=1` 无效。v0.1-test2 把字体步骤移动到 Display gate 之前，正式确立两套独立开关语义：

- `Display.Enable`：宽屏 / HUD / 输入；
- `Font.FixDPI`：字体 DPI；
- 允许只开字体、完全关闭显示主线。
