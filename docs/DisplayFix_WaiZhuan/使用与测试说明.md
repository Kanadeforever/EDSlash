# 使用与测试说明

## 当前正式版

`DisplayFix_WaiZhuan v0.2.0`

代码主体仍是 `v0.1-clean1`：test2 稳定主线 + test4 已实机通过的 `ResJM.Lib` 多语言兜底。

`v0.2-test3` 已由用户实机确认 Steam + cnc-ddraw OpenGL 可以成功启动、进入 Strategy 并正常退出；日志实际命中 3 次 class atom。正式版 `v0.2.0` 原样保留这条最小修复，不再继续缩小。

## 安装

发行包严格只有：

```text
DisplayFix.asi
DisplayFix.ini
```

放到 ASI Loader 实际加载脚本的目录。日志 `DisplayFix.log` 写在 ASI 同目录。

## 推荐配置

```ini
[Display]
Enable=1
BaseHeight=480
AspectRatio=Auto

[Font]
FixDPI=1

[GUI]
CenterMainHUD=1
```

`BaseHeight=480` 或 `600` 推荐。更高值会扩大内部世界/FOV与 Surface，可能明显降低性能。

## Steam v0.2.0 关键日志

正常安装最小 OpenGL 修复时应出现：

```text
[OK] Steam multilingual ResJM.Lib CreateFileA fallback installed
[OK] Steam ComeOn.dll CreateWindowExA class-atom compatibility fix installed; official EDIT handling remains intact
[INFO] Steam OpenGL compatibility fix only bypasses unsafe ComeOn.dll string parsing for NULL/MAKEINTATOM class names
[INFO] WaiZhuan Steam/ComeOn.dll detected; stable display/HUD timing remains unchanged
[INFO] launcher-controlled Steam opening movie is outside DisplayFix scope; no historical movie experiment is active
```

真正遇到裸 `ResJM.Lib` 时还应出现：

```text
[RUNTIME] Steam raw ResJM.Lib redirect -> ...\ResJM.Lib.chs result=OK
```

如果出现：

```text
[FAIL] Steam CreateWindowExA callback atom-guard signature did not match; ComeOn.dll callback remains original
```

说明本轮最小修复没有安装，不能根据 OpenGL 是否崩溃判断根因。

## OpenGL 已确认结论

Steam + cnc-ddraw OpenGL 已实机通过。正式版保持：

- `ComeOn.dll` 必须保留；
- SteamAPI、多语言、CreateFileA Hook 保留；
- 全局 CreateWindowExA Hook 保留；
- 官方 EDIT WndProc 子类化恢复；
- 普通字符串 class 的 callback 仍完整执行；
- 只有 NULL/MAKEINTATOM 跳过不安全的字符串比较/EDIT 后处理；
- `SetWindowLongA(..., GWL_WNDPROC, ComeOn.dll+0x26A0)` 官方路径对真正的 `EDIT` 字符串类名仍完整保留。

实机已经出现 `[RUNTIME] Steam CreateWindowExA class-atom guard hit count=3 last_atom=0x0000C1F2`，并正常进入/退出 Strategy，因此根因与修复均已闭环。Steam 官方 launcher 控制的开场动画不属于 DisplayFix 主程序验收范围。

## 非 Steam 回归

非 Steam 不安装 ComeOn.dll 专项补丁，应继续保持：标题 4:3、进入游戏宽屏、HUD/GUI 居中、右侧按钮可用、返回标题恢复 4:3、高 DPI 字体正常。
