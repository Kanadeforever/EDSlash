## test11 基线正文（历史保留，当前结论以上方增补为准）

## 用途

`source\FontFix_DaoJian\` 是 DisplayFix ASI 之外保留的**永久 EXE 字体 DPI 修复工具**。正常使用 DisplayFix.asi 时不必永久修改 EXE；该工具主要用于：

- 不加载 ASI、只想永久修正 DPI 字体裁切；
- 其它兼容改版 EXE 需要单独打字体补丁；
- 离线验证字体路径是否仍然属于已确认结构。

目录：

```text
source\FontFix_DaoJian\
  apply_dpi_font_fix.py
  apply_fix.bat
```

## 根因与补丁

原游戏创建字体时调用 `GetDeviceCaps(hdc, LOGPIXELSY)`，在 Windows 125%/150% DPI 下会按真实 DPI 放大字体，但游戏文字格和裁切区域仍按 96 DPI 设计，导致字符被截断。

关键链：

- `0x004B438E`：`GetDeviceCaps(LOGPIXELSY)`；
- `0x004B439F`：`MulDiv`；
- `0x004B43A5`：`neg eax`；
- `0x004B43EE`：`CreateFontIndirectA`。

原 6 字节间接 CALL 被等长替换成：

```asm
add esp, 8
push 96
pop eax
```

必须手工 `add esp,8`，因为原 Win32 API 是 stdcall，直接改成 `mov eax,96` 会留下两个参数破坏 ESP。

## 兼容性策略

工具**不锁整个 EXE 的 SHA-256**。它验证真正准备修改的字体机器码、前后上下文和命中唯一性；因此宽屏改版、Steam EXE 或其它只改了无关区域的版本，不需要逐个加入哈希白名单。

如果目标已经是 96 DPI 修复状态，工具应识别并拒绝重复破坏性写入/报告已修复。

## 实机结论

用户在 4K、Windows 125% 缩放、取消“高 DPI 缩放替代”条件下实机确认：字体完整显示，右上角 `v 1.05` 不再被裁切，并可与 cnc-ddraw、宽屏改版共存。

## 与 DisplayFix.asi 的关系

DisplayFix.asi 已内置同一 96 DPI 运行时修复；正式 release 只需要 `DisplayFix.asi + DisplayFix.ini`，不会复制本工具。独立 FontFix 仅保存在源码仓库中作为可选工具和长期接档能力。
