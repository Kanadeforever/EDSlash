# DisplayFix v0.3-test8a 使用与测试说明

## 运行文件

正式发行目录只有：

- `DisplayFix.asi`
- `DisplayFix.ini`

放到游戏 ASI Loader 能加载的位置即可。运行后会在插件同目录生成 `DisplayFix.log`。

## 推荐配置

```ini
[Display]
Enable=1
BaseHeight=720
AspectRatio=Auto

[Font]
FixDPI=1

[GUI]
CenterMainHUD=1
```

`BaseHeight` 是逻辑纵向高度，也会改变世界可视范围；不是单纯的输出画质参数。

## v0.3-test8a 本轮重点测试

test8 的输入修复已经由实机确认恢复了 test7 的普通地图左键 / Alt+F4 回归，并保留属性、道具两个顶部按钮响应。test8a 不改这条输入链，本轮重点改为验证 INI 的 BaseHeight 能稳定读取：

- 把 `BaseHeight` 改成 720 或 1080 后，日志里的 `BaseHeight` 必须显示同样数值。
- `ConfigPath=` 必须指向与实际加载的 `DisplayFix.asi` 同目录的 `DisplayFix.ini`。
- 720 在 16:9 下应得到 1280x720；1080 在 16:9 下应得到 1920x1080。
- 顺手回归普通地图左键、属性/道具按钮、右侧鼠标技能设置按钮和 Alt+F4，确认 test8 输入链未被构建/配置修复影响。

如果出现问题，请提供完整 `DisplayFix.log`。

### 关键日志

顶部按钮按下并阻止世界输入：

```text
[RUNTIME] WORLD press ... top_id=0x0000000B ... block_world=1
```

或：

```text
[RUNTIME] WORLD press ... top_id=0x0000000E ... block_world=1
```

普通地图世界输入应是：

```text
[RUNTIME] WORLD press ... top_id=0x00000000 ... block_world=0
```

释放时窗口 fallback 仍会记录：

```text
[RUNTIME] GLOBAL release ... fallback=1
```

## BaseHeight

没有人为上限。示例 16:9：

- 480 -> 约 854x480
- 540 -> 960x540
- 600 -> 约 1067x600
- 720 -> 1280x720
- 1080 -> 1920x1080

极端值可能超过老 DirectDraw/游戏 Surface 能力，属于游戏本身限制。

## 已知未解决

- 主界面固定 640x480 目前还不会自动 4:3 等比放大并居中。
- Steam 启动环境的 GUI 异常/速度拖慢尚未解决。
- 这两项与本轮 test8 的顶部按钮穿透修复分开处理。

## v0.3-test8a 同步说明

- `v0.3-test8` 实机确认已经修复 test7 的普通地图左键 / Alt+F4 回归，并保留属性、道具两个顶部按钮响应；当前输入实现继续沿用 test8。
- test8 日志显示用户把 `BaseHeight` 改为 1080 后插件仍读取成 480。复核发行 INI 后确认 `[Display]` 原本正好位于 UTF-8 BOM 后的第一行；Win32 `GetPrivateProfile*A` 对 UTF-8 BOM 不可靠，第一节可能读不到，于是 `BaseHeight` 静默使用默认 480。test8a 将 INI 改为 UTF-8 无 BOM，并在 `[Display]` 前增加 ASCII 保护行，使以后编辑器即使重新加入 BOM，也不会再破坏第一节。
- test8a 日志新增 `ConfigPath=`，用于直接确认插件实际读取的是哪一份 `DisplayFix.ini`。
- `build.bat` 已按仓库位置重新整理：同时自动查找 PATH、`LLVM_HOME`、`LLVM_PATH`、`Program Files\LLVM` 和 Visual Studio 自带 LLVM，兼容本地与 Windows GitHub Actions；发行目录仍严格只有 ASI 与 INI。
- 主界面固定 640x480 的等比放大居中仍是后续任务，本轮没有处理。
