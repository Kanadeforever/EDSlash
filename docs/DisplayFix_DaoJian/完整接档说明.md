# DisplayFix v0.3-test8a 完整接档说明

## 当前版本定位

`v0.3-test8a` 以 `v0.3-test8` 为运行时基线。test8 已实机确认修复 test7 的普通地图左键 / Alt+F4 回归，并保留属性/道具两个顶部按钮响应；test8a 不改变该输入链，只修复 INI 第一节读取与本地/GitHub Actions 构建器自动定位。

### 已实机确认的稳定事实

- DPI 字体修复有效：4K + Windows 125% 缩放、不启用高 DPI 缩放替代时，文字完整显示。
- 固定 Y / 自动 X 的世界分辨率方案成立；`BaseHeight` 可自由调整，可作为类 FOV / 世界缩放参数。
- `v0.2-test1` 的底部主 HUD 视觉居中已被用户确认“非常完美”。
- 非 Steam GUI 从 v0.2-test1 起就是正常主线；高 BaseHeight 在 v0.3-test1 后非 Steam 也正常。
- 属性/道具真正的两个顶部按钮是 `0x0B / 0x0E`。
- `v0.3-test6` 在 BaseHeight=720 下已确认两个按钮可以打开，而且没有 v0.3-test1 的右侧鼠标技能按钮回归。

### v0.3-test7 为什么废弃

虽然 test7 阻止了按钮点击导致角色移动，但同时：

- 普通地图左键不能移动角色；
- Alt+F4 不能关闭游戏。

日志证明普通地图点击并没有被错误标成 consume=1。反汇编进一步发现 `0x004B44F0` 会使用调用者保留的 ESI 作为下游虚函数的隐式输入，普通 C wrapper 会改变调用原函数那一刻的寄存器上下文。因此 test7 的全局 press wrapper 必须整体撤销，不能修修补补继续用。

### v0.3-test8 的唯一新实验

保留原版：

```text
0x004060CD -> 0x004B44F0
```

只 hook：

```text
0x004060EB -> 0x00473F10
```

如果世界输入真正准备执行时，鼠标位于当前主 HUD ID 0x0B / 0x0E 的实时矩形，就只跳过本次 `0x473F10`；其它位置原样调用。窗口开关仍由 test6 已成功的 release fallback 完成。

## v0.3-test8a 本轮必须实机验收

优先修改 `DisplayFix.ini` 的 `BaseHeight=1080` 后启动：

1. 日志必须出现 `ConfigPath=`，且路径就是当前 ASI 同目录 INI；
2. 日志必须出现 `BaseHeight=1080`、`TargetWidth=1920`、`TargetHeight=1080`；
3. 再改回 720 时应得到 1280x720；
4. 普通地图左键、属性/道具、右侧鼠标技能设置按钮、Alt+F4 做一次快速回归即可。

日志中顶部按钮应看到：

```text
[RUNTIME] WORLD press ... top_id=0x0000000B ... block_world=1
```

或：

```text
[RUNTIME] WORLD press ... top_id=0x0000000E ... block_world=1
```

普通地图进入世界输入时应是 `top_id=0`、`block_world=0`。

## 当前架构

- 主插件：Win32/x86 `DisplayFix.asi`
- 零 Import Directory；运行所需 Win32 API 尽量复用 ComeOn.exe IAT，无法直接复用的通过其 `GetProcAddress` 取得。

- 发行目录只允许：`DisplayFix.asi`、`DisplayFix.ini`。

## v0.3-test8a 同步说明

- `v0.3-test8` 实机确认已经修复 test7 的普通地图左键 / Alt+F4 回归，并保留属性、道具两个顶部按钮响应；当前输入实现继续沿用 test8。

- `build.bat` 已按仓库位置重新整理：同时自动查找 PATH、`LLVM_HOME`、`LLVM_PATH`、`Program Files\LLVM` 和 Visual Studio 自带 LLVM，兼容本地与 Windows GitHub Actions；发行目录仍严格只有 ASI 与 INI。
