# 手柄快捷施放与套组操作设计

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 已定操作与菜单边界

X当前左手动作，Y当前自定义套组；RT技能直发，RB投掷直发，LB药品；LT防御与方向闪避，LT十字键四套切换，LT+ABXY必杀准备/同键新边沿确认。X/Y长按选择菜单不采用，现有按住连续请求保留。

LT右摇杆打开原生左键GUI，保持LT显示与防御，回中保留焦点，右杆导航，松LT确认焦点对应左键选择并关闭；确认不自动发动，不改Y或快捷技能。此菜单未实现，后置。菜单须消费选择输入，防止打开页面、切组、必杀或闪避泄漏，不能用鼠标模拟作为普通手柄方案。

## 原生数据与请求隔离

### 四套连招可以按编号独立读取

本体 `0x4C4A70`、外传 `0x4D9050` 接受明确索引 0..3 时返回对应列表；只有传 -1 才依赖当前右手选择字段。列表头保存数量/首末节点，节点 +0x08 保存原版选择数据。

因此 Y 可以持有独立的选中套组与进度，不再通过“当前右手 getter”决定自己执行什么。快捷技能与投掷的成功通知不能推进 Y 的套组游标。只在真正的套组步骤成功建立时推进。

### 原版投掷快捷执行器不能直接当作直投接口

两版十二槽执行器：本体 `0x4C3CA0`、外传 `0x4D8260`。

- 前六槽调用物品使用业务。
- 后六槽将对应物品切入右手，并设置投掷选择状态。
- 再次按已选的同一投掷槽会取消选择，恢复上一右手动作。

原版右手读取还有投掷专门分支：在对应类别与槽有效时，从物品 +0x20 生成 `值+10000` 的特殊选择码；数量 +0x1C 必须有效。因而不能只拿通用投掷招式 ID，也不能简单“调用旧快捷执行器后再调用 Y”。

直接投掷沿具体逻辑槽解析物品专用选择码，执行与消耗仍由原版处理。物品消耗完、槽被移动或重复选择时，都不能污染 Y 的套组状态。

请求分别区分左手、套组、快捷技能、指定槽投掷与药品。来源、选择、目标、期限和提交代次绑定到实际动作；套组编辑或切换不能让旧通知推进新组。

## X/Y持续与释放语义

Control_Step的pressed为新边沿，held为持续按住；没有X/Y长按选择门。新按下立即请求，持续按住且无活动动作/待重试时才发下一请求。松开阻止新连发，不等于清空仍在期限内的短缓冲。切层屏蔽与真实松键分别处理。

新按另一键可以进入原资格/窗口判断，两键同按用最新边沿选择。held不是让某个Runtime一直活动，不能因按住连发就声明蓄力技能已支持。

## 持续技能的静态证据边界



双版本技能记录构造器先把子记录计数及指针清零。本体 0x4D6510、外传 0x4EB980 的标准首次加载路径随后调用固定字段解析（0x4D62A0 / 0x4EB6E0），解析末尾调用标志派生 helper（0x4D6180 / 0x4EB5E0）；此时子记录计数仍是 0，因此该次 +0x98 / +0x9D 派生结果为 0。固定字段解析返回后，加载器才读取子记录数量、分配每条 0x20 字节的数组并加载子记录；已核对的函数返回前没有再次派生。

在两份可执行节中扫描 rel32 直接调用，派生 helper 分别只有 0x4D64EF / 0x4EB967 一处候选，均是上述提前调用；未发现 helper 地址被作为完整常量函数指针引用。该扫描不排除所有间接修改或其它外部数据写入，不能升级为“全游戏绝无长按技能”，但足以撤销“已证明实际存在需要按住的玩家技能”的强结论。

目前确认的是条件性结束代码存在，以及标准首次加载不启用该标志；没有确认任何具体玩家技能必须长按，也没有确认蓄力松开发动。Game_Async的影响必须限定为“若运行时实际启用了此标志，则会把其视为已松开”，不能写成用户当前普通战斗必然被该机制中断。实际名单和活跃标志仍未实机读取，亦未向游戏附加调试器。



若后续确认实际持续技能，保存角色/世界/Runtime、来源按钮和执行序号，区分待请求、已提交与已活动；不能以X或Y任意按住维持另一动作，也不能全局伪造右键或修改共享Method标志。失焦、断线、切图、模式切换必须清理自身状态。未确认具体玩家技能名单，原资源与活跃标志需独立验证。
