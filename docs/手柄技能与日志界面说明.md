# 手柄技能与日志界面说明

## 操作设计

本体1.05／外传2.01的Steam与非Steam版使用同一Controller菜单路由。技能页JM7D分为技能学习JM7F和连招编辑JM80，日志页JM63包含JM66列表和四个分类。按键由菜单消费，不会同时执行世界攻击、药品、投掷或技能快捷键。

| 页面 | 操作 | 原生行为 |
|---|---|---|
| 技能学习 | 十字键／左摇杆移动焦点，A确认 | 当前实际显示技能节点的学习／升级，资格、技能点、原动画由游戏处理 |
| 技能两页 | LB技能学习，RB连招编辑，B／START关闭 | 调原切页helper和原Show关闭；不修改角色战斗选择 |
| 连招编辑 | X在上方连招清单和下方可选技能之间切换 | 只改变插件焦点区域，不撤销、不删除 |
| 连招编辑下方 | 十字键／左杆选择技能，A确认 | 将当前招式追加至当前套组末尾，原可用资格及容量限制保留 |
| 连招编辑上方 | 十字键／左杆选择已编排节点，A确认 | 删除对应位置；中间项停在补位项，末项停在新末项，空清单保留首空位。重复招式按位置区分，顺序由原游戏维护 |
| 连招编辑 | Y循环1→2→3→4→1 | 调原套组索引setter，仅切编辑对象，不替代战斗LT十字键切套 |
| 任务日志 | 上下／左杆上下选项，左右翻列表一屏；LB／RB循环分类；B／START关闭 | 一屏按实际视口高度／行高取至少一项，仍调原编排滚动和刷新详情；分类独立保持 |
| 任务日志 | A、X、Y留空 | 原版没有确认执行任务的独立业务，不制造操作 |

进入技能页默认聚焦可选技能JM84，缺失时按实际有效几何选项确定。连招编辑默认下方可选技能，X切到上方清单；切页和切套后重新核对焦点。连招空清单显示第一个位置的原光标图样标记，A不创建或删除节点。每次确认、切区域、切套和切页必须松开后才可再次提交。

删除后优先保留原位置编号，原后继节点由游戏补到该位置；原位置失效时回退新末项，不跳首项。实际删除返回后同帧校正，原业务拒绝删除则保持焦点。这是连续编辑的局部焦点规则，与[W3C删除后优先后继、末项退前项的界面导航模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)一致；引用用来支撑交互判断，不当成动作游戏的强制标准。

[Xbox游戏界面导航指南112](https://learn.microsoft.com/en-us/gaming/accessibility/xbox-accessibility-guidelines/112)要求焦点顺序与界面的意义和操作一致。结合本编辑器的顺序列表，保留补位位置可连续删除当前附近节点，回退末项则保持编辑尾部；这是对该原则在本界面的应用判断，指南没有逐条规定所有游戏的删除规则。

方向首次按下立即导航，按住350毫秒后开始重复，随后110毫秒重复。上方连招布局沿原绘制的六列、44屏幕像素列间距和48像素行间距；原资源第3组位置加页面实际坐标，未固定为某个分辨率。下方技能节点按真实子控件几何导航，不按鼠标位置选择。

日志列表选择存于JM66+F4，原编排读取列表E0条数、F0行高、链节点及滚动位置，并更新父页详情。手柄直接调用编排，已接通页面不再注入箭头键。空列表和不可读链不提交导航。画焦点标记直接按原字段计算位置，不在每帧遍历全部文本链。

技能真实节点以自身JM ID保存在插件内，每次重收集实际显示的直属子控件；技能点和技能数据不由插件改写。技能原base Tick可能清悬停，包装该处CALL，在原技能详情业务运行之前重新投影独立焦点。原技能详情、说明及已有悬停绘制继续使用原数据。

上方连招条没有独立子控件，插件按原序列生成自己的位置编号，不能把编号伪装成GUI对象指针。只替换主／辅助操作中的两处原鼠标命中查询：手柄返回当前合法节点位置，下方技能或空清单返回-1；物理来源完整调用原GetCursorPos命中函数。随后仍由原主操作执行追加／删除。原辅助操作未绑定到X，也未绑定到B。

菜单包含背包／储物箱后共十五类、45个Tick／Show／hover虚表槽、一个Talk命中CALL、三个技能CALL与三处界面摆放坐标调用，合计52处安装写入。安装失败撤回自己的已写入口，卸载不覆盖后来被其它模块替换的槽或CALL。Draw槽仍归显示模块，未移动真实鼠标、未写MouseManager坐标、未发假鼠标点击。

## 必杀学习机制

两作原技能主操作只把JM84～8F的十二个普通学习节点送入技能点检查和学习函数；JM CF～DA的必杀说明控件不进入扣点点击学习分支。因此无需新增必杀图标的A加点动作。

本体4AAB7A／外传4BD7FA的学习CALL分别进入480DA0／48FBD0。原函数以技能记录字段3分组，查询前三条记录是否都在角色已学链+364；计数为3时再取同组第四记录，若尚未学习则调用481B40／490970自动加入。这属于普通技能学习条件满足后的自动解锁，不由手柄直接写角色数据；具体技能/等级门仍取原数据。施放资格仍通过47E1F0／48CF60检查已学链，LT必杀保持原资格拒绝。

说明与绘制链参见《手柄技能日志界面原始证据.txt》，学习完整分支另存《手柄必杀自动学习原始证据.txt》。此结论来自两份冻结EXE静态控制流，不能把普通按钮fixture回放当成真实角色全部必杀解锁验收。

## 反馈、性能与验证边界

日志原分类选择外观、原列表选择及自动滚动直接复用。技能实际节点的原详情与悬停效果继续复用；连招清单位置另用已经接通的原软件鼠标图样作焦点标记。没有新增A/B素材，也没有把投掷红框强行拉伸成任意格子边框。

导航枚举限128个子节点／64个候选，连招容量和节点读取有界；当前原容量18可覆盖全部六列三行。热路径不读磁盘、不遍历全技能库，日志链资格仅在方向操作时核查。真实菜单帧耗时及各角色实际GUI布局仍需实机观察。

双版本EXE散列、局部签名、虚表槽、三处技能CALL目标由verify_profiles.py独立核对；test_menu链接真实Menu／Control／Game，覆盖正确上下布局、按位置删除重复技能、首项/中间项/末项/六列行边界的焦点保持、同帧校正、删除拒绝及按住不连删、下方追加、X无副作用、四套循环、空列表／空套组、原Tick详情投影、物理命中恢复、关页隔离和普通菜单/HUD的55处失败回滚及动作菜单另两槽回滚。离线通过不代表真实游戏验收，阶段执行数和产物散列见[版本与更新记录](版本与更新记录.md)。

## 实机检查与格子界面接续

先在两作分别打开日志，检查分类、上下选择、详情同步、长列表自动滚动和B关闭。技能学习检查实际可见节点及原资格拒绝；连招编辑先在下方A追加，再X到上方A删除指定位置，特别检查重复招式、删除末尾、空套组、Y切四套、保存后重开及实际战斗套组。物理鼠标与手柄交替操作，菜单关闭后回中再发动战斗动作；原动画、焦点图样和宽屏布局分项记录。

六类物品区域已接入，见《手柄物品格子与多区域界面说明.md》：A原业务、X切已显示面板、Y切格子／按钮、B先放回持有再关闭；商店通过原按钮区A切买卖；LB/RB仅日志/招式有效。背包/仓库/商品用格号，合成7槽/镶嵌12槽/护身石5槽用真实控件；原类型门和属性更新保留，不把右键当B，不移动真实鼠标。十二快捷格已接入，装备区域与数字编辑后续。
