## 用户确认与本轮范围

用户实机确认 dev6 的手柄 Y/物理右键交接和本体防御受击扣费正常；闪避位移过大、表现不像原空格，标记失败待查。dev6 快捷键仍只选择右手，未落实此前要求；本轮已改为直接请求发动。

RT+技能键：读取原角色热键绑定，直接请求其选择码，保持原资格、硬直、消耗和五周期有限重试；不调用左右手 setter，不要求再按 Y。RB+六个道具键：从原 HUD 槽6..11的逻辑绑定找具体物品，检查数量，按原右手 getter 生成物品值+10000 的选择码，直接投掷；不调用旧槽切换执行器，不重复按同槽取消。消耗和弹道仍由原版决定。LB 药品保持原业务。

Y 专用四套自定义连招：按明确编号读取列表，独立保存选中套组、步骤与切换代次；只在该套组步骤实际成功创建时推进。快捷技能/投掷不会推进 Y；切组后的旧通知也不能推进新套组。X 保持当前左键动作。LT+上/右/下/左切第1/2/3/4套，回首项；RT 右摇杆旧切组移除。原生左键 GUI 的 LT+右摇杆菜单与必杀技依此前安排仍未实现。

两套输入的已确认交接保留，交接共享成功动作的战斗历史及原生套组进度；正常手柄不使用鼠标坐标或虚拟鼠标按键。快捷请求与已提交动作来源分开保存，不能拿右手布尔值区分套组、技能和投掷。

## 配置

插件旁 EDSlashController.ini 的 [Combat]：

```ini
ChargeGuardOnHit=1
FreeRun=1
GuardHitCost=-1
AttackHitRecovery=-1
```

修改后重启游戏。FreeRun=1 为跑步不扣费，不再查战斗状态；0 恢复原版。原版奔跑资格/耗尽退出和恢复逻辑不改变。旧 FreeRunOutsideCombat 键由构建器迁移为 FreeRun，保留用户的0/1值并删除废弃键。

ChargeGuardOnHit=1 保持受击扣费；0 恢复原防御周期扣费。GuardHitCost=-1 为角色原防御一个周期的2×消耗值，0不扣，正数指定体力点数。AttackHitRecovery=-1 使用同一扣费幅度设置，0不恢复，正数指定恢复点数；两个幅度可分别调整，范围-1..10000。使用原体力修改 helper 钳制上下限，不直接补写体力字段。

恢复只认本次真正攻击者是当前玩家、受击对象为合法敌人、攻击回调确实减少其生命值。用户明确完全格挡不恢复；挥空、miss、闪避、无敌、治疗、NPC攻击也不恢复。伤害来源从当前 Runtime 解析，不用“最后攻击者”残留字段；只比较真实攻击回调前后，不把持续状态或环境扣血猜成新命中。致命一击只要对象仍可验证同样恢复，换图/角色失效不跨场景补值。

## 双版本核对补充

真实受击入口必须由 Role 虚表+0x6C核对：本体0x419E80，外传0x422360。外传旧 dev6 使用0x422315虽然是同一个状态Getter的CALL，但不是对应受击分支，本轮修正为0x4224D4；本体0x419FC5保持用户已确认入口。真正攻击者 getter 为0x466EB0/0x4749A0。

受击入口首条完整指令64 A1 00 00 00 00可复制到网关，再跳回+6；保留原 SEH、栈和返回值。原回调返回“已处理”也可能是miss，所以不以返回值1当成生命减少。

物品访问器0x47F320/0x48E130接受统一逻辑槽0..135；玩家物品上下文 getter0x4892D0/0x4987F0。套组编号访问0x4C4A70/0x4D9050。HUD快捷绑定字段为0x208+槽编号×0xE4，物品数量+0x1C、专用选择值+0x20。无需改写右手选择或假冒额外 Y。

## 闪避仅调查，不调实现

原空格是opcode17，核心要求有效近距离目标，然后把真实目标坐标和八向装入state17。当前手柄旁路近距离目标，以角色位置+摇杆方向×256作参考。

已确认state17把参考点转为地图格，再以其为基础计算周围方向候选，交给碰撞和位移求解。因此256不是单纯速度或距离上限，而是把参考点放到角色前方约四格，候选点也围绕此点生成。这能解释手柄位移大和轨迹不同，是静态推断，尚未用实机轨迹确认。下一阶段应决定保留原版绕近目标动作，或另做受控短距方向闪避；不能只降动画速度便称修好。当前256与方向门逻辑本轮不调，原物理空格保留原路径。

## 验证

现有与新增双版本回放通过快捷技能不装备、同槽连投及空槽拒绝、Y独立游标、真实攻击回调前后血量、零伤害不回、治疗/NPC隔离、上限钳制及自定幅度。42个函数/局部签名与原调用点核对；研究证据19组函数、9组基本块。实际库存消耗、全技能、物理/手柄交替及两作新规则还需实机，替身检查不能代替游戏。

下一次测试优先RT技能、RB连续投掷及消耗、穿插快捷施放后的Y步骤、LT十字切组、实际伤害才回体力，以及开关/自定幅度。闪避留待下一阶段处理。详见完整接档最新节。


当前源码补充（2026-10-01，尚未发布）：GuardHitCost 与 AttackHitRecovery 的非负配置按角色最大体力百分比解析，范围 0 到 100.00，最多两位小数；12.50 表示 12.50%，最大体力 200 时对应 25 点。-1 保留原周期默认／恢复跟随扣费。每次事件通过角色虚表 +0x80 查询当前最大体力，不按当前剩余体力或原周期倍率计算。本文原 dev7 固定点数描述仅对应已发布历史基线。内部验证包已通过输入 88 项、连续方向 8640 组、双版本宿主 3480 项及 ASI/SDL 加载检查；不代表实机通过，release 仍为验收基线。
