# 手柄实机验证说明

适用当前源码：EDSlashController v0.1-dev7。两份非 Steam 本体 1.05／外传 2.01 分别测试，共用 ASI 和 SDL3.dll。旧节为 dev1～dev6 阶段步骤，当前按末尾 dev7 清单；Steam 和改版 EXE 未列入 Controller 运行基线。

## 一、部署与记录

将 release 中的 `EDSlashController.asi`、`EDSlashController.ini`、`SDL3.dll` 放在游戏 ASI 加载器实际加载的同一个目录。ASI 加载器使用游戏现有安装，本项目未另带或下载加载器。

暂时移出旧手柄实验 ASI，防止多个手柄插件同时注入。首次测试先验证独立手柄，再验证与主插件 BladeSwordQOL 同时加载。主插件内部 EventBus 并未跨 DLL 共享，不能省略共存测试。

日志位于插件旁的 `EDSlashController.log`，每次启动覆盖旧内容。测试完一作后先另存该次日志，再测试另一作，避免覆盖对照。日志应显示对应非 Steam Profile、输入桥安装、SDL 初始化、手柄连接；首次连接或切换模式后请松开所有摇杆、扳机与按钮。

## 三、本版不能当成已完成的功能

- 全菜单几何导航、格子导航、标签页和焦点区域切换、特殊操作以及导航框。
- 方向闪避、LT+ABXY 两次按键必杀技。
- 跳跃/瞬移等动作的长按目标外扩、松开执行；本版 X/Y 仅走普通动作释放。
- 角色专属特殊动作自动识别；RT+L3/R3 默认未配置。
- 连续招式内部的精确重定向、受击震动。
- 静态交互物的独立空间枚举；本版仅复用鼠标已有静态候选，动态 NPC 则做附近筛选。
- 手柄图标、游戏内模组设置页及 Steam 兼容。

尚未覆盖的菜单可以切换鼠标模式完成操作，但不能因此把该菜单的原生手柄导航标为通过。

## 四、dev2 当前重点

本轮先测试进入地图后左摇杆走路、松杆停止、靠近 NPC 按 A、选择好左右手动作后按 X/Y。不要用菜单 Enter 是否响应代替世界操作验收。

若仍无反应，保存本次 `EDSlashController.log`，重点看 `[输入链]`：按键/摇杆是否改变、层是否一直为菜单、门编号与界面 ID、原生帧计数是否增长；再看是否出现 `[移动]`、`[调查]`、`[动作]`。这些字段用于定位阻断点，提交日志并不等于动作执行成功。

## 五、最新实机反馈

2026-09-28 用户确认各方向移动、松杆停止、A 不再开控制台、左右手及 RT 技能/RB 投掷操作已有响应，但移动手感很差。反馈暂未明确覆盖的游戏版本，所以上表仍保留两作分别待验收。下一专项是连续方向与转向手感，不以“八个测试方向能移动”作为手感通过标准；NPC 调查本身仍需独立确认。

## 六、dev3 移动手感专项

只替换 ASI，INI 中没有新增字段时也会使用默认 12 格前探。默认死区仍为 8000，但改为左摇杆二维圆形判断；右摇杆处理保持原状。

两作分别测试：

1. 在开阔地缓慢绕一圈转动左摇杆，观察方向是否平滑变化，尤其靠近水平/垂直方向时是否仍明显吸附。
2. 在刚超过死区与满推两种力度下，比较相同角度的前进方向；小幅斜推不能被吃成停止。走跑仍由 L3 决定，不因力度自动变速。
3. 固定摇杆方向，按 L3 切换跑步，确认速度变化且目标方向不跳；松杆立即停，再推恢复走路。
4. 在墙边、狭窄通道与地图边缘转弯，检查是否因远目标绕路、卡住或走跑异常。
5. 回归 A 不开控制台、X/Y 动作、RT 技能、RB 投掷和鼠标模式。

可选配置：

```ini
[Movement]
LeadTiles=12
```

允许范围 6..32，改动后重启游戏。更大前探能降低目标方向量化，但不保证狭窄地形更好；先测试默认值再决定是否调整。记录问题时同时说明游戏版本、场景、走路/跑步和配置值。

## 七、dev3 用户反馈

2026-09-28 用户确认“操控比之前顺滑多了”，要求暂时保留当前手感，完整功能完成后再精调。该反馈不自动扩大为双版本所有场景验收。后续拟研究前方扇区、目标指向及换图机制；本版尚未实现 90 度扇区或自动换区。

## 八、技能方向重大失败反馈（2026-09-29）

用户报告技能仍朝真实鼠标方向释放。将“能发动动作”与“动作目标方向正确”分开：后者当前不通过。代码评估发现未覆盖的鼠标世界点读取和最多五周期重试重新取鼠标目标的路径；具体技能的实际触发链仍待动态定位。本轮未生成修复版。

后续必须加入鼠标位置无关性测试：手柄与角色状态保持相同，把鼠标置于左/右/后方，分别检查首发、无目标释放、RT 切技能、重试和续段，鼠标模式再单独验证原版行为。

> 用户已补充：技能方向跟随鼠标在本体和外传均出现，表现涉及其所见所有技能，且角色发动时会转向鼠标。按两作共性转向/目标来源错误处理，不能只修个别技能或只验证缓冲重试。

## 九、dev4 战斗专项

先替换 `EDSlashController.asi`，原 INI 和 SDL3.dll 保留。日志首行应为 dev4。普通手柄模式中的真实鼠标点击已屏蔽；需要鼠标操作时明确按 BACK+START 切换，切回后先松开全部控制。

两作分别验证：

1. 没有附近敌人时，先让角色面向一侧，松开摇杆，移动真实鼠标到相反侧再释放 X/Y。技能应使用角色朝向，不能跟着鼠标转。
2. 有有效敌人时持续攻击，分别把鼠标放到敌人左、右、后方或 NPC 上；目标与技能方向应不受鼠标影响。
3. 推动左摇杆给新方向后释放技能，检查目标/方向选择；90 度扇区和同栈续段转向尚未新增，不把这两项作为已实现功能。
4. 攻击过程中按住 RT 换技能，再使用 Y，检查是否保持原攻击目标。
5. 对当前动作尚未结束时的短按、无法立即释放的输入，检查短时缓冲和超时：松开很久以后不能突然补放技能。
6. 检查普通连招和四组自定义连招是否正确推进，分别验证左手动作、右手动作、投掷动作，记录角色与技能名称。
7. 切入鼠标模式后检查原版点击施放；切回后再次验证鼠标位置无关性。
8. 回归已确认的移动、松杆停止、走跑、RT/RB 选择，并测试与主插件共存。

记录完整日志。`[战斗提交]` 只说明插件已发送事件；`[战斗执行]` 来自原生动作建立成功的通知。没有成功通知、方向错误、某角色不能连招等情况都要保留对应上下文，不能只用“有日志”判定通过。

## 十、dev5 当前重点

用户本体 dev4 日志已确认方向不随鼠标和部分动作运作，但衔接严重失败，不能将第九节整体标为通过。只替换新 ASI，日志首行应为 dev5。两作分别检查：

1. X 攻击过程中按 Y，以及反过来按 X；区分在原版允许衔接的时机是否正常响应，不要求强制取消不可中断动作。
2. Y 上配置包含普通攻击和女侠踢击的预设，连续按 Y，检查是否还会出现必须等一段时间才能继续的异常停顿。
3. 同一招式组完成一轮后继续按，检查能否从首招自然重新开始。
4. 衔接恢复后再测 RT 换技能，之前此项因衔接问题尚无法验收。
5. 回归无敌人角色正面释放、移动鼠标不改锁定目标、投掷、手柄/鼠标模式切换与已暂定移动手感。

保留完整日志。失败时说明是新按键没有 `[战斗输入]`，还是有输入却出现恢复/丢弃、提交后没有执行；也可直接提供整份日志，不需要手工分析。用户原 dev4 日志已存入 docs 的证据副本，原 release 日志本轮未被改写。

## 十一、dev5 最新反馈

用户本体测试报告“看起来没问题”，体验接近原版；第五版日志已保存到 docs。该次看到了旧历史恢复后成功建立首招，未出现未匹配执行通知。日志中仍有忙碌到期/不可解析记录，不能仅凭计数定义异常；后续重点观察合法衔接时机的实际表现，不改变原版动作限制来追求日志无丢弃。当前反馈不覆盖外传全部技能或其它未测试场景。

## 十二、预输入解释

dev5 已有最多五个后续更新周期的单槽预输入，新按键优先替换旧等待请求；不是无限队列，也不扩大原版可取消条件。预输入是否成功取决于窗口内动作能否变为可执行。按住自动继续攻击、原生追近等待与这个短缓冲是不同机制。当前仅解释实现，不调整参数。

> dev5 阶段设计记录：当时快捷直发和 Y 专用套组未实现；当前 dev7 已落实，按末尾 dev7 清单验收。

## dev6 历史验证步骤（旧免费跑步规则已被 dev7 替代）

按《手柄防御闪避与热切换说明.md》的六项顺序分别在本体/外传测试，尤其同一战斗 Y→物理右键→Y 的多轮连续动作、低体力受击、防御中多段命中、无目标方向闪避和复杂地形。两项 INI 开关须分别关闭并重启，确认恢复原版支出且互不影响。非战斗以存活敌人的原版追击目标判断，不以玩家红圈或血条判断。新 QoL 日志应含初始化配置与运行/等待；运行扫描日志不证明已经入包。BACK+START 不参与物理鼠标交接验收。

## dev7 优先实测

先测试RT组合是否一次直接发动、RB同槽连续投掷是否确实减库存，穿插快捷后Y仍按当前套组推进，LT十字切组。再查FreeRun在战斗/非战斗均免支出；真实扣敌人生命才回血，完全格挡/无敌/空挥不回。配置幅度默认-1，另测指定正数与0，改INI后重启。保留Y/物理右键多轮接管。闪避已明确失败，此包不作为闪避修复验收，后续另查。详见《手柄快捷施放与体力规则说明.md》。
