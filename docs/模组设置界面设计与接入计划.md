# 模组设置界面设计与接入计划

## 已确认的设计

在游戏最小640×480逻辑画布内使用顶部分页、页内双列滚动，建议面板608×448、四边16留白；窗口放大由cnc-ddraw负责，不增加逻辑面积。大类覆盖模组设置、按键设置、技能快捷，技能快捷配置为主要职责。采用原界面暗底、铜金细框与方形控件，原图标／Runtime焦点可复用，保存值与候选修改分别标识。

LB/RB切大类，十字键导航，A确定，B分级取消。悬浮说明不永久占列表面积，不改变布局或阻止浏览；说明层由Y呼出／隐藏，已获用户确认。

入口改为待机时LT+RT+Back。不能把任意双扳机状态视为待机：需要核对无其它菜单／动作选择、无在途攻击／跳跃／闪避、无待提交请求、摇杆中立以及双扳机原防御状态的资格。两扳机先成立再新按Back可避免只RT时Back技能槽误触；BACK+START救援组合和R3动作菜单也必须隔离。具体门尚未实施，不宣称当前组合已经可用。

## 实施边界

设置窗口拥有输入时隔离世界快捷／攻击／必杀／跳跃／小地图，并消费原物理鼠标确认；关闭后消耗过的输入需释放／回中。物理鼠标与手柄都可操作，焦点／滚动一致。原游戏业务／库存／技能数据不由设置窗口改写。

模组设置沿RuntimeConfig描述表；SetInt／SetText／SetBinding保留原子保存、外部改动检测和角色独立绑定。保存成功只证明磁盘成功；FRAME／IDLE／RESTART生效分别提示，正在执行的动作不被半程改写。技能绑定保存后用于下次输入，无需重启；当前B预览也持有自己的本次选择／缓存世界点，不随保存改绑。

场景Actor与PlayerManager档案必须区分。后续角色独立绑定以原玩家档案的初始化selector为权威核对，不因Actor同偏移可读就当成正确玩家类别。自建绘制需要独立核对原Surface／文本／图标ABI，最高640×480布局与四准确EXE共用来源验证；不能把外部HTML布局预览当实际游戏资产。

## 当前接续

生产设置界面尚未实施。优先完成用户正在验收的B共用技能路线及缓存落点，后续按输入所有权／布局滚动／说明层／候选保存／生效状态分阶段推进。新游戏页面为后续独立批次。阶段执行、构建身份与实机反馈仅进入《版本与更新记录.md》，当前总接档见《完整接档说明.md》。

设置后端已接通RuntimeConfig_SaveBatch：普通选项与多角色槽位候选全部验证后一次原子保存，重复字段／重复槽／任一无效值／外部文件变更均拒绝整批，不部分写入。RuntimeConfig_Saved及GetSavedBinding提供已保存值；Current及GetBinding提供生效值，FRAME／IDLE／RESTART仍走既有边界。生产窗口尚未接通，说明键Y已确认，按键改绑是否影响菜单待用户选择，保存后端不能当作界面已可用。

用户确认仅世界操作／技能快捷改绑，菜单保留固定布局，另允许A/B确认取消交换。Y说明、LB/RB分类保持固定。

已接通[controller.menu].swap_confirm_cancel和[controller.world_keys]七项普通世界动作映射，IDLE安全点应用；菜单／RT/RB/LB修饰组合不使用世界映射，物理救援组合保留。重复键位整批拒绝，交换两键用批量保存。SettingsModel已实现三类、双列边界／滚动、每页焦点保持、说明状态、候选编辑／取消／整批保存。原生窗口绘制／待机入口／鼠标与手柄接线尚未完成，不能把模型测试当作游戏内设置UI已可用。
