# 工具说明

## 1. `source\tools\verify_build.py`

主插件产物与配置验证器，只使用 Python 3 标准库，不联网、不改游戏文件。检查 MZ／PE32／i386、DLL、非零入口、零 Import Directory、Export Directory 及文件内 InitializeASI 名称；名称检查未逐项解析导出表，不等同实际 GetProcAddress 加载验证。

INI 检查拒绝 BOM／无效 UTF-8／重复定义，要求 Display.Enable／BaseHeight／AspectRatio、Font.FixDPI、GUI.CenterMainHUD／AuxiliaryUIAboveHUD，并比较 release 与 source/config 的这组必需接口。当前不要求／校验 GroundItems 与 AutoPickup 参数，QOL 运行时负责缺项默认与范围钳制。

工具不检查源码、docs 结构／换行、Hook 所有权、事件顺序、宽度函数一致性、layer1d 或 Steam 红线。旧文档称“源码防回归锁定”的内容不能作为当前工具能力或测试证据。

## 2. `source\tools\verify_compatibility.py`

统一 EXE 兼容检查入口。先按 PE 头识别 Profile，再分派到：

```text
source\tools\compat\compat_daojian.py
source\tools\compat\compat_waizhuan.py
```

子验证器只读 EXE，核对 DisplayFix 内容签名、调用关系、vtable 与 UI 结构；保留的历史结构不代表当前 ASI 安装对应旧 Hook。统一入口只分派 EXE；Steam ComeOn.dll 要直接调用 tools/compat/compat_waizhuan.py。QOL 三入口由 QOLModule 在运行时核对，不由此工具完整验证。

## 3. 永久字体工具

保留历史稳定工具：

```text
source\tools\font_fix\DaoJian\apply_dpi_font_fix.py
source\tools\font_fix\DaoJian\apply_fix.bat
source\tools\font_fix\WaiZhuan\apply_dpi_font_fix.py
source\tools\font_fix\WaiZhuan\apply_fix.bat
```

一般运行用 ASI 的 `[Font] FixDPI=1`。永久脚本验证 PE 与唯一上下文，只修改同目录 *_DPI_FontFix.exe 副本的 6 字节范围并重读比对，不覆盖输入 EXE；已修复输入不重复生成。同名输出副本可能被覆盖，不可把工具输出置于只读参考目录。

## 4. 维护规则

工具升级时包内只保留最新/最稳定版。新增工具必须同步本文件与 `完整接档说明.md`；项目说明放在 `docs\`；源码目录同级 readme.md 构建说明、tools 内工具说明按用户规则允许保留。

## 5. Controller 独立工具

工具位于 `source/tools/controller/`，不依赖外部项目和个人编译器路径文件。

| 文件 | 用途 | 依赖与输入 |
|---|---|---|
| `build_controller.py` | 构建、测试、校验、更新独立产物 | Python 3 标准库、32 位 MinGW GCC、随包 SDL ZIP；参考 EXE 仅用于可选双样本复核 |
| `generate_profiles.py` | 检查双版本 C 地址表与元数据一致 | 默认只检查；确认修改元数据后用 `--write` 重新生成 |
| `profiles.json` | 冻结两份非 Steam EXE 散列、地址、偏移、签名和 SDL 包散列 | 从参考基线只读提取，不以旧聊天地址替代 |
| `test_control.c` | 输入时间线、死区、层切换、走跑与八方向测试 | 由独立构建自动编译执行 |
| `test_motion.c` | 验证圆形死区保留角度与连续目标精度 | 8640 组角度、力度、位置组合，数值验证不代替实机轨迹 |
| `test_load.c` | 实际加载 32 位 ASI 与 SDL，并检查 12 个公开导出 | 非游戏进程验证未知宿主安全返回，不初始化手柄设备 |
| `test_game.c` | 在 Win32 进程用同调用约定替身验证两版适配 | 覆盖调用对象、参数、A/X/Y 路由、菜单与快捷层；不是实机游戏 |

独立构建更新自身 ASI、SDL、验证报告，并迁移已有 INI 的废弃键／补缺项；保留既有配置值，不清空共享 release。详细调用方式见 `source/readme.md`。生成的 `release/手柄构建验证.json` 会明确区分双样本静态复核与待实机验收。

## 6. 原生动作拆分研究工具

`source/tools/controller/trace_native_actions.py` 只读两份非 Steam 基线，验证冻结 SHA-256 后使用 pefile 与 Capstone 解码原生技能解析、执行、转向、历史回写、输入分发等 19 组函数范围与 9 组基本块，并验证历史门初始值及各 6 处写入。依赖仅用于研究工具，正式构建仍使用 Python 标准库，不自动安装依赖。

从项目根运行：

```powershell
python source/tools/controller/trace_native_actions.py --baselines "参考资料/刀剑封魔录系列反编译资料库_v0.31/基线程序" --output "docs/手柄原生动作拆分证据.txt"
```

只有两版全部校验和完整解码成功后才写输出。工具拒绝把输出写入只读参考资料或基线目录，不运行游戏、不修改 EXE、不安装 Hook。解码从已确认函数起点进行，不从任意地址猜指令边界。结果说明局部静态控制流，不证明实机触发频率或完整功能可用。

## 7. dev4 战斗验证扩展

构建器已加入 Combat.c 与 SkillResolver.c，并验证两份 EXE 的动作历史回写及旧鼠标重试 callsite。test_game.c 扩展为实际运行新的解析和动作上下文，旧鼠标 SkillRelease 替身若被调用会直接失败；覆盖鼠标数据污染、忙碌缓冲、超时、RT 切层、序列与时间方向条件和连招游标。它仍不是原游戏执行器，不能替代两作实机。当前冻结函数签名为每作 26 个。

## 8. dev5 回归补充

新增首招时间条件 0、X/Y 新边沿接管、混合预设循环、原生同帧结束通知和迟到动作来源测试。此前测试使用较宽松的首招条件，未覆盖本轮实机失败机制。dev5 每作 27 个函数签名，构建器还验证动作结束通知调用点；完整宿主回放为 2682 检查点，不代替实机。

## 9. Runtime 失败回滚回归工具

从项目根运行 `python source/tools/run_runtime_checks.py`，或从 source 运行 `python tools/run_runtime_checks.py`。需要 Python 3 标准库与 32 位 MinGW GCC；复用 Controller 构建器的 CONTROLLER_CC、PATH、MSYS2_ROOT 探测，不执行该构建器的发布入口。中间文件保留在 source/.build/RuntimeChecks，不更新 release，也不启动、注入或修改游戏。

run_runtime_checks.py 编译 tools/test_runtime.c 与真实 X86Detour.c。测试在自有进程用 Windows API 替身模拟写入前保护失败、写入后保护恢复失败、缓存刷新失败、撤销失败和外来跳转，执行真实桥接写入与撤销逻辑。当前 28 项通过；测试未覆盖所有并发热卸载情形，工具只支持初始化期间同步回滚，不宣称热卸载安全。

## 10. dev6 验证扩展

build_controller.py 加入 Guard.c，验证每作 37 个函数/局部签名；test_control.c 加入新操作/稳定按住/慢推杆的来源判定，test_game.c 加入双向链表历史交接、原周期受击扣费、耗尽事件、NPC 隔离、追击目标判定、两开关独立组合及在自有进程执行真实闪避裸钩子的栈检查。运行时工具新增共用日志的追加和数字写入检查，现为 28 项。配置升级只补缺项，保留已有玩家值；输入回放与真实游戏严格分开。

## 11. dev7 工具与验证

构建器迁移FreeRunOutsideCombat为FreeRun并保留旧0/1，加入两幅度缺项；重复升级不改已有完整文件。元数据42个函数/局部签名；真实受击入口依虚表+0x6C定位，不靠相同Getter匹配。回放新增直接施放/投掷、不装备/不推进Y、原受击网关、血量差判定与幅度；trace工具19组函数/9组基本块。角色原HP是否降低和本次攻击者一起决定恢复，不以返回1当命中。

## 本轮审计边界

Runtime 28 项既有测试记录只覆盖 Win32Bridge／X86Detour 的替身故障和日志路径，不覆盖 Controller Main 的 patch、Guard 安装失败回滚或所有模块热卸载。宿主回放不是原游戏结果。本轮只执行地址表同步检查和 Python 语法／元数据解析，没有调用会读取参考 EXE 或写 release 的完整构建，详见《源码与文档一致性审计.md》。
