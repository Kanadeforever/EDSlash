# 手柄原生事件拆分方案

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 当前落实与边界

Controller的Combat/SkillResolver已独立组织普通手柄请求、目标、解析、历史和短重试，接入成功/结束通知、原生防御及物理交接。以下保留接口证据与必须维持的约束；不是尚未开始的实施时间线。

普通手柄模式必须独立维护焦点、目标和方向。鼠标可以复用的是它最终触发的原生业务事件，不是光标位置、鼠标命中、鼠标按钮或鼠标输入状态机。

禁止作为完成方案：模拟点击、移动或隐藏鼠标后继续用其命中、临时改全局鼠标坐标、复制一个假的 MouseManager 喂给旧输入函数、将菜单确认简单映射成 Enter，以及用鼠标模式绕过未完成的原生手柄功能。

只有用户主动通过 BACK+START 进入独立鼠标模式时，才恢复鼠标输入行为。普通手柄模式最终也必须取消指针绘制和鼠标悬停业务对焦点的影响；不能只隐藏 Win32 指针就认定游戏自绘指针和鼠标业务都已退出。

参考资料中“把真实鼠标移动到格子中心”的历史方案不再采用。参考资料只读，不修改历史文本；后续实现以本文件及用户最新要求为准。

## 已核对的业务出口

下表给出可复用的原生业务层，不代表直接调用它们就能跳过上游资格与状态协议。

| 语义 | 本体 1.05 | 外传 2.01 | 边界 |
|---|---:|---:|---|
| 玩家动作提交 | `0x477680` | `0x486090` | ECX=玩家管理器，四个栈参数，ret 0x10 |
| 原生招式执行/运行时创建 | `0x420E90` | `0x429480` | ECX=Role，实际 Method、显式点或空、目标 Handle，ret 0x0C |
| 实际 Method 记录解析 | `0x420BE0` | `0x4291D0` | 原生招式执行入口内调用，保留资格 |
| 执行资格检查 | `0x4244C0` | `0x42D120` | 执行入口内检查，不能直接创建 Runtime 绕过 |
| 两点计算当前角色 Facing | `0x429CB0` | `0x432CB0` | 原版 8/16 向模式由角色决定 |
| Facing Setter | `0x429D20` | `0x432D20` | 同步动画方向，不能只写 Role+0x14B |
| 两点对齐朝向 | `0x429D60` | `0x432D60` | ECX=Role，两点参数，ret 8 |
| 左右手选择读取 | `0x4C40D0/0x4C40E0` | `0x4D86B0/0x4D86C0` | 右手含准备动作、投掷与负值连招槽，不能当简单字段读 |
| 左右手选择设置 | `0x4C4280/0x4C41F0` | `0x4D8860/0x4D87D0` | 复用原版选择及显示更新，不模拟热键 |
| 药品/投掷六槽业务 | `0x4C3CA0` | `0x4D8260` | 前六槽执行物品，后六槽选择投掷动作，业务不同 |
| 动态交互去重 | `0x477740` | `0x486150` | 通过后发 opcode19；静态交互资格另算 |

普通提交优先继续走原生玩家动作协议：9 为实体立即尝试，10 为显式世界坐标，11 为追近后释放。后续 Role 更新、资格、距离、碰撞、伤害和 Runtime 仍由游戏负责。

关键新证据：原生 ExecuteMethod 内部本身会从显式世界点或实体目标计算位置，并在自身条件满足时调用两点对齐朝向，再创建 Runtime。这是复用原版动作语义的正确层次，不需要总在外面无条件强刷 Facing；但它仍触发下节的历史记录回写，必须一起拆分。

## 不能跳过的选择解析层

需要保留三种不同数据：

1. 普通技能 selector：表示玩家选择的技能。
2. RightSelectionCode：还包含 -1..-4 四组连招槽。
3. final Method：实际交给动作协议执行的招式 ID。

原 SkillRelease 本体 `0x4752C0`、外传 `0x483B40` 同时承担了读取鼠标和技能解析，因此不再作为普通手柄模式的总入口。

独立解析层保留它的业务规则：

- 枚举 Role+0x193 的角色候选容器，并经过原版技能资格查询。
- 读取 Skill.gop 组与 Method 记录，匹配 selector；不能直接把 getter 返回值当作 final Method。
- 有动作历史时匹配序列前缀、选择可续接成员。
- 判断记录中的时间窗口和方向条件。方向来自手柄目标/地面点，历史来自控制器动作历史。
- 正确处理失败、不可用、特殊选择值，以及不同左右手释放策略；不能用首个候选或最接近的 ID 兜底。

已展开的内部函数：

| 内部职责 | 本体 | 外传 | 当前判断 |
|---|---:|---:|---|
| 序列前缀匹配 | `0x4750F0` | `0x483970` | 参数传入序列，函数体未读取 MouseManager this；可评估封装复用 |
| 后续成员解析 | `0x475280` | `0x483B00` | 参数传入组和索引，读取实际记录表；可评估复用 |
| 时间/方向资格 | `0x475160` | `0x4839E0` | 仍读 this+0x38 取得角色；应按证据拆成显式角色、历史、目标点参数的独立语义函数，不伪造鼠标对象 |

以上“可复用”仍需检查所有下游与异常路径，不能因局部没有鼠标坐标就宣称整条链已完全隔离。

## 运行时回写也是输入来源的一部分

已成对核对：Runtime 初始化时，在当前受控玩家等条件满足后，会回写动作历史。

- 本体 Runtime 初始化 `0x4693A0`，调用点 `0x469793 -> 0x475070`。
- 外传 Runtime 初始化 `0x477000`，调用点 `0x4773F3 -> 0x4838F0`。
- 两者传入实际动作的组信息与方向相关参数，this 使用全局 MouseManager。
- 记录函数更新 +0x48/+0x4C/+0x50/+0x54/+0x58 和 +0x5C/+0x60/+0x64 历史链。
- 记录函数还根据全局右手输入标志（本体 `0x557D30`，外传 `0x588BBC`）决定是否推进 HUD+0x120 的自定义连招游标。

因此，即使直接调用 ExecuteMethod，也不是整条调用链天然与鼠标无关。必须把“当前玩家、由手柄发起的动作实际建立成功”作为业务通知，更新控制器动作历史和相应连招游标。鼠标模式保留原处理，AI 动作不能受到手柄意图影响。

额外全局门已进一步核对：本体 `0x5457F0`、外传 `0x574D10` 初始均为 1，subtype5 自动续段与 effect command9 建立后续动作时临时置 0，随后恢复为 1。其作用包括避免自动衍生动作再次记入输入历史，新历史服务必须保留这一区别；不能每观察到一个 Runtime 就追加一次手柄按键。Runtime+0x6F 的值由两版原生 8 向点差换算函数生成，再作为历史方向参数传入。

生命周期必须覆盖：技能被中断/自然结束的历史维护、左右手并发或快速切换的归属、失败动作不能推进游标。不能依靠当前仍按着哪只按钮猜一次已提交动作的来源。

## 手柄动作上下文与生命周期

每次动作明确保存：控制角色 Handle、输入来源与左右手、选择类型/选择值、有效目标 Handle、显式世界点/方向、提交代次、所处阶段与重试期限。

流程：

```text
手柄按键/方向意图
  → 世界上下文和角色资格
  → 保持或取得手柄目标，形成显式方向/点
  → 按角色数据和控制器历史解析实际 Method
  → 提交原生 opcode9/10/11
  → 原版执行、资格、距离、碰撞、Runtime
  → 受控玩家动作通知，更新控制器历史
  → 结束/中断/失效时清理对应状态
```

重试属于手柄动作，不写 MouseManager+0x6C/+0x70/+0x74，也不允许 target=NULL 后回退取鼠标。重试前重新校验 Handle 和角色生命周期；目标失效时明确取消或按设计重选，不悄悄换成鼠标候选。

RT/LB/RB 层切换不是战斗结束，不能顺便清空全部锁定。明确新方向允许在合适动作边界重定向；没有新方向则保持原目标。subtype5 同栈续段需要独立接入原版新 Method 边界，不能靠下一帧轮询补做，更不能任意改运行中每一 hit 的目标。

## 输入所有权与鼠标模式切换

仅建立新的动作发送端还不够，必须阻止普通手柄模式下的旧鼠标生产端同时发送动作、改朝向、改焦点或滚动地图。

- 原版 MouseTargetResolver 可包含玩家/地形维护，不能未经拆解就跳过整函数。
- 原版每帧输入更新混合了重试、历史超时、边缘滚屏、防御和其它业务，也不能整段停掉。
- 按来源拆出“鼠标取点/命中/按钮动作/边缘滚屏”和必须继续运行的世界、角色维护。
- 防御改成原生 opcode16 后，还要处理原版“真实 Alt 松开→取消防御”的输入生产分支，否则手柄防御会被下一帧取消。
- 切换模式时清理该来源拥有的按钮、重试和焦点，保持明确的交接；普通按键层切换不等于模式交接。
- 指针显示需要分别核对系统鼠标和游戏自绘指针；真实鼠标位置不应成为普通手柄模式是否生效的判据。

模块不得重复覆盖已经登记的公共Hook。共享需求通过Runtime服务/事件接入，调整公共能力前解释原因。
