# 手柄模块接档说明

更新日期：2026-09-28。当前状态：v0.1-dev2 调查与操作修正版已构建；用户已报告 dev1 游戏内核心操作无反应、A/Enter 会打开控制台。dev2 两作静态与回放通过，但修复效果均待实机确认。

## 一、模块定位与目录

Controller 是 EDSlash 的子模块，当前阶段独立开发、独立产出，未来再合入主插件。用户明确要求沿用主项目目录结构，不能因为暂时独立而在包根新增 controller 工程。

- 现有手柄源码：`source/src/Modules/Controller/`。
- 项目接档与设计文档：根目录 `docs/`。
- 独立构建入口：`source/build_controller.bat`，统一构建说明为 `source/readme.md`。
- 模块工具：`source/tools/controller/`，包括构建器、地址表生成器和三个回放/加载测试程序。
- 配置模板：`source/template/EDSlashController.ini`。
- 产物：根目录 `release/EDSlashController.asi`、`EDSlashController.ini`、`SDL3.dll` 与 `手柄构建验证.json`。

本轮已经把错误创建的根目录 `controller/src/` 四个初稿迁移到模块目录，并仅删除本轮创建且已确认为空的旧目录。文件统一为 UTF-8 无 BOM、CRLF。主插件功能源码没有修改。后续已说明并修正主 `source/build.bat` 清空整个 release 的行为；原有根 `.gitignore` 修改没有处理，仅新增 `source/.gitignore` 排除独立构建中间文件。

## 二、本体与外传同时支持的硬性要求

用户明确：同一份独立手柄 ASI 必须同时支持《刀剑封魔录》本体与《上古传说》外传。不能先交付只支持其中一作的版本，再把另一作列为后续适配。开发基线同时采用非 Steam 本体 1.05 与非 Steam 外传 2.01；Steam 适配仍后置，不得把“Steam 后置”误读为“外传后置”。

每项功能均须成对核对地址、ABI、结构偏移、资源与角色差异，并具有两版实现及验证记录。未知版本或签名不匹配必须停止该功能，不得回退使用另一作地址。静态验证与真实游戏验收分开记录；一作未完成或未实测时，不能宣称该项已获双版本验收。

当前同一 ASI 已含两版地址档案，并通过两份真实 EXE 的静态核对及两套偏移的适配回放。坐标转换已成对核实。可以进入两作基础功能实测，但不能称为完整双版本实机验收通过。

## 三、已经确认的操控设计

全地图采用相同基础布局，不根据城镇或野外切换按键职责：A 调查交互，X 当前左手动作，Y 当前右手动作，B 暂时留空。菜单继续 A 确定、B 取消、X/Y/R3 特殊操作。

- 左摇杆走路，移动时按 L3 进入跑步，松杆停止并重置走路。
- LT 防御，配合左摇杆方向闪避；LT 加 ABXY 选择四个必杀技，再按同键发动，换键切换选择。
- LB 按住进入六槽药品层，RB 按住进入六槽物品/投掷层；层内 ABXY、左、右对应六槽。
- RT 按住进入技能层：ABXY、四方向、LB/RB、BACK/START 对应十二快捷位置；L3/R3 对应角色适用的特殊动作。
- RT 加右摇杆上、右、下、左，对应四个连招预设。
- 十字键上属性、下技能、左日志、右物品；START 系统菜单；普通 R3 小地图。
- BACK+START 切换鼠标模式。左摇杆移动鼠标，右摇杆速度为左摇杆的三分之一，LT 右键、RT 左键。进入鼠标模式震动 200 毫秒，返回手柄模式震动 1500 毫秒。
- 位置型动作由当前 X/Y 动作键长按展开目标点，松开执行，扩展速度可配置；不恢复早期固定 X 跳跃设计。
- 攻击中保持目标；新的左摇杆方向意图可以改变目标，攻击停止或中断后恢复非攻击时的选取规则。受击需震动。
- 菜单采用列表或格子导航，LB/RB 切换适用的标签页或已显示区域；优先考虑导航框，否则用鼠标指针显示焦点。不能为填满特殊键制造不存在的业务。

以上为完整设计要求。以下单独列出当前实现范围，未列入已实现范围的要求仍是后续工作。

## 四、当前源码、已实现范围与测试

源码由以下部分组成：

- `Main.c`：Loader 锁内只做 PE/内存签名与键盘采样引导；首个游戏输入帧执行 EXE SHA-256、安装动作阶段和异步键桥。游戏线程初始化 SDL；窗口失焦时即时释放本插件鼠标输入。
- `Profile.c`、`ProfileData.h`：两版基线、函数签名和偏移，数据源为 `source/tools/controller/profiles.json`。未知版本或签名不匹配不启用动作。
- `Control.h`、`Control.c`：模式、组合层、按键边沿、走跑状态、中立恢复和等距投影方向规则。
- `Input.c`：用户提供的 SDL3 3.4.14 x86 动态加载、热插拔、状态采样、模式震动和鼠标输入。
- `Game.c`、`Plugin.h`：双版本统一业务适配，分别提供各自地址，不在业务里猜版本。

当前已经编译实现，但尚待实机确认：

1. 左摇杆八方向移动；L3 跑步、松杆停止并重置；快捷层内仍可移动。
2. A 调查附近动态交互角色，经过原版句柄去重；静态交互仅复用原版鼠标当前候选。
3. X 左手、Y 右手、B 留空。基础近距离敌人筛选与攻击间目标保持已实现；复杂连招重定向尚未实现。
4. LT 通过游戏自己的异步 Alt 路径防御，避免只写键盘快照导致无效。
5. LB 六槽药品、RB 六槽投掷选择；RT 通过当前角色原版热键绑定切换动作；右摇杆四向选择四组连招。
6. 保留现有菜单打开快捷键、普通 R3 小地图、Esc/方向键桥接；已移除 A→Enter 注入。菜单 A 原生确认尚未实现，不得称为已支持。
7. BACK+START 鼠标模式、左右摇杆速度比例、LT/RT 真实鼠标键、200/1500 ms 模式震动。
8. 断线、失焦、模式及上下文切换清理，重新接入先等待中立，组合层退出避免按住 X/Y 穿透为攻击。

未实现：全菜单几何/格子导航与特殊操作、方向闪避、LT+ABXY 必杀技选择执行、位置型动作长按外扩、角色特殊动作自动映射、精确连招续段重定向、受击震动、图标、游戏内设置与 Steam。RT+L3/R3 默认留空；前十二槽默认使用可配置的原版字母键绑定，未绑定时日志说明，不伪造技能。

本轮机器验证：

- 32 位 GCC，`-Wall -Wextra -Werror` 编译通过。
- 两份真实基线 EXE：散列、17 个函数入口签名、原版目标解析 callsite、投影与世界到地图格转换均通过。
- 69 项输入时间线/八方向检查通过。
- dev1 曾有本体与外传适配回放共 568 项检查通过；dev2 针对真实反馈重建上下文测试（当前 180 个检查点）；使用同调用约定的替身函数验证 this/参数和路由，不等于真实游戏。
- 32 位非游戏测试进程成功加载/卸载 ASI；SDL3.dll 成功加载并包含使用的全部 12 个公开导出。
- 实际运行 `source/build.bat` 完成主插件构建和原有 `verify_build.py` 检查；运行前后四份手柄产物的 SHA-256 全部保持。本轮未重新进行主插件实机验收。
- 独立 BAT 入口也实际执行通过。宿主 PATH 重复累积超过 CMD 长度限制，首次 BAT 测试无法找到 Python/chcp；仅对子进程 PATH 去重后通过，未改系统环境配置。

测试发现并修复：断线前按住 X，恢复中立后首次重按仍被旧 blocked 位吞掉。补充了菜单开启当帧阻断世界动作、窗口失焦即时松鼠标，以及按原版 typed resolver 范围检查受控角色的规则。

两作实机结果均为待测试，具体步骤见《手柄实机验证说明.md》。主插件 ModuleRegistry 仍只注册 DisplayFix，独立 Controller 尚未合入。

## 五、本轮实际核实的接口与证据边界

本轮使用本地 pefile、Capstone 只读检查两份非 Steam 基线的机器码，没有修改参考程序。

- 本体 SubmitPlayerAction `0x477680`、外传 `0x486090`：ECX 是 `WorldRoot+0x30` 的玩家目标管理对象，四个栈参数，`ret 0x10`。
- 本体 SkillRelease `0x4752C0`、外传 `0x483B40`：使用鼠标管理对象，不能与 SubmitPlayerAction 混用 this 指针。
- 本体原版鼠标解析调用点 `0x406031`，目标 `0x4744B0`；外传调用点 `0x40CF41`，目标 `0x482D30`。是否与当前部署中的其它插件共存仍需验证。
- 本体 KeyboardUpdate `0x4CE3D0`、外传 `0x4E3280`；GetKeyboardState IAT 分别为 `0x528390`、`0x5513AC`。
- 本体 `0x40B0E0` 将世界坐标按 64 换算为地图格；普通鼠标移动向 opcode1 提交 `MouseManager+0x1C/+0x20` 地图格坐标。不能照抄资料中的简化公式，把世界坐标直接当成移动动作参数。
- 本体投影逆变换 `0x4F1390`、外传 `0x507E60`，完整 0x45 字节函数一致：世界增量 X=画面增量 X+2Y，世界增量 Y=2Y-X。本体 `0x40B0E0` 与外传 `0x4125B0` 的 0x35 字节世界到地图格函数也一致。
- 本体原版动态交互去重调用点确认：`0x477740` 的 ECX 同样来自 `WorldRoot+0x30`，不能把文档中的“当前玩家对象”误解成 Role 裸指针。
- 世界悬停、战斗目标、本次动作目标必须分层。原始资料中的静态闭合不等于插件实机验收。

## 六、参考资料、依赖与历史失败

参考资料目录始终只读。v0.31 逆向库含两份非 Steam EXE；旧线程 Markdown 主要用于恢复用户操控设计，不作为已实现源码或成功证明。

用户指定 SDL 依赖为 `参考资料/SDL3-3.4.14-win32-x86.zip`，已复制原包到 `source/vendor/SDL3/` 并由构建器提取到 release；原参考包未改动。此前官方下载授权被拒绝，后续使用用户提供的本地包，不再下载。包内许可证以 `docs/SDL第三方许可.txt` 保留原文；原包 SHA-256 固化在 profiles.json，DLL 校验值记录在构建报告。

旧线程实测曾出现：摇杆任何方向都向下走、多数动作无效、鼠标模式基本可用但短震需改为 200 毫秒。本轮尚不能确认这些旧问题的全部根因，也没有宣称修复成功。当前线程新增实机失败反馈为“只有菜单、Esc/Enter 有反应，Enter 在游戏内打开控制台”；反馈尚未明确是哪一作、是否与主插件同时加载，不能扩写为两作相同结论。

主插件内部 HookManager/EventBus 不自动成为跨 DLL 服务。独立开发仍须核对实际 Hook 所有权，不能重复覆盖 DisplayFix 的 Strategy、UI Draw、鼠标 press/release 等入口。

## 八、2026-09-28 调查与操作纠正

用户要求先恢复游戏内调查和操作，暂不扩展菜单导航。dev1 的模拟测试没有覆盖真实游戏中鼠标玩家缓存为空、非交互控件仍 active、普通顶层路由残留等情况，不能以当时的检查数量作为操作有效的依据。

已纠正：

1. 删除 `Game_Keyboard` 的通用 A→Enter 注入；保留真实键盘 Enter，插件不替玩家按它。菜单 A 暂无自动确认业务。
2. 受控玩家改从 `WorldRoot+0x30 -> manager+0x0C` 句柄解析；不再用 `MouseManager+0x38` 的上一帧缓存决定是否进入菜单。玩家暂不可用只阻断动作，不改变菜单语义。
3. UI 判定采用原版真实顶层链 `CJMMng+0x18/+0x1C`、对象 `+0x0C` 后继和资源属性 `0x0D==1`；捕获对象优先。删除全局 ID active 扫描，普通鼠标路由 `+0x40` 不再单独作为全局菜单门。
4. 双版本属性读取入口：本体 `0x4D0210`、外传 `0x4E4EF0`；原版 picker 分别位于 `0x4B4800`、`0x4C7BD0`，原始机器码已成对核对。
5. X/Y 原生 SkillRelease 在调用期间使用已校验的受控玩家和动作目标，调用后恢复鼠标缓存；A 仍调用原版交互资格与 opcode19/23/24，并调用原版 WorldHover setter 提供交互目标反馈。
6. 新增限频 `[输入链]`、`[移动]` 与调查失败原因，区分手柄采样、上下文阻断、原生阶段是否运行及动作是否提交。

诊断门编号：0=未发现 UI 门，1=捕获对象，2=真实顶层交互页面，3=世界尚不可用，4=控制句柄无法解析为有效玩家。日志包含界面 ID、对象地址、权威玩家与鼠标缓存、控制句柄、原生帧计数、按键、摇杆、角色状态和活动动作地址。

已证明的是旧实现有错误的阻断与 Enter 注入设计，以及新实现通过新增回放；尚无日志证明本次实机失效恰好由哪一项触发。下一步应测试走路和 A/X/Y，并查看上述日志，不能把候选原因宣布成已实机闭合的根因。
