# 体积分析与发布裁剪说明

> 当前接续（2026-10-02）：统一DisplayFix＋QOL＋Controller、TOML及静态SDL3.4.16；用户确认性能候选1掉帧缓解、功能正常、实机验收通过。build.bat现在一次输出发行EDSlash.asi与debug/EDSlash_debug.asi，优化相同、运行段一致，UPX仅处理发行副本。MOD设置界面后置，未来F12和L3＋R3。最新配置／构建／验收见《统一配置与基础迁移说明.md》《完整接档说明.md》；下文旧阶段保留历史，不扩为所有设备或新产物全部实机。

2026-10-02。用户询问统一ASI未压缩及UPX版本为什么较大。本轮仅分析当前产物、对临时副本剥离符号并测量，不修改源码构建选项或现有release性能测试件。

## 当前体积来源

当前EDSlash.asi为4,872,982字节；UPX件2,397,462字节。文件包含三模块、静态SDL 3.4.16及所需编译器运行库，不是单独Controller业务代码。

| 未压缩文件部分 | 文件字节数 | 意义 |
|---|---:|---|
| .text | 2,407,936 | 实际机器码，主要还包含SDL及公共依赖 |
| COFF符号／名称表尾部 | 1,139,990 | 36,852个符号及字符串表，运行不需要完整保留 |
| .debug各段 | 542,720 | 调试信息，发布可以剥离 |
| 常量、数据、异常展开、导入／导出、重定位、头部等 | 782,336 | 混合运行数据，不应一概删除 |

UPX仍原样携带1,139,990字节尾部，占压缩件约47.6%。当前是没有做发布剥离的验证构建；CMake Release不保证静态依赖和GNU符号信息自动消失。

Controller自有目标文件总计88,455字节，其中代码／常量／已初始化数据目标段合计45,176字节。DisplayFix对应目标段90,904字节，QOL8,072字节。这些是目标文件量级参考，不是经过链接映射精确分摊的最终ASI占用。不能把libSDL3.a的4,550,144字节直接当作全数进入ASI。

.bss逻辑大小557,392字节、文件占用为0。TOML缓冲和日志队列等未初始化大数组主要影响运行内存，不是磁盘体积膨胀的直接原因。

## 临时副本实验

路径为source/.build/SizeAnalysis；没有替换release。

| 处理 | 字节数 | 约MiB |
|---|---:|---:|
| 当前未压缩件 | 4,872,982 | 4.65 |
| 当前UPX件 | 2,397,462 | 2.29 |
| strip --strip-unneeded后 | 3,207,581 | 3.06 |
| 剥离后再UPX -9 | 1,084,829 | 1.03 |

剥离后.text／.data／.rdata原字节逐段一致。两个临时件均通过非游戏加载、InitializeASI及重定位检查；压缩完整性检查通过。没有据此宣布剥离件两作实机通过，也没有把该实验混入正在等待性能复测的候选。

## SDL为何仍有较多代码

当前SDL动态API表把公开接口指向对应REAL实现，使静态链接时许多通用函数仍被引用。符号实际显示包含软件像素转换、PNG解析、WAV读取等；关闭Render／Audio等子系统不等于所有通用图像／文件处理实现都不会链接。Video公共代码又为官方DirectInput检查保留，运行只初始化GAMEPAD，已经验证不初始化VIDEO／AUDIO。

进一步裁剪需先做链接映射和上游受支持配置验证，不能随意删文件、修改SDL内部分支或取消设备后端。最直接的发布优化是保留完整验证件作诊断，另输出剥离符号的发布件，再做UPX；当时分析阶段没有改变发布流程；后续用户已授权自动双产物，当前构建流程已实现，见最新接档。

磁盘体积、运行内存和多敌人CPU耗时是不同量。删除不参与加载的符号／调试数据不能作为外传掉帧已经修复的证据，性能继续按完整聚合日志与同场景对照验收。

## 当前发行与完整版（2026-10-02）

已纳入build.bat：同一带-g优化链接件保留为_debug，发行副本自动去符号，UPX只压发行副本。完整版为项目及SDL提供源码行信息，体积大于原4.87MB部分符号验证件；这是诊断资料增加，不是游戏功能增加。实际体积和散列由统一构建验证.json记录。发行／完整版运行段及虚拟布局逐段相同，不以关闭设备后端来换取体积。
