# 自动拾取与地面物品名称说明

核对日期：2026-10-01。本文恢复 QOL 合并前旧说明中仍适用于当前源码的内容；当前行为以 source/src/Modules/QOL 为准。旧资料的验证记录标为“合并前-alt”，原文没有明确整合版本号的地方不补造 dev 编号。

## 一、当前实现与配置

主插件 BladeSwordQOL.asi 的 ModuleRegistry 注册 DisplayFix 和 QOL；Controller 仍独立构建。QOL 分为 GroundItems、ItemClassifier、AutoPickup，由 QOLModule 读取配置和安装入口。

插件启动时读取同目录 BladeSwordQOL.ini：

```ini
[GroundItems]
AlwaysShowNames=1

[AutoPickup]
Mode=2
IntervalMs=100
DropDelayMs=1000
```

缺少配置项时使用上述默认值。名称开关以零／非零判断；Mode 钳制到 0～4，两个时间参数钳制到 0～3000 毫秒。启动后修改配置需重新启动游戏。主构建保留已有 INI，不自动补写 QOL 缺项。

| Mode | 自动拾取范围 |
|---:|---|
| 0 | 关闭 |
| 1 | 金钱 |
| 2 | 金钱＋回复道具 |
| 3 | 金钱＋回复道具＋宝石＋护身石 |
| 4 | 所有合法且满足落地／等待条件的地面物品 |

## 二、名称常显

GroundItem Update 包装先执行原版更新，再执行 GroundItems_AfterUpdate。启用名称常显时调用游戏自己的 ShowItemName(object, 1)。插件改变名称显示的请求时机；名称文本、字体、颜色、背景及实际绘制继续由原版负责。

名称关闭但自动拾取开启时，GroundItem Update 仍用于生命周期跟踪。名称与自动拾取都关闭时不安装业务 Hook，但 QOLModule 仍先检查三个入口签名和配置路径；不能把“全部关闭”解释为跳过初始化校验。

## 三、原生扫描与手动 Z

Input Update 包装先执行原版输入更新，再按周期调度自动拾取。插件从原版动作槽表寻找 vtable 和 GroundManager 均匹配的唯一拾取 Action 对象，调用其 ActionEntry(action=22)。无候选或存在多个候选时不猜对象，不发起拾取。

距离、背包容量、入包、音效和地面对象删除由原版处理。插件不直接写背包或自行删除掉落物。

自动过滤标志只在这次同步 ActionEntry 调用期间为真，原函数返回后立即清零。玩家手动按 Z 时过滤函数直接放行，不受 Mode 的自动分类筛选影响。Mode=4 跳过分类读取，但仍检查合法地面对象、落地状态和等待时间。

## 四、两个时间参数与落地条件

IntervalMs 决定扫描周期；正数时首次输入帧只建立计时起点，等待完整周期后才首次扫描。0 表示每个原版输入更新帧都允许扫描。

DropDelayMs 决定物品从插件首次观察到当前生命周期开始的最短保留时间。它不是两次扫描的间隔，0 也不会绕过原版落地条件。

每个自动候选必须同时满足：

```text
flight_tick >= 原版飞行动画总 tick
vertical_offset == 0
当前生命周期已观察时间 >= DropDelayMs
```

动画总 tick 必须为 1～10000；读取失败或状态异常时暂不自动拾取。

GroundItems 使用 64 桶×4 路的固定跟踪表。对象地址变化、物品记录变化、飞行动画 tick 回退或超过 750 毫秒未更新，会重新计时；同桶满时替换最久未更新项。替换和无法确认生命周期只会延后拾取。DropDelayMs=0 时不维护等待记录，但仍检查原版落地。

## 五、对象与分类

| GroundItem 偏移 | 语义 |
|---|---|
| +0x63 | 垂直偏移 |
| +0x67 | 对象 kind，地面物品为 0x17 |
| +0x7D | 飞行动画 tick |
| +0x81 | 物品记录指针 |

ItemClassifier 同时核对 GroundItem vtable 和 kind。物品记录 +0x04 保存列数，+0x08 保存值数组指针，Type 读取数组下标 2。分类不依赖中文／日文名称。

| Type | 当前分类 |
|---:|---|
| 0 | 金钱 |
| 10 | 回复道具 |
| 30、35 | 宝石 |
| 50 | 护身石 |
| 其他 | Other；模式 1～3 拒绝，模式 4 允许通过分类门 |

合并前-alt 旧资料记录 Type 40 为任务类；本轮未读取游戏资源或 EXE 重新验证该语义。当前源码只把它归入 Other，没有单独的“任务类”分支。

两作地址与 VA／RVA 说明见[逆向工程知识库](逆向工程知识库.md)的“QOL 当前源码地址与对象结构”。

## 六、初始化、回滚与日志

QOL 使用 Runtime 的 GameProfile，不建立第二套游戏识别器。主 ASI 通过 Win32Bridge 动态解析系统 API，构建目标保持零导入；入口跳转由 X86Detour 提供。

安装前验证 GroundItem Update 的 7 字节和 Input Update／PickupEntry 各 5 字节。先 Claim 对应公共 Hook，再安装；不是任意入口都能套用的自动反汇编 Hook 库。

失败回滚先关闭自动拾取，再分别撤销三个物理入口。任一入口未完整撤销时保留 owner 和必要网关；HookManager_ReleaseOwned 本身不负责恢复机器码。RuntimeWin32_WriteCode 的返回 2 表示字节已写入但缓存或保护处理失败，安装器保留安装记录，不能解释为缓存／保护均成功。上述流程仅支持初始化期间同步回滚，不宣称运行中热卸载安全。

dev6 起 QOL 向同目录 BladeSwordQOL.log 追加启动参数、关闭／签名或安装失败、等待唯一对象及首次开始扫描信息。连续等待第十次记录一次等待；首次成功定位并发起扫描记录一次运行。日志 API 不可用不阻止必需 API 已就绪的业务运行。扫描日志证明调用已发起，不证明物品已入包。
