# 自动拾取与地面物品名称说明

> 文档维护约定：本文按主题维护当前有效的技术正文，不再追加版本更迭、日期同步或发布补丁章节。版本变化、旧版散列、阶段测试与用户反馈统一记入[版本与更新记录](版本与更新记录.md)；技术结论变化时直接修订对应正文。

## 模块与配置

QOL由QOLModule、GroundItems、ItemClassifier、AutoPickup组成，在统一ModuleRegistry中注册。EDSlash.toml设置如下，普通参数在安全输入边界应用，修改不清空已观察的掉落生命周期。

```toml
[qol.ground_items]
always_show_names = true
[qol.auto_pickup]
mode = 2
interval_ms = 100
drop_delay_ms = 1000
```

mode=0关闭、1金钱、2再加回复、3再加宝石/护身石、4全部合法落地物品；时间范围0..3000毫秒。候选范围不绕过原版距离、背包或资格。

## 二、名称常显

GroundItem Update 包装先执行原版更新，再执行 GroundItems_AfterUpdate。启用名称常显时调用游戏自己的 ShowItemName(object, 1)。插件改变名称显示的请求时机；名称文本、字体、颜色、背景及实际绘制继续由原版负责。

名称关闭但自动拾取开启时，GroundItem Update 仍用于生命周期跟踪。基础桥在初始化时一次安装，业务开关只更新参数，不重装Hook；不能把全部关闭解释为跳过初始化校验。

## 三、原生扫描与手动 Z

Runtime公共InputFrame在原版input_update返回后发布END，QOL在该事件按周期调度自动拾取。插件从原版动作槽表寻找 vtable 和 GroundManager 均匹配的唯一拾取 Action 对象，调用其 ActionEntry(action=22)。无候选或存在多个候选时不猜对象，不发起拾取。

首次定位每输入帧最多1024登记槽，连续读块最多6144字节，完整范围最多32768槽；扫描完确认唯一再发动作22。已绑定缓存每次核对登记指针、代数与manager，失效或切表重扫。该预算减少单帧开销，首次定位仍可能需32输入帧，不等同绕过加载/落地等待。

距离、背包容量、入包、音效和地面对象删除由原版处理。插件不直接写背包或自行删除掉落物。

自动过滤标志只在这次同步 ActionEntry 调用期间为真，原函数返回后立即清零。玩家手动按 Z 时过滤函数直接放行，不受 Mode 的自动分类筛选影响。Mode=4 跳过分类读取，但仍检查合法地面对象、落地状态和等待时间。

## 四、两个时间参数与落地条件

IntervalMs 决定扫描周期；正数时首次输入帧只建立计时起点，等待完整周期后才首次扫描。0 表示每个原版输入更新帧都允许扫描。

DropDelayMs 决定物品从插件首次观察到当前生命周期开始的最短保留时间。它不是两次扫描的间隔，0 也不会绕过原版落地条件。

每个自动候选必须同时满足：

```text
flight_tick >= 原版飞行动画总 tick
vertical_offset == 0
当前生命周期已观察时间 >= DropDelayMs
```

动画总 tick 必须为 1～10000；读取失败或状态异常时暂不自动拾取。

GroundItems 使用 64 桶×4 路的固定跟踪表。对象地址变化、物品记录变化、飞行动画 tick 回退或超过 750 毫秒未更新，会重新计时；同桶满时替换最久未更新项。替换和无法确认生命周期只会延后拾取。DropDelayMs=0 时不维护等待记录，但仍检查原版落地。

## 五、对象与分类

| GroundItem 偏移 | 语义 |
|---|---|
| +0x63 | 垂直偏移 |
| +0x67 | 对象 kind，地面物品为 0x17 |
| +0x7D | 飞行动画 tick |
| +0x81 | 物品记录指针 |

ItemClassifier 同时核对 GroundItem vtable 和 kind。物品记录 +0x04 保存列数，+0x08 保存值数组指针，Type 读取数组下标 2。分类不依赖中文／日文名称。

| Type | 当前分类 |
|---:|---|
| 0 | 金钱 |
| 10 | 回复道具 |
| 30、35 | 宝石 |
| 50 | 护身石 |
| 其他 | Other；模式 1～3 拒绝，模式 4 允许通过分类门 |

Type40是否为任务类缺少当前资源复核；源码把它归入Other，没有任务类专用分支。

两作地址与 VA／RVA 说明见[逆向工程知识库](逆向工程知识库.md)的“QOL 当前源码地址与对象结构”。

## 六、初始化、回滚与日志

QOL 使用 Runtime 的 GameProfile，不建立第二套游戏识别器。主ASI允许标准Windows导入；入口跳转由X86Detour提供。

安装前验证 GroundItem Update 的 7 字节和 Input Update／PickupEntry 各 5 字节。物理输入刷新归Runtime，QOL不重复安装；其它入口先Claim再安装；不是任意入口都能套用的自动反汇编 Hook 库。

失败回滚先关闭自动拾取，再撤销自己实际安装的入口。任一入口未完整撤销时保留 owner 和必要网关；HookManager_ReleaseOwned 本身不负责恢复机器码。RuntimeWin32_WriteCode 的返回 2 表示字节已写入但缓存或保护处理失败，安装器保留安装记录，不能解释为缓存／保护均成功。上述流程仅支持初始化期间同步回滚，不宣称运行中热卸载安全。

QOL向ASI旁EDSlash.log 追加启动参数、关闭／签名或安装失败、等待唯一对象及首次开始扫描信息。连续等待第十次记录一次等待；首次成功定位并发起扫描记录一次运行。日志 API 不可用不阻止必需 API 已就绪的业务运行。扫描日志证明调用已发起，不证明物品已入包。



## 成功拾取提示

自动/手动调用前复制GBK名字、模板ID、玩家、场景及背包，返回后比较相同对象的实际增长；返回1不代表成功。钱比较背包+0x20，物品统计136槽中模板+0x18的数量+0x1C。名字在地面对象销毁前复制，截断保持完整GBK字符。

提示通过UI_DRAW_END绘制，x=16、起始y=192、行距22、最多6条、保留5秒，切图/玩家变化清除。关闭自动扫描时手动成功仍显示。不重复安装显示Draw入口，不与Controller私有耦合。具体阶段验收见更新记录，回归方法见《构建与测试说明.md》。
