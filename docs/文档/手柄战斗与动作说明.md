## 世界操控与组合层

默认新模式使用双扳机必杀和面键切连招。旧模式兼容开关只改变单LT面键分工；普通战斗、RT技能直发、RB投掷直发、LB药品及双扳机动作菜单保持各自职责。

| 输入 | 默认新模式 | 旧模式兼容开启 |
|---|---|---|
| X | 当前左手动作 | 同左 |
| Y | 右手选中四套连招时沿既有历史推进；普通技能执行该技能；投掷不进入此分支 | 同左 |
| 单RT＋技能键 | 既有十四槽即时请求，原资格和消耗保留 | 同左 |
| RB／LB＋六槽键 | 原投掷直接请求／原药品使用 | 同左 |
| 单LT＋Y/B/A/X | 默认切第1/2/3/4套；配置为dpad时面键不切组 | 必杀首次准备、同键再次新按释放 |
| 单LT＋上/右/下/左 | 配置为dpad才切第1/2/3/4套 | 固定切第1/2/3/4套 |
| LT＋RT＋A/B/X/Y | 第1/2/3/4必杀，首次准备、再次新按释放 | 同左 |
| LT＋RT＋右摇杆 | 拨杆才打开原右手动作菜单，右杆按几何导航；回中保留候选 | 同左 |
| 菜单内R3 | 收起当前侧并重建另一侧候选，不提交浏览过的那侧 | 同左 |
| 菜单松开任一扳机 | 只调用原提交入口确认当前侧、关闭菜单；不直接出招 | 同左 |
| 普通BACK＋START | 保留救援鼠标模式 | 同左 |

单LT继续防御和左杆方向闪避；双扳机非菜单状态保留防御，左杆不兼办单LT闪避。动作菜单展开时保留LT防御，禁止闪避、面键必杀/攻击以及R3小地图。双扳机不代办单RT技能、单LT套组、肩键物品或BACK/START救援；同一新边沿只交一个层。菜单关闭后刚才持有的按钮逐个等释放，两摇杆分别等回中；还按住LT时可继续防御。

```toml
[controller.combat]
single_trigger_ultimate = false
combo_switch_input = "face"
```

single_trigger_ultimate=false为新模式，true恢复单LT面键必杀。combo_switch_input允许face或dpad；新模式二选一，默认face顺时针Y/B/A/X。旧模式忽略此项并固定十字键切套组。手改配置文件需重启；发布构建同步新增键并保留原值、绑定与注释。配置服务支持按face/dpad枚举名或编号保存，未知名拒绝，复用原子保存和帧应用链。

## 物理输入交接与移动

真实物理键/鼠标新边沿与摇杆输入分别判定来源，稳定按住不误接管。交接先停止旧来源未提交请求，再保留已成功动作的原生历史和进度；不每次切层清掉全部战斗锁定。失焦/断线/场景变化等待释放，避免旧held泄漏。

BACK+START提供主动鼠标模式，普通手柄仍独立组织目标与动作。模式切换不代表完整原生GUI和鼠标焦点隔离都已实现。

R3在世界玩家有效时允许GAME/MENU层走原Tab小地图入口，菜单仍独占A/B及导航，RT组合层不追加Tab。连续摇杆远目标经过原地图通行资格的有界直线检查，墙前缩短、第一格被挡则不启动原绕路。原速度、最终寻路、动态占用和碰撞保留。日志可自动给出世界位置和请求/有效目标；实际复杂墙角手感仍待验收。

## 快捷技能、投掷与套组数据

### 四套连招可以按编号独立读取

本体 `0x4C4A70`、外传 `0x4D9050` 接受明确索引 0..3 时返回对应列表；只有传 -1 才依赖当前右手选择字段。列表头保存数量/首末节点，节点 +0x08 保存原版选择数据。

右手HUD12C为-1..-4时，Y持有对应独立套组进度；普通已选技能则按该选择码解析，不调用含必杀/投掷优先分支的原right_get。快捷技能与投掷的成功通知不能推进 Y 的套组游标。只在真正的套组步骤成功建立时推进。

### 原版投掷快捷执行器不能直接当作直投接口

两版十二槽执行器：本体 `0x4C3CA0`、外传 `0x4D8260`。

- 前六槽调用物品使用业务。
- 后六槽将对应物品切入右手，并设置投掷选择状态。
- 再次按已选的同一投掷槽会取消选择，恢复上一右手动作。

原版右手读取还有投掷专门分支：在对应类别与槽有效时，从物品 +0x20 生成 `值+10000` 的特殊选择码；数量 +0x1C 必须有效。因而不能只拿通用投掷招式 ID，也不能简单“调用旧快捷执行器后再调用 Y”。

直接投掷沿具体逻辑槽解析物品专用选择码，执行与消耗仍由原版处理。物品消耗完、槽被移动或重复选择时，都不能污染 Y 的套组状态。

请求分别区分左手、套组、快捷技能、指定槽投掷与药品。来源、选择、目标、期限和提交代次绑定到实际动作；套组编辑或切换不能让旧通知推进新组。

## 请求来源、解析与生命周期

### 已核对的业务出口

下表给出可复用的原生业务层，不代表直接调用它们就能跳过上游资格与状态协议。

| 语义 | 本体 1.05 | 外传 2.01 | 边界 |
|---|---:|---:|---|
| 玩家动作提交 | `0x477680` | `0x486090` | ECX=玩家管理器，四个栈参数，ret 0x10 |
| 原生招式执行/运行时创建 | `0x420E90` | `0x429480` | ECX=Role，实际 Method、显式点或空、目标 Handle，ret 0x0C |
| 实际 Method 记录解析 | `0x420BE0` | `0x4291D0` | 原生招式执行入口内调用，保留资格 |
| 执行资格检查 | `0x4244C0` | `0x42D120` | 执行入口内检查，不能直接创建 Runtime 绕过 |
| 两点计算当前角色 Facing | `0x429CB0` | `0x432CB0` | 原版 8/16 向模式由角色决定 |
| Facing Setter | `0x429D20` | `0x432D20` | 同步动画方向，不能只写 Role+0x14B |
| 两点对齐朝向 | `0x429D60` | `0x432D60` | ECX=Role，两点参数，ret 8 |
| 左右手选择读取 | `0x4C40D0/0x4C40E0` | `0x4D86B0/0x4D86C0` | 右手含准备动作、投掷与负值连招槽，不能当简单字段读 |
| 左右手选择设置 | `0x4C4280/0x4C41F0` | `0x4D8860/0x4D87D0` | 复用原版选择及显示更新，不模拟热键 |
| 药品/投掷六槽业务 | `0x4C3CA0` | `0x4D8260` | 前六槽执行物品，后六槽选择投掷动作，业务不同 |
| 动态交互去重 | `0x477740` | `0x486150` | 通过后发 opcode19；静态交互资格另算 |

普通提交优先继续走原生玩家动作协议：9 为实体立即尝试，10 为显式世界坐标，11 为追近后释放。后续 Role 更新、资格、距离、碰撞、伤害和 Runtime 仍由游戏负责。

关键新证据：原生 ExecuteMethod 内部本身会从显式世界点或实体目标计算位置，并在自身条件满足时调用两点对齐朝向，再创建 Runtime。这是复用原版动作语义的正确层次，不需要总在外面无条件强刷 Facing；但它仍触发下节的历史记录回写，必须一起拆分。

### 不能跳过的选择解析层

需要保留三种不同数据：

1. 普通技能 selector：表示玩家选择的技能。
2. RightSelectionCode：还包含 -1..-4 四组连招槽。
3. final Method：实际交给动作协议执行的招式 ID。

原 SkillRelease 本体 `0x4752C0`、外传 `0x483B40` 同时承担了读取鼠标和技能解析，因此不再作为普通手柄模式的总入口。

独立解析层保留它的业务规则：

- 枚举 Role+0x193 的角色候选容器，并经过原版技能资格查询。
- 读取 Skill.gop 组与 Method 记录，匹配 selector；不能直接把 getter 返回值当作 final Method。
- 有动作历史时匹配序列前缀、选择可续接成员。
- 判断记录中的时间窗口和方向条件。方向来自手柄目标/地面点，历史来自控制器动作历史。
- 正确处理失败、不可用、特殊选择值，以及不同左右手释放策略；不能用首个候选或最接近的 ID 兜底。

已展开的内部函数：

| 内部职责 | 本体 | 外传 | 当前判断 |
|---|---:|---:|---|
| 序列前缀匹配 | `0x4750F0` | `0x483970` | 参数传入序列，函数体未读取 MouseManager this；可评估封装复用 |
| 后续成员解析 | `0x475280` | `0x483B00` | 参数传入组和索引，读取实际记录表；可评估复用 |
| 时间/方向资格 | `0x475160` | `0x4839E0` | 仍读 this+0x38 取得角色；应按证据拆成显式角色、历史、目标点参数的独立语义函数，不伪造鼠标对象 |

以上“可复用”仍需检查所有下游与异常路径，不能因局部没有鼠标坐标就宣称整条链已完全隔离。

### 运行时回写也是输入来源的一部分

已成对核对：Runtime 初始化时，在当前受控玩家等条件满足后，会回写动作历史。

- 本体 Runtime 初始化 `0x4693A0`，调用点 `0x469793 -> 0x475070`。
- 外传 Runtime 初始化 `0x477000`，调用点 `0x4773F3 -> 0x4838F0`。
- 两者传入实际动作的组信息与方向相关参数，this 使用全局 MouseManager。
- 记录函数更新 +0x48/+0x4C/+0x50/+0x54/+0x58 和 +0x5C/+0x60/+0x64 历史链。
- 记录函数还根据全局右手输入标志（本体 `0x557D30`，外传 `0x588BBC`）决定是否推进 HUD+0x120 的自定义连招游标。

因此，即使直接调用 ExecuteMethod，也不是整条调用链天然与鼠标无关。必须把“当前玩家、由手柄发起的动作实际建立成功”作为业务通知，更新控制器动作历史和相应连招游标。鼠标模式保留原处理，AI 动作不能受到手柄意图影响。

额外全局门已进一步核对：本体 `0x5457F0`、外传 `0x574D10` 初始均为 1，subtype5 自动续段与 effect command9 建立后续动作时临时置 0，随后恢复为 1。其作用包括避免自动衍生动作再次记入输入历史，新历史服务必须保留这一区别；不能每观察到一个 Runtime 就追加一次手柄按键。Runtime+0x6F 的值由两版原生 8 向点差换算函数生成，再作为历史方向参数传入。

生命周期必须覆盖：技能被中断/自然结束的历史维护、左右手并发或快速切换的归属、失败动作不能推进游标。不能依靠当前仍按着哪只按钮猜一次已提交动作的来源。

### 手柄动作上下文与生命周期

每次动作明确保存：控制角色 Handle、输入来源与左右手、选择类型/选择值、有效目标 Handle、显式世界点/方向、提交代次、所处阶段与重试期限。

流程：

```text
手柄按键/方向意图
  → 世界上下文和角色资格
  → 保持或取得手柄目标，形成显式方向/点
  → 按角色数据和控制器历史解析实际 Method
  → 提交原生 opcode9/10/11
  → 原版执行、资格、距离、碰撞、Runtime
  → 受控玩家动作通知，更新控制器历史
  → 结束/中断/失效时清理对应状态
```

重试属于手柄动作，不写 MouseManager+0x6C/+0x70/+0x74，也不允许 target=NULL 后回退取鼠标。重试前重新校验 Handle 和角色生命周期；目标失效时明确取消或按设计重选，不悄悄换成鼠标候选。

RT/LB/RB 层切换不是战斗结束，不能顺便清空全部锁定。明确新方向允许在合适动作边界重定向；没有新方向则保持原目标。subtype5 同栈续段需要独立接入原版新 Method 边界，不能靠下一帧轮询补做，更不能任意改运行中每一 hit 的目标。

### 输入所有权与鼠标模式切换

仅建立新的动作发送端还不够，必须阻止普通手柄模式下的旧鼠标生产端同时发送动作、改朝向、改焦点或滚动地图。

- 原版 MouseTargetResolver 可包含玩家/地形维护，不能未经拆解就跳过整函数。
- 原版每帧输入更新混合了重试、历史超时、边缘滚屏、防御和其它业务，也不能整段停掉。
- 按来源拆出“鼠标取点/命中/按钮动作/边缘滚屏”和必须继续运行的世界、角色维护。
- 防御改成原生 opcode16 后，还要处理原版“真实 Alt 松开→取消防御”的输入生产分支，否则手柄防御会被下一帧取消。
- 切换模式时清理该来源拥有的按钮、重试和焦点，保持明确的交接；普通按键层切换不等于模式交接。
- 指针显示需要分别核对系统鼠标和游戏自绘指针；真实鼠标位置不应成为普通手柄模式是否生效的判据。

模块不得重复覆盖已经登记的公共Hook。共享需求通过Runtime服务/事件接入，调整公共能力前解释原因。

## X/Y连续请求与持续技能边界

Control_Step的pressed为新边沿，held为持续按住；没有X/Y长按选择门。新按下立即请求，持续按住且无活动动作/待重试时才发下一请求。松开阻止新连发，不等于清空仍在期限内的短缓冲。切层屏蔽与真实松键分别处理。

新按另一键可以进入原资格/窗口判断，两键同按用最新边沿选择。held不是让某个Runtime一直活动，不能因按住连发就声明蓄力技能已支持。

双版本技能记录构造器先把子记录计数及指针清零。本体 0x4D6510、外传 0x4EB980 的标准首次加载路径随后调用固定字段解析（0x4D62A0 / 0x4EB6E0），解析末尾调用标志派生 helper（0x4D6180 / 0x4EB5E0）；此时子记录计数仍是 0，因此该次 +0x98 / +0x9D 派生结果为 0。固定字段解析返回后，加载器才读取子记录数量、分配每条 0x20 字节的数组并加载子记录；已核对的函数返回前没有再次派生。

在两份可执行节中扫描 rel32 直接调用，派生 helper 分别只有 0x4D64EF / 0x4EB967 一处候选，均是上述提前调用；未发现 helper 地址被作为完整常量函数指针引用。该扫描不排除所有间接修改或其它外部数据写入，不能升级为“全游戏绝无长按技能”，但足以撤销“已证明实际存在需要按住的玩家技能”的强结论。

目前确认的是条件性结束代码存在，以及标准首次加载不启用该标志；没有确认任何具体玩家技能必须长按，也没有确认蓄力松开发动。Game_Async的影响必须限定为“若运行时实际启用了此标志，则会把其视为已松开”，不能写成用户当前普通战斗必然被该机制中断。实际名单和活跃标志仍未实机读取，亦未向游戏附加调试器。

若后续确认实际持续技能，保存角色/世界/Runtime、来源按钮和执行序号，区分待请求、已提交与已活动；不能以X或Y任意按住维持另一动作，也不能全局伪造右键或修改共享Method标志。失焦、断线、切图、模式切换必须清理自身状态。未确认具体玩家技能名单，原资源与活跃标志需独立验证。

## 原生历史与战斗衔接

### 原生历史与衔接规则

解析失败时，若历史已结束，原版清理历史并再尝试；本体0x47546B..0x475473、外传0x483CEB..0x483CF3。缺少该分支会让不匹配历史持续阻挡混合预设首招，直到历史超时。

Runtime结束时同步通知历史：本体0x4699D0→0x475060，外传0x477630→0x4838E0。只在下一帧轮询ActiveRuntime为空会错过同帧结束并续段的窗口。

### 当前请求处理

## 体力规则

EDSlash.toml的gameplay.combat含charge_guard_on_hit/free_run，gameplay.stamina含guard_mode、guard_percent、recovery_mode、recovery_percent。

防御original模式保留角色原周期规则；percent模式按当前最大体力计算，恢复guard模式跟随实际防御幅度，percent模式独立计算。百分比0..100.00、最多两位小数，内部用百分之一整数。最大体力200时12.50扣25、5.25回10.5；不按剩余体力或原周期倍数算。通过角色虚表+0x80读当前最大体力，原体力调整函数处理上下限和耗尽。

开启受击扣费时不在空防御期间周期扣费；攻击只有实际减少敌方生命才恢复，挥空、零伤害、治疗和NPC不计。真实受击入口从虚表+0x6C定位，不能因Getter相同猜入口。关闭该规则恢复原版周期防御并停止附加命中恢复。free_run开启时全程免跑步体力，不按追击敌人判定。

原最低5点防御门和特殊穿防保留，不把全向格挡当永久免伤。防御诊断用于区分姿态、体力与攻击反应。

pending请求与已提交issued动作分别记录来源；不能只用右手布尔值区分技能、套组、投掷。有限缓冲是状态受限重试，不是无限预输入或强制取消原动作。普通手柄不以鼠标位置组织技能。

离线宿主验证资格、库存、同槽连投、空槽、Y隔离、原受击网关、HP差、幅度与上限；实际全技能、真实消耗及全部配置仍按实机覆盖判断。阶段测试数和反馈只记在更新记录。方向闪避、全向格挡、必杀和图标当前机制见对应专题正文。

## 防御与全方位格挡

LT调用原防御资格和opcode16/状态事件，保持原角色朝向，避免ON事件按鼠标点重定向。原Alt松开生产端需按来源处理，不能下一帧把手柄防御取消。全向格挡只接管当前有效防御玩家，保留原最低5点及特殊穿防。

受击扣费、实伤恢复和全程免费跑步按当前TOML设置，幅度以最大体力百分比计算，详见本文件对应主题章节。

- gameplay.combat.omnidirectional_guard=true。有效防御姿态下当前玩家普通攻击可全方位格挡，false恢复原版方向分支，默认true，运行中通过公共配置安全应用。当前玩家手柄与物理Alt共用；未防御角色、敌人和原特殊穿防不被改成免伤。
- 两作方向分支：本体0x41A034，外传0x422543，原指令为6字节jle。包装保存全部寄存器/标志；仅接管有效玩家防御时走已有格挡反应块，其它情况精确重放原条件分支。特殊受击反应仍由后续原版处理。
- 手柄防御开启事件后，用原版转向接口保持事件前角色的朝向，避免原ON事件用鼠标点改变最终朝向；8/16向通过原方向换算反查，不直接写Facing或伪造鼠标。

两作原最低防御体力阈值都是5.0点：本体常量0x528AEC，外传0x551C08。原防御资格与受击后退出检查都用这个最低值；原版并不等到精确0。最大体力80、每次1%=0.8点时，5.5被扣到4.7，虽仍有体力，防御已退出。全方位开关仍保留此门槛，用户尚未要求修改它。

原受击路径先看0x6A防御状态，再看八向角度差，部分方向进入正常伤害；特殊反应method+0x60=3也不走普通格挡的提前成功返回。全向开关取消已有防御的角度限制，保留特殊反应/硬直/原体力门。当前局部路径未发现独立“防御累计时间或次数达阈值必定破防”的计量，不能据此断言整个游戏绝无其它破防状态。

[防御诊断]观测受击前后HP、体力、防御状态、角色状态、朝向、反应与双方位置；不覆盖特殊行为。有体力仍扣血需区分低于5点、姿态失效、特殊反应及方向开关，不能只凭配置日志推断。

## 方向闪避与受击免疫

LT+左摇杆按投影换算后的摇杆方向直线闪避，启动后锁定该次方向。松杆回中后才能再触发。原版启动冷却、硬直、当前技能资格和状态动画保留；改变的是状态17的初始化与逐帧位移，不是直接瞬移或伪造鼠标目标。

gameplay.combat.directional_dodge=true开启新位移；false时闪避目标门、初始化和逐帧运动全部回原版函数，原版需要目标或不接受当前启动时仍按原版处理。dodge_distance是世界单位，64单位=1地图格，默认128=2格，范围16至512；在8个逻辑更新周期内完成。只在新位移开启时生效，通过保存接口修改后在动作安全点应用；手改文件后重启读取。

每8世界单位检查途经地图格、原版地形资格和占用；斜向跨格同时检查两侧格，遇障碍提前结束，不触发原版近邻找空格的绕行。调用原版grid_commit更新占用表，再调用角色虚表+8的位置setter保持世界位置同步。鼠标接管或松开LT不会让已开始的新闪避突然回圆弧；新原版闪避初始化会清除旧新位移所有权。

当前Guard.c方向闪避启动调用role_effect(0x66,1,1,0)，8次逻辑更新的第4次结束时清0x66，碰撞提前结束时也立即清除。代码设计的免疫窗口覆盖前半段，不是整个闪避全程免伤；这不是渲染帧计数，未把它换算成固定毫秒。

两份实际基线确认0x66消费路径：状态字节基址Role+0x1AF，索引0x66对应+0x215；角色受击虚表+0x34在本体419E50/外传422330读取该字节，非0返回1。普通受击入口419E80/422360调用此虚方法，返回非0则在伤害计算前退出。因此可以确认当前闪避开启的是原版普通受击免疫状态。

状态Getter还会检查另一标志0x4000；不能把日志中所有“防御0但HP不变”都归于闪避。治疗/特殊技能类别有不同分支，环境或脚本伤害也未证明都走相同门。实际窗口尚未逐帧统计；现有结论为源码+双基线静态证据，原始指令见[闪避受击免疫与界面入口原始证据.txt](../证据/逆向分析/闪避受击免疫与界面入口原始证据.txt)。
