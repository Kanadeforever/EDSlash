## 统一入口与模块边界

生产链为source/src/Main.c→Runtime→ModuleRegistry，顺序注册DisplayFix、QOL、Controller。只有Main.c定义DllMain/InitializeASI；ControllerModule.c是模块接入层，业务保留在Controller目录。

Runtime只识别一次游戏PE身份，模块取同一GameProfile并执行自身内容签名门。Controller另核本体／外传Steam与非Steam四份准确EXE散列和局部签名；不能用另一作地址兜底。未识别宿主或真实基址不是0x400000时不访问固定地址。主ASI可导入标准Windows DLL，静态SDL和编译器运行库随产物链接。

| PE身份 | 本体 | 外传 |
|---|---|---|
| SizeOfImage | 0x00173000 | 0x001A5000 |
| EntryPoint RVA | 0x0010F0EF | 0x00127BCF |

Registry保存模块初始化返回值并隔离可选模块失败。成功不代表全部补丁成功，也不代表Controller延后初始化完成；查看后端日志。SHA、动作桥和SDL在Loader锁外的游戏输入线程完成。

## Hook与事件所有权

每个公共物理入口只有一个提供者。HookManager.h登记15种归属：Strategy、HUD布局、UI Draw、root picker、世界按下/全局释放、地面物品、输入帧、拾取、Controller键盘/异步/resolver/菜单/软件光标/调查。它们不是具体补丁数量。

当前Menu.c的MENU_KINDS=19，每页Tick/Show/hover三个槽共57槽，加Talk一处、技能三处和信息框三处局部调用，菜单本体共64处写入；ActionMenu另有Tick/hover两槽。来源为当前源码登记，不沿用旧十五/十六类统计。软件光标三处局部调用和世界hover包装有各自归属；菜单不接管DisplayFix Draw/root picker。

Runtime/InputFrame独占原输入刷新。QOL订阅INPUT_FRAME_END，Controller保留原键盘采样和鼠标解析后的业务位置。EventBus有GAMEPLAY_ENTER/EXIT、UI_DRAW_BEGIN/END、INPUT_FRAME_BEGIN/SAMPLED/RESOLVED/END八事件。

BEGIN/END的subject是原输入管理对象，SAMPLED是真实键盘缓冲，RESOLVED是鼠标管理对象。END只代表原input_update返回，不代表世界逻辑帧结束或Controller业务已执行；UI_DRAW_END后还可能有延迟GUI补画。

模块Claim失败时释放尚未安装的owner；已写入口先完整撤销，失败保留owner及网关。HookManager_ReleaseOwned不恢复机器码。RuntimeWin32_WriteCode返回2表示已写入但缓存/保护处理失败，不能当完全成功。只承诺初始化同步回滚，不承诺全模块热卸载。

## 公共服务

配置由Runtime维护TOML描述表、候选、快照和原子保存，业务热路径读内存。保存成功后按普通输入边界、动作结束或重启分类应用。Guard确认完整接收后才消费generation；世界改绑等按键释放和请求结束；技能绑定只影响后续新请求，下一输入帧接收。Runtime设置窗口借用原系统菜单暂停与捕获，Controller只转交原始输入。

日志共用持久句柄、有界后台队列和聚合性能摘要。模块不得逐帧读配置或重复采样设备，不建立跨模块私有耦合。需要改公共Runtime能力时先解释原因，模块修改保持在其职责内。

## 显示与平台稳定契约

Strategy状态3进入GAMEPLAY，标题/动画保持FRONTEND原版4:3和mode4；修改profile还须处理live Surface。HUD居中不搬移辅助窗口、不反算鼠标。Steam完整JMM延迟应用、多语言裸资源名兜底、class atom保护与官方EDIT链必须保留。地址及失败机制见[逆向工程知识库](逆向工程知识库.md)和[逆向工程知识库](逆向工程知识库.md)。

交付职责为docs、source、release和根.build；SDL完整源码在thirdparty。当前单源码工程直接使用source/build.bat，不另加无业务意义的中间工程目录。游戏本体与逆向参考只读；不依赖其他工程或个人编译器地址文件。代码文件英文名、中文详细注释；自有代码和文档UTF-8无BOM＋CRLF。

## 共享事件、网关与真实就绪

EventBus.h逐事件明确subject和value，并规定同步借用、不得保存供下一帧解引用：INPUT_FRAME_BEGIN/END是键盘对象（缓冲位于对象+8），SAMPLED是实际256字节缓冲，RESOLVED是WorldMouseManager；Gameplay是Strategy，value1/2为进入目标或退出实际宽高；UI_DRAW是CJMMng，value1为绘制上下文。BEGIN两值0，END的value1为原函数返回值，SAMPLED的value1为毫秒，其他输入value为0。总线拒绝非法事件与空subject，不猜测void*类型、不解引用游戏内存。独立探针验证八类不同地址和value原样转发及非法输入拒绝。

### 登记状态与延后业务状态

ControllerModule_IsReady仅在runtime_state=1返回真。Runtime公共输入帧以实际就绪结果判断是否代办idle配置；未启动/禁用/延后初始化尚未完成或失败时没有手柄动作，Runtime接收idle候选；已就绪时仍交Guard安全点，不半程改变运动。SDL在Loader锁外输入线程、动作桥之前初始化；初始化失败撤回采样并停止该模块，没有连接设备不算SDL失败。延后失败路径释放自己的SDL引用，Registry登记结果不伪装业务就绪。

test_startup链接真实Controller接入与业务、Registry、HookManager、EventBus、公共帧和TOML保存/快照；档案判断、SDL启动及物理写入使用可控替身，主桥使用宿主数组。覆盖档案选择/签名拒绝、SDL失败、五处主桥写入失败及真实Guard签名失败；验证已写槽回滚、Registry保持成功但ready为假、QOL帧订阅继续、DisplayFix/QOL登记隔离及idle候选/代数确认，另验证ready时延后、失去ready后接收。DisplayFix/QOL在此集成中的启动函数为替身，所以只能证明Registry与帧订阅隔离，不能扩大为实际显示/拾取运行效果；各自生产地址和既有回归另行复核。

## Runtime焦点提示服务

### 当前职责

安全原动态框绘制已从Controller提炼到source/src/Runtime/Focus.c，公开接口在Focus.h。Controller的Cursor.c只注册本帧焦点提供者并管理软件光标/持有图标；Menu.c和ActionMenu.c继续负责导航、焦点、确认取消和原业务。Runtime不依赖Controller头文件、g_profile、g_input或g_intent，不读取菜单对象或操作库存。

Runtime初始化共享服务早于ModuleRegistry，独立于Controller开关。没有提供者不绘制；原接口签名失配只停公共提示，不阻止其它模块初始化。服务消费既有UI_DRAW_BEGIN／END，并提供原图标之后的DrawIcon接口，不占DisplayFix Draw槽，不重画HUD或改世界输入。

### 模块接口

| 接口 | 行为 |
|---|---|
| RuntimeFocus_Initialize | 根据Runtime游戏身份校验原绘制接口并订阅共享UI绘制结束 |
| RuntimeFocus_Register | 用合法RuntimeModuleId注册提供者；同回调/数据幂等，冲突拒绝 |
| RuntimeFocus_Unregister | 注销该模块及其最近绘制标记；NONE/COUNT/非法值不操作 |
| RuntimeFocus_WasDrawn | 查询该模块是否在最近UI帧成功绘制，资源不可用可保留原反馈 |
| RuntimeFocus_Stage | 供异常记录器取得当前共享渲染阶段，绘制外返回NULL |

提供者签名为int(RuntimeFocusRequest*,void*)，每个UI绘制帧首次需要时验证页面并返回矩形/优先级/图标阶段，0表示无有效焦点。Runtime不跨帧保存CJm/Slot/角色裸指针。注册/查询/注销在游戏线程调用，模块自行管理状态和提供者userdata生命周期；提供者注销自己后本次结果也被排除。BEGIN与END分别登记成功状态，部分订阅失败后重试不重复登记。BEGIN清除上一帧成功标记与本帧快照；本帧只收集一次矩形，不在每个技能图标CALL重复扫描控件。登记变动立即使快照失效。

Runtime先在全部提供者中选最高优先级的一项，再判断当前绘制阶段，同优先级按模块编号稳定选取；无效矩形不遮挡合法低优先级焦点。当前Controller物品页50、原物品确认/动作菜单100。未来MOD界面等其它模块可按自己真实输入所有权提供焦点，不以所有已打开窗口作为共同高亮。输入导航、原业务、物理接管和页面关闭都仍由提供者决定。

矩形使用原GUI逻辑坐标，不改HitRect/布局/鼠标位置。宽高4..128，使用64位减法检查溢出；关闭/隐藏/模态遮挡/来源变化时提供者返回0，绘制结果在下一UI帧清除。

### 原资源与四版本档案

FocusData.h由source/tools/generate_focus_profiles.py从同一profiles.json生成，共享六字段：HUD全局/虚表、SpriteDraw、RectDraw、FrameGetter、ImageGetter。同一游戏折叠Steam/非Steam行之前逐字段和签名证明相同，差异即拒绝生成，不借用偏移。生成/同步检查纳入正式构建。

Runtime使用GameProfile的PE游戏身份和四函数12字节签名作为共享绘制门；Controller自己的四份准确SHA和动作签名门继续保持，服务不代替它。当前四准确EXE源地址/签名、原调用链及清栈均静态核对，全项目audit额外读取实际Runtime生成表，防止共享表串用另一作地址。

| 原接口 | 本体 | 外传 |
|---|---|---|
| HUD全局／虚表 | 55BBB0／52A7D4 | 58D164／553B34 |
| 普通精灵绘制 | 4F4BE0 | 50BAC0 |
| 矩形裁取（不是缩放） | 4F4C10 | 50BAF0 |
| 动画帧getter | 4F4D60 | 50BC40 |
| 图像getter | 4F5CF0 | 50CD10 |

每帧读取当前HUD第5动态精灵，验证动画表/下标、22字节帧、资源管理器/登记对象、源图及目标缓冲区尺寸；不缓存旧地图资源对象。同尺寸原Draw，不同尺寸以原边缘片段拼接，每片限制源范围，中心透明不画。素材暂不可用时Controller保留旧箭头临时指示，不能变成无反馈页面。

原错误“十参数就是缩放”的解释已撤销，用户实机确认过安全源图方案；这次是服务迁移和格子提示扩展，仍待新实机，不把旧反馈扩大为迁移后全面验收。

### 当前视觉分工与格内边界

用户指定收尾前临时规则：物品格/特殊槽、技能学习图标、连招编排下方普通攻击／踢击／跳跃三个基础动作图标、连招编排虚拟格和左右手技能图标使用内框；非格子、非方形、菜单按钮区和确认项沿原鼠标指针/手型图样。不能以控件矩形存在就把金币/关闭/页签等按钮当格子。原素材仅支持矩形拼接，当前没有自由圆框/任意形状，因此不统一所有菜单。外传标题原清楚高亮及既有隐藏约定保持。

物品24像素格按原页坐标每边内收1，内框22像素；真实特殊槽/技能控件由14/18/1C/20每边内收1，连招虚拟格还原原43×47可见范围再内收。各界面只提交最终可见矩形，不改命中/布局。Runtime根据原帧E/10与12/14的有符号原点差补偿调用坐标，正负偏移和换帧均重读；普通Draw和矩形裁取都遵循同一补偿，不修改帧表。

持有图标仍沿原格中心，原交换/堆叠/资格/数量/资金/属性由游戏负责。X区域循环、Y分区/套组、B取消、Back原丢弃及日志/招式LB/RB规则保持。按钮区不请求框也不隐藏原指针；当前仍使用游戏已有图样，具体素材/手型样式和页面例外在补丁收尾决定。

### 验证与接档

技能页基础动作控件81～83与普通技能84～8F均提交内框，不因属于基础动作退回指针；非格子按钮仍沿原指针。

test_menu链接/包含真实Runtime服务及生产菜单，宿主原接口替身只提供自有帧/图像，逐片检查源范围。覆盖七格子区最终像素边界、按钮/确认项指针、技能图标及持有中心、模块ID非法值、幂等/冲突、优先级、无效高优先级矩形、提供者自注销、物理接管、旧成功绘制标记清理和原A/B/交换/丢弃回归。

icon_phase=1用于技能/动作菜单方形图标：Controller在原icon_draw的精灵CALL之后调用RuntimeFocus_DrawIcon(surface,x,y)，只有与候选矩形左上匹配时才画，随后原函数继续说明文字。END不重复绘制此类请求。普通物品格icon_phase=0沿END绘制，原模态优先级保持，不改变文字或图标资源。

启动故障与异常文本测试继续保持；Crash.c通过共享Stage取Runtime绘制阶段，Runtime不反向调用Controller诊断。最新debug仍是同一优化链接件保留源码符号，实际GUI/设备/Steam环境按分项验收。

阶段身份和执行结果见更新记录，当前接续见完整接档；共享服务的新增路径按实际实机覆盖判断。
test_focus_containment通过test_menu --containment驱动生产Menu→Runtime绘制，断言最终实际边界在真实格内；原绘制替身计入有符号动画偏移，不再只把目标矩形当答案。最小test_menu --containment bag可复现旧外框/偏移/按钮策略失败，修复后两作正负偏移都通过。四准确EXE核对普通/裁取两条原点指令链，原证据保留。

## 工程及架构与模块开发规范

### 正文与更新记录的职责

技术文档不再做版本更迭。发生变化时直接修订对应机制、配置、地址、限制或验证结论，不在末尾叠加日期、版本同步与补丁说明。完整接档也维护当前可独立继续工作的状态。

版本号、发布散列、阶段测试数量、旧方案的替换过程、用户逐轮反馈和提交记录只维护在《版本与更新记录.md》。正文可以记录现行依赖版本、游戏基线版本、必要实验标识和验证边界；这些用于精确定位技术对象，不组织成发布时间线。

原始实机日志、逆向机器码证据、第三方许可保留原字节。日志文件名的阶段标识不改名。失败机制与不能重复的方案应留在技术正文，失败发生在哪一版及后续修复时间进入更新记录。

### 更新流程

1. 修改对应主题的正文，删除已失效的当前结论，把替代过程记入更新记录。
2. 遍历 docs 全部文档，检查同一配置、架构、地址、路径和验收边界是否一致。
3. 更新完整接档中的架构、关键地址入口、稳定方案、失败边界、当前阻塞与下一步。
4. 检查本地链接、文件名、UTF-8无BOM和CRLF；原始证据与许可不作格式修复。
5. 整理出可审阅差异后，完成可用实现、用户实机确认或重构前存在有效修改时，主动本地微提交，无需逐次询问；远端交用户手动操作。

### 文件与目录

文档采用简体中文文件名。源码目录同级的readme.md是唯一构建说明，保持原位置；docs中的构建与测试文档只说明验证职责和回归边界，不另造构建教程。自有工具位于source/tools及模块工具目录，说明同步[工具说明](../../source/tools/工具说明.md)。参考资料目录只读。

## Git和交付边界

按当前AGENTS.md，完成可用实现、用户实机确认、较大重构前存在有效修改时主动本地微提交，无需事前询问；不主动推送。远端由用户操作。参考资料和archive只读；原始证据及许可按来源保存。自有文档UTF-8无BOM＋CRLF。

正式技术说明留在docs/文档，原始证据按逆向分析、实机日志、核对数据集中在docs/证据；第三方许可单独在docs/第三方许可。新增证据沿对应目录输出并从正文链接，不再散置于docs根。迁移保持原字节和来源，更新工具输出示例与构建许可来源，不改只读参考资料。

根.gitattributes对docs/证据与docs/第三方许可设置-text，禁止Git自动转换原始文件换行。该规则不扩展到普通代码和技术文档；迁移同时核对原工作文件和提交blob字节。

## 新游戏与跨模块随机请求

Controller负责新游戏两层导航和Y边沿，调用QOLModule_RandomName(page)这一公开语义接口；不包含词库或写名称字符串。QOL的RandomNameUI负责登记对象/虚表/父页/HWND/线程校验、原生编码、容量与编辑字体字形筛选，最终调用原setter同步CString和EDIT。随机核心仍独立，不接触游戏内存。八事件和公共Hook编号保持，随机适配只复用QOL输入结束订阅。

原角色提交打开第二层后再次读取第一层A8；Controller通过同步提交标记延后清理该源焦点，直到原调用返回并验证同一对象/原值后才清空。不得把页面路由切换等同于原业务已经结束。

共享框可在标题借用隐藏HUD的已加载框资源，实际可见页由提供者验证；资源及源范围检查不放宽。目标宽至512、高至128，拼接最多96段，超出或素材未就绪保留指针兜底。
