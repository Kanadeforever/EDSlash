# 显示与平台兼容说明

> 维护约定：本文直接维护当前有效的技术正文，不追加版本更迭或日期同步章节。阶段变化、发布身份及测试执行记录见[版本与更新记录](版本与更新记录.md)。

## 配置入口

EDSlash.toml使用display.enabled/base_height/aspect_ratio、font.fix_dpi、gui.center_hud/auxiliary_above_hud。默认高度480、比例auto；显示安装、逻辑高度、画面比例与字体开关需重启；HUD居中与辅助界面层级已可通过设置保存热应用。配置完整范围见《统一配置与模组设置说明.md》。

## BaseHeight

`BaseHeight` 是游戏内部逻辑世界高度/FOV 尺度，不是最终输出分辨率。通常推荐 480 或 600，再由 cnc-ddraw 等兼容层放大到桌面分辨率。过高会显著增加老游戏绘制/对象负担。

## AspectRatio

`AspectRatio` 支持：

- `Auto`
- 任意合法正整数 `W:H`

Auto 与手工比例只在“比例来源”上不同，最终宽度计算完全相同：

```text
ideal = BaseHeight × AspectWidth / AspectHeight
TargetWidth = 最接近 ideal 的 8 像素倍数
```

8 像素对齐是 AspectRatio 统一规则，不是独立模块。

本体 `BaseHeight=480 + 16:9` 计算得到856；该比例的右侧竖条消除已有用户确认。

## FRONTEND / GAMEPLAY

标题、主菜单、固定分辨率动画保持游戏原版 4:3 生命周期。真正进入 Strategy 状态 3 后才启用宽屏 GAMEPLAY profile；离开状态 3 后强制恢复原版 mode 4。

## Steam delayed JMM

本体后端检测 Steam/ComeOn.dll 后，等待 HUD、顶层 UI、资源根成熟补一次完整原版 JMM，不在初始化阶段提前重放。外传后端当前明确设置 g_steam_environment=FALSE，该延迟同步路径休眠；Steam 专属运行修改为 ResJM 多语言兜底与 class-atom guard。旧外传 delayed JMM 日志属于历史版本。

## HUD 与辅助 GUI

主 HUD 在 GAMEPLAY 中按 `MainHUDCenterDelta=(TargetWidth-NativeBaseWidth)/2` 居中。

layer1d 不移动物品/装备/技能窗口坐标，而是：

1. 原顶层 Draw 遇到相关菜单时延后；
2. 主 HUD 画完后按原 Draw 函数补画菜单；
3. 若原版输入 picker 选到 HUD、鼠标又位于已延后菜单 root 内，则只替换这一次 picker 返回值；
4. 后续 `manager+0x40`、child hit-test、事件和按钮业务全部继续走原版；
5. 独立左侧辅助面板在合法菜单上下文中确认后做短生命周期跟踪，即使物品主窗口先关闭，只要面板自身仍 active/存在/与 HUD 相交就继续保持在 HUD 上方。

### 6.1 属性/物品顶部按钮的按压动画

主 HUD 居中以后，`0x0B/0x0E` 两个顶部圆形按钮此前已经能够正确执行打开/关闭功能，但用户指出鼠标点击时缺少原版按下动画。根因不是动画资源缺失，而是 press 阶段原版顶层 root picker 有时没有把这一次输入交给已经居中的 HUD。

`v0.1-dev1` 继续复用 layer1d 已验证过的 picker callsite，但增加一个更高优先级、范围非常窄的 HUD 校正：

1. 必须已经进入 GAMEPLAY；
2. `CenterMainHUD=1`；
3. 当前不在 Strategy 分辨率切换；
4. 鼠标必须落在 HUD **当前实时布局**后的 `0x0B` 或 `0x0E` child 矩形；
5. 满足后只把这一次 picker 返回值设为 HUD；后续 `manager+0x40`、`0x4B44F0`、HUD `vtable+0x20` 和释放事件全部继续由原版执行。

因此本修复没有手工设置 pressed 状态，也没有恢复 会破坏隐式ESI语义并影响地图左键/Alt+F4的 `0x4B44F0` C wrapper。`AuxiliaryUIAboveHUD=0` 时这条按钮动画校正仍然存在，因为它属于 HUD 居中兼容，而不是辅助 GUI 图层功能。

禁止使用坐标搬运/鼠标反算路线，失败原因见《逆向工程知识库.md》。

## 字体 DPI

字体修复只局部固定游戏字体创建链使用 96 DPI，不修改整个进程 DPI。`Font.FixDPI` 与 `Display.Enable` 独立。

## 验证边界

稳定显示机制有既有实机证据；极端比例和不同平台分别验证。Registry初始化成功不代表所有patch成功，应核对后端日志。阶段产物与反馈见《版本与更新记录.md》。## Steam与资源兼容

### 1. 本体

Steam EXE 主体与非 Steam 版本高度接近，Steam 版额外通过启动桩加载 `ComeOn.dll`。DisplayFix 的 Steam 专项主要是 delayed full JMM apply；非 Steam 路径不执行该补偿。

Steam 性能/帧速历史问题不是非Steam手柄验收覆盖的变量，后续单独调查。

### 2. 外传多语言

外传 Steam 目录依赖语言化资源：

```text
ResJM.Lib.chs
ResJM.Lib.cht
ResJM.Lib.eng
ResJM.Lib.jpn
```

已确认正式方案：只对 basename 精确为 `ResJM.Lib` 的裸请求追加当前语言后缀；不覆盖整个 `CreateFileA` IAT。

关键地址：

- `CreateFileA` IAT：`0x005511E4`
- 主 EXE 低层 CreateFileA CALL：`0x0052824E`

### 3. 外传 Steam OpenGL 根因

最终实机闭环证明：ComeOn.dll 的全局 `CreateWindowExA` post-create callback 对 `lpClassName` 只检查 NULL，却没有识别合法 `MAKEINTATOM(atom)`；之后把低地址 atom 当 C 字符串解引用，导致 cnc-ddraw OpenGL 路径崩溃。

正式修复只为：

- `lpClassName == NULL`
- `0 < lpClassName < 0x10000` 的合法 class atom

跳过字符串类名解析；普通字符串类名仍走官方逻辑。

必须继续保留：

- SteamAPI
- 多语言
- 全局 CreateWindowExA Hook
- 官方 EDIT HWND 记录
- 官方 `SetWindowLongA` 自定义 WndProc

### 4. 禁止恢复的 Steam 影片路线

DirectShow/ActiveMovie/MovieManager 的历史逆向地址仍是知识，但此前实验没有证明 ComeOn.exe 进程内 ComeOn.dll 就是 Steam launcher 开场动画实际实例。统一项目不继续开发 launcher 影片补丁。

### 支持与测试矩阵

DisplayFix平台专项与Controller四份Steam／非Steam准确基线分别判断。扩大声明须分别测试本体Steam/非Steam、外传Steam/非Steam、外传Steam＋cnc-ddraw OpenGL、资源语言切换；旧显示验收不扩大为三模块全支持。

Controller准确Steam本体SHA-256为0887ceae7589999a389ec271d690e1c55204d59575f8f2adb5ef46a1e605b3f5，Steam外传为97ae4c2350618f38a74c3d02bf315c749fc448f705e860129372ebd592ed66e5。地址表中的game_id限定同一游戏再按完整散列选择，四样本签名/CALL/虚表均复核。原Runtime身份和显示专项保持，新Controller支持以四样本静态通过、两作宿主回放为证据，准确Steam外传默认360度、LT面键切组和双扳机动作菜单选择/设置已获用户确认；本体Steam、新动态框/丢弃/肩键收敛及全部场景未全面验收。

全项目核查从生产显示数组/导入独立确认两作依赖；外传未使用显示对象声明已核对并修正为578928，本体548398；不将声明修正当作现有运行故障修复，详见《全项目代码与四版本一致性核查.md》。当前参考资料没有官方ComeOn.dll样本，当前四EXE检查不包含该DLL专项重新验证，旧class-atom/语言实机结论不扩大。
