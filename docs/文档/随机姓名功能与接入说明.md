# 随机姓名功能与接入说明

本功能属于 QOL，用于角色创建的名称填写窗口。当前已经实现独立的姓名生成核心与内置词库，尚未接入游戏窗口、键盘或手柄；现有 CMake 会自动收集新增 C 文件，未来构建可编入核心与词库，但没有业务调用入口，当前发行 ASI 未更新。接入工作等待手柄线程完成现有代码编辑后再开始。

## 词库与生成规则

词库保存在 `source/src/Modules/QOL/RandomNameData.h`，随引用它的生产代码编译，不需要运行时外部文件。包含 262 个单姓、30 个复姓、356 个中性名字、159 个男性名字和 175 个女性名字，合计 690 个名字。原始姓与名组合为 201480 种，实际有效数量受重复首字、性别、长度、编码、字库和接入方过滤影响。

姓氏以真实姓氏为基础；名字围绕江湖、山水、玄意和志怪幽境等主题整理。名字本身作为完整词条，运行时只组合姓氏与名字，不任意拼接名字内部的字。数据内部去重，中性、男性和女性名字池互不重叠。

每次抽样约 12% 选择复姓，其余选择单姓。已知性别时约 70% 选择对应性别池，其余选择中性池；未知性别只选中性池。这些是候选抽样比例，经过长度与过滤后实际比例会变化。单字和双字名字都在各自池中等概率选择，没有额外单字名权重。

生成器拒绝姓与名首字重复的组合，避开当前名称以及最近八次成功结果。生成采用非零状态 xorshift32 与拒绝采样，相同种子和相同调用输入可复现结果；种子由接入方提供，不用于安全或加密用途。最多尝试 256 个候选，找不到可接受结果时返回失败，输出与历史保持原值，随机状态会推进。

## 核心接口与所有权

接口位于 `RandomName.h`，实现位于 `RandomName.c`。全部姓名输出为 UTF-8，输出容量按字节计算，最大姓名长度参数按汉字数计算，容量包含字符串终止字节。当前数据全是基本汉字，每字三个 UTF-8 字节；内部容量为 32 字节。

- `RandomName_Begin`：进入一个新的有效名称窗口后初始化会话、随机种子和历史。
- `RandomName_Generate`：提供所选角色性别、最大汉字数、当前 UTF-8 名称、候选检查回调和输出缓冲区，成功返回非零。
- `RandomName_End`：退出窗口、取消或成功创建角色时清空会话，使后续生成请求无效。

候选检查回调是必填参数。接入方必须使用游戏实际编码检查可表示性、输入框实际字节容量及字体支持；检查失败时返回零。生成器不进行游戏内存读写、不保存窗口指针、不修改文本、不自动确认创建。会话必须由游戏线程独占，当前接口不是线程安全队列。

## 游戏与手柄接入约定

后续首先静态确认角色创建窗口身份、名称控件、所选角色与性别的真实对应关系、文本设置方法、编码、字节上限、字库，以及窗口关闭和创建完成的生命周期。未经确认不得猜测地址、控件偏移或角色编号。未知类别使用中性池。

键盘默认 R，仅在角色创建名称窗口有效时作为随机快捷键，消费对应按键与字符输入，避免额外追加 r。一次按下只随机一次，长按不连发；进入窗口时若 R 已按住，先释放再重新按下。其余页面保留原游戏 R 行为。生成成功后通过确认过的原生文本设置方法替换整个输入框，仍允许用户继续手动编辑。

手柄提供同一语义的随机请求，不模拟 R。具体按钮由手柄线程接入时确定。若请求来自独立线程，后续适配层需要线程安全的请求投递与会话身份标识，游戏线程执行前重新核对窗口资格；取消、退出、创建成功或切换窗口后丢弃旧请求。核心当前不实现请求投递或页面资格检测。

随机不自动创建角色。当前创建流程结束即失效，下次进入新的创建流程重新启用。性别变化时调用方每次传入新的类别，生成器不缓存角色身份。

## 已验证与待验证

运行 `python source/tools/qol/test_random_name.py` 使用项目现有 32 位 MinGW 探测器，仅编译并运行生产随机核心；临时程序在 `.build/qol/random_name_test.exe`，不构建 ASI，不更新 release，不读取游戏进程。

离线检查通过：词条去重、池隔离、标准 GBK 无损编码，三类各 5000 次生产生成回放，当前名称与近期结果去重，同种子复现，候选过滤，两汉字长度与七字节 UTF-8 输出缓冲区，非法参数、未启用会话、退出后禁用，以及全部拒绝时输出不变。C 编译开启 `-Wall -Wextra -Werror`。

GBK 可编码不代表游戏字体有字形；长度参数目前由测试提供，不代表已确认原游戏上限。尚未完成四版本窗口地址、文本 ABI、真实字库、R 字符消费、页面生命周期、手柄线程投递、生产 ASI 编译与实机创建存档验收。没有调用 attach、注入或进程写入。
