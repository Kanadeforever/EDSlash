# 技能阶段与闪避保留说明

## 目标与操作

RT快捷与普通Y按技能选择码、实际成功动作和当前序列前缀判断同一次会话，物理按钮不是阶段身份。同一技能可以RT起手、Y确认，也可以Y起手、RT确认。技能名称不参与运行判断，老英雄与普通剑客的同名技能各自读取实际记录。

阶段结果分为未匹配、可执行、等待窗口、窗口过期和方向未满足。等待或方向未满足时保留已有前置，不按空历史回首段。仍有活动动作时，同一技能的自动后段也不重新起手。窗口已过期且角色空闲时，新的输入可以按原版资格重新起手。

输入缓冲沿用原有五次更新重试，不扩大成自动等待蓄满。重试会重新解析合法续段：起手计时续段允许通过原生入口处理当前实例；新起手和普通后段仍遵守原版资格。长按普通攻击可以循环，长按本身不会生成蓄力阶段的第二次确认。

只有实际成功建立动作的通知才推进历史。不同技能的空历史起手成功时替换旧历史，提交失败不提前删除旧会话；实际Method也随通知记录，不能只根据共享选择码猜阶段。命中推进与自动派生继续由原生事件控制，资源、方向、目标、原生取消门均不由插件强行通过。

## Offset保护技能前置

Offset仍为原版／闪避保留两档，默认闪避保留。成功闪避可以保护原生预设进度，也可以保护实际技能组内已经建立、仍可手动续接的前置阶段，不要求当前Y装备的是预设连招。

原闪避入口可能同步终止旧Runtime，因此Guard在提出闪避前保存候选历史；只有实际进入状态17并收到成功通知才采用快照。失败请求撤销候选，不获得暂停。快照保存逻辑阶段和时间，不能复活旧Runtime指针或提前视为蓄满。

成功闪避期间平移动作起始时刻及已存在的结束时刻，已有蓄力进度保持不变。闪避中不执行阶段确认。正常收尾后继续原阶段，起手计时恢复增长；此时的宽限只延后失效，不冻结下界、不提高已有蓄力，也不自动释放。

“闪避续招宽限”对应controller.combat.offset_grace_ms，0～500ms，默认250ms，步长10。原技能窗口使用游戏逻辑计时，宽限使用真实毫秒；两者不直接换算。宽限有效时，真实前缀匹配的手动阶段可以暂时越过原上界；下界和方向资格继续检查。宽限到期恢复原时间判断，原剩余窗口更长时不强制缩短。0ms只暂停实际闪避耗时。

新动作成功、受击导致状态或活动实例中断、进入暂停业务、失焦、断线或场景／角色变化结束旧保护；失败的新技能尝试不冒充成功切换。预设还受当前HUD套组选择约束。原生HUD归零查询只在预设保护有效时拦截，普通技能保护不伪造或干预预设游标。

## 状态抽象

| 阶段规则 | 推进来源 | 保留的边界 |
|---|---|---|
| 单次主动发动 | 一次输入及原版发动资格 | 动作结束与效果到期分开 |
| 收招窗口手动续接 | 前段结束后窗口内的新意图 | 前缀、结束时刻、方向 |
| 起手窗口再次确认 | 同会话在严格起手时间窗内的新意图 | 实际Method、起手时刻、未确认阶段 |
| 命中驱动推进 | 原生接触／命中和执行子型 | 不用输入代替命中 |
| 运行事件自动推进 | 动画、更新计数、终止回调及派生命令 | 不因多段而重复起手 |
| 非主动施放声明 | 学习／属性／状态消费 | 不虚构主动等待确认阶段 |

这些是可组合的阶段规则，不是给整招分配一个互斥类别。瞄准、资源资格、状态效果寿命和取消条件各自独立。当前运行实现读取原技能组和Method条件，不新增按技能名称或职业维护的手工名单。

力士锻造360、健身361、战气362的组类型为4且动作无子命令，是非主动声明候选，当前技能菜单也排除组类型≥2；具体属性加成消费仍需独立核对。女侠御风等有实际动作和子命令，主动增益不能仅因效果持续就归为被动。

原事件类型0按动画进度，1按实体接触登记，2与动画／阶段结束相关，3为通用终止，4为外部停止请求，5按局部更新计数阈值一次执行，6按更新计数取模周期执行。类型3可由自然结束或合法主动终止进入，不能一概称自然收招。两作实际Skill.ini和SkillChild.ini均没有类型4，不能据长动画或周期效果就声称存在“松键释放／长按引导”。

## 接线与原生证据

SkillResolver提供Skill_Query与Skill_Continuation，保留Skill_Resolve布尔兼容入口；ActionHistory追加last_method与grace，仅为插件内存字段，不修改游戏数据结构。Combat管理成功通知、有限缓冲、闪避快照和暂停时钟；Guard只接入提出闪避前／返回后的快照事务及已有受击中断通知。Target和药品快捷分工不变。

原条件函数本体0x475160按Method+29/+2D决定时间窗，模型节点资格由0x4244C0检查Method+26，不应把它的0..8误称蓄力枚举。原生插入0x4D2530与外传0x4E7460前0x38字节一致，编号槽已占用时不覆盖；Method按源行顺序载入，所以重复编号首条生效。玩家可达重复614按首条处理，全部原始候选仍由核对工具保留。

两份资源mb.fol输入SHA256：本体c315a8ffe46ae9de4a42bc848f8f894d43c66ed57d38685d97b44b4dacce4fd1；外传e28d86cdd590a4efbc423689dd6021ebe0ff5ee78a61ab081682f8e1d48d6c45。共有79个选择码的GOP相同，Skill.ini仍有数值、命令与命名差异，不按两作数据完全相同处理。

## 验证与接档

test_skill_session实际调用生产Control／Combat／SkillResolver／Guard接口，覆盖两作偏移、RT与Y四种交叉确认、早按不回首段、有限缓冲重查、闪避冻结、结束回调快照、宽限下界继续增长、超时、失败闪避、长按防自动确认、普通续击、自动后段和成功／失败切换。test_game与test_target继续核对药品、投掷、预设、闪避裸桥、原生历史交接和命中锁。

技能阶段日志记录新输入被暂缓和成功闪避保存的实际动作及已有逻辑进度。暂缓原因2为等待窗口，4为方向未满足；日志的逻辑进度不能当毫秒。

资源盘点工具为source/tools/controller/audit_skill_states.py，只读两份FOL，自包含地产生全部职业、等级、事件和显式引用图；说明与工具同目录。无需依赖临时.workspace调查目录。未覆盖其他操作码隐含生成、外部脚本临时技能或运行时改写；宿主回归和资源枚举都不等于两作全部技能实机验收。
