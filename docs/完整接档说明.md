## 2. 本轮新增证据与根因

用户 layer1c 日志已经证明独立左侧装备面板确实被动态系统捕获：当次运行对象 `0x04255670`、vtable `0x0052A60C`、矩形 `0,217,325,442`。这些地址属于该次运行实例，只用于证据，**绝不硬编码**。

layer1c 的候选函数有一个总门槛：`0x0B/0x0D/0x0E` 至少一个主菜单必须 active。物品 root 关闭后，独立装备面板虽然自身仍 active、仍在 HUD 前真实 Draw 链，也会因为总门槛失败而立即退出 HUD 后延迟 Draw。这就是最后问题的直接代码原因。

## 2. 不可违反的项目红线

1. 稳定基线运行逻辑不得因 layer1b 回归：分辨率、Strategy FRONTEND/GAMEPLAY 生命周期、主 HUD 居中、字体 DPI、既有输入保护都必须保留。
2. test1~test7 的“移动菜单以后再补输入”路线已经失败，任何 `GetCursorPos` 反算、`self+0xA8` 修补、菜单 X/Y 平移、乾坤袋手工跟随等运行时代码都禁止回流。
3. `0x004B44F0` 存在调用者 ESI 隐式语义，历史普通 C wrapper 已实机造成普通地图左键和 Alt+F4 回归；**绝不能再次包装它**。
4. 外传 Steam 两条封版兼容路径不能改：`ResJM.Lib` 多语言低层 CreateFileA 兜底；`ComeOn.dll CreateWindowExA` class-atom guard + 官方 EDIT WndProc/OpenGL 原路径。
5. 所有新增 UI 修复必须优先保持原版业务逻辑；视觉正确不能以按钮、快捷键、世界输入或 HUD 功能回归为代价。

## 3. 从 test1~test7 到 layer1a 的结论

### 3.1 test1~test7 为什么停止

旧路线核心是把装备/技能/物品重新搬到居中 4:3 区域，再处理由位移产生的输入问题。

- test1：相对位移存在累计漂移。
- test2：改绝对锚点并补键盘路径，仍然人为拆开原版视觉/输入关系。
- test3/test4：尝试在 child hit-test 内反算鼠标 X；桥接执行并不等于按钮命中正确。
- test5：继续围绕独立对象/乾坤袋补布局，结构假设仍不稳。
- test6：Hook `vtable+0x30` 并修 `self+0xA8`；实机出现插件把原版正确 child 改错的证据。
- test7：增加原版命中优先和 delayed JMM 时序门控，但根前提仍是“先搬菜单再修副作用”，因此停止。

这些版本保留的价值只有逆向证据、对象地址、调用链、失败原因与实机日志。

### 3.2 layer1a 为什么方向正确但不完整

layer1a 从 v0.3.2/v0.2.1 稳定版重新开线，不移动任何菜单。它 Hook UI manager Draw 包装入口和目标类 `vtable+0x08 Draw`：如果 0x0B/0x0D/0x0E 原本在主 HUD 之前画，就暂时跳过，待主 HUD 普通 Draw 完成后再各调用一次原 Draw。

优点已经被本体实机证明：菜单视觉完整、位置完全保留原版、整体效果远好于搬菜单路线。

缺陷同样被实机证明：

- 视觉上菜单在 HUD 上方，但 UI manager 输入仍走原本反向链，HUD 在重叠区域仍可能先吃掉点击；
- 独立于三个已知根对象的左侧菜单/辅助面板不会自动被延后 Draw，因此仍可能在 HUD 下。

所以 layer1b 不再修按钮，而是修**顶层 Z 顺序本身**。

## 4. layer1b 核心架构：同步游戏自己的双向顶层 Z 链

### 4.1 已确认字段

UI manager / 顶层对象结构当前采用：

- `manager+0x1C`：正向顶层链头；普通 Draw 从这里沿 next 向后遍历。
- `manager+0x18`：反向顶层链尾；顶层鼠标分派按 previous 方向查找。
- `object+0x08`：next。
- `object+0x0C`：previous。
- `manager+0x20`：manager Draw 当前对象上下文。
- `object+0x14/+0x18/+0x1C/+0x20`：矩形 X/Y/宽/高。
- `object+0x64/+0x68`：活动状态相关字段。
- `object+0xA4`：parent 关系，供“这个独立顶层节点是否实际属于当前主菜单树”判断。

layer1a 只利用了正向 Draw 链；layer1b 把正向/反向两侧作为同一个 Z-order 数据结构处理。

### 4.2 写链前的硬验证

每一帧真正写任何指针前，`layer_validate_bidirectional_top_level_chain()` 必须确认：

1. `manager+0x1C` 与 `manager+0x18` 要么同时 NULL，要么同时非 NULL；
2. 头节点 `previous == NULL`；
3. 每个节点的 `next->previous == 当前节点`；
4. 正向走到最后的节点必须等于 `manager+0x18`；
5. 尾节点 `next == NULL`；
6. 最多 128 项，超过视为循环/未知结构。

任一条件失败：**本帧完全不写链**，只写一次警告，继续使用 layer1a Draw-only 兜底。

### 4.3 何时允许调整

必须同时满足：

- 已进入 GAMEPLAY；
- `CenterMainHUD=1`；
- `AuxiliaryUIAboveHUD=1`；
- Strategy 不处在显示切换过渡；
- 主 HUD 在当前顶层链里；
- 0x0B 装备 / 0x0D 技能 / 0x0E 物品至少一个真实对象 active。

普通跑图、战斗但未开菜单、FRONTEND、主 HUD 未居中时均不调整。

### 4.4 哪些节点会被提升

只扫描**原本位于 HUD 之前**的活动顶层节点。候选满足以下任一证据：

1. 节点就是 0x0B/0x0D/0x0E 当前主菜单对象；
2. 沿 `+0xA4 parent` 最多 16 层能追到上述主菜单；
3. 节点有有效屏幕矩形，且确实与主 HUD 矩形相交。

第三条用于捕获用户实机看到的“独立左侧菜单/辅助面板”这类没有被三个已知根 Draw 覆盖的对象。为避免误把世界根/全屏遮罩抬高，宽和高都接近目标画面 7/8 以上的对象会排除。

### 4.5 如何移动

候选先按原正向链顺序记录，再通过 `layer_move_top_level_node_after()` 逐个插入 HUD 后方：

```text
原始：A -> 候选1 -> B -> 候选2 -> HUD -> C
结果：A -> B -> HUD -> 候选1 -> 候选2 -> C
```

因此：

- 正向 Draw：HUD 先画，候选菜单后画；
- 反向输入：C -> 候选2 -> 候选1 -> HUD ...，菜单先获得点击；
- 候选彼此原顺序保持；
- 原本已经在 HUD 后面的 C 等更高层对象继续保持更高层级。

提升后会再次完整验证双向链。若复核失败只记录警告并停止后续写入。

### 4.6 layer1a Draw wrapper 为什么还保留

保留的三个菜单 Draw wrapper、主 HUD wrapper、manager scope 有两个职责：

- 提供已确认的 Draw/vtable 结构验证与逐菜单 fail-open；
- 如果双向链运行时自检失败，退回 layer1a Draw-only，至少保持已经实机证明方向正确的视觉结果，而不是让菜单重新被 HUD 完全遮住。

它们不再是 layer1b 的首选 Z-order 修复。

## 6. 独立辅助对象证据

历史逆向还确认过物品 `0x17` 相关辅助对象：

- 本体：构造写槽约 `0x004BCE29`，vtable `0x0052A60C`，global `0x0055B784`。
- 外传：构造写槽约 `0x004D0D39`，vtable `0x0055395C`，global `0x0058CCB8`。

旧实验曾把它误定性为“装备面板”并手工移动，后来由物品 `0x17` 事件关系纠正为乾坤袋/物品辅助对象证据。layer1b **不按这个地址直接移动或调用业务**。如果它在实机确实是独立顶层且与 HUD 相交，它只能通过通用 Z-order 候选规则被提升。

## 7. 主 HUD 与快捷栏边界

本体主 HUD vtable 已知 `0x0052A7D4`；普通布局 `+0x58 -> 0x004B2B90`。

主 HUD 除普通 `+0x9C` child 外，还有一组约 `self+0x154` 开始、12 项、步长约 `0xE4` 的快捷栏内部记录：

- `0x004C3040` 扫描 12 项矩形做命中；
- `0x004C31E0` 使用同组记录绘制；
- 初始化路径会按 HUD 控件矩形构造两组六槽。

UI manager 在顶层普通 Draw 前还有 HUD 特殊 pass（本体已逆到 `0x004C3090`）。layer1b 不 Hook、不跳过、不重放这个 pass，只确认其结构仍合理。

因此 layer1b 实机必须继续检查 12 槽鼠标/快捷键/悬停，不能只看三个大菜单。

## 8. 输入边界

layer1b 改的是“谁在顶层链里排前排后”，不是输入算法：

- 不改 `GetCursorPos`；
- 不改通用 child hit-test；
- 不改 `self+0xA8`；
- 不 Hook 菜单 `+0x30`；
- 不改菜单 `+0x24` 业务；
- 不改键盘快捷键；
- 不包装 `0x004B44F0`；
- 稳定基线已有的 0x0B/0x0E 世界点击防穿透与 release fallback 保留。

这正是 layer1b 与 test1~test7 的根本区别。

## 10. 外传 Steam 永久红线

### 10.1 ResJM.Lib

只在游戏低层 CreateFileA CALL 做 basename 精确为 `ResJM.Lib` 的多语言后缀兜底；不覆盖游戏 IAT。

### 10.2 ComeOn.dll class atom

ComeOn.dll 原 callback 会把 CreateWindowExA `lpClassName` 直接当字符串解引用，但 Win32 允许 MAKEINTATOM。稳定修复只在 NULL/`<0x10000` 时跳过不安全字符串比较；普通字符串类继续回到官方 EDIT 判断、SetWindowLongA/WndProc 与 OpenGL 路径。

历史“neutralize 全 callback”“禁 EDIT WndProc”“DirectShow/影片 watchdog/teardown”等失败实验永久禁止回流。

## 11. 配置

新增/沿用关键项：

```ini
[GUI]
CenterMainHUD=1
AuxiliaryUIAboveHUD=1
```

`AuxiliaryUIAboveHUD=1`：允许 layer1b 在满足严格门槛时同步顶层 Z 顺序；链自检失败时 Draw-only fail-open。  
`AuxiliaryUIAboveHUD=0`：完全不安装本轮 Z 顺序/图层 Hook，退回稳定基线原顶层顺序。  
`CenterMainHUD=0`：没有居中 HUD 遮挡需求，layer1b 不安装。

字体仍可独立：

```ini
[Display]
Enable=0
[Font]
FixDPI=1
```

## 12. 构建与工具

每个 DisplayFix 工程包含：

- `build.bat`：Windows 一键构建；UTF-8 + CRLF；
- `src/DisplayFix.c`：主源码；
- `template/DisplayFix.ini`；
- `tools/verify_build.py`：成品/源码/编码/失败路线防回归；
- `tools/verify_compatibility.py`：只读 EXE/DLL 结构验证；
- `tools/verify_compatibility.bat`；

独立 `FontFix_*` 继续随包，是固定 96 DPI 的 EXE 离线局部补丁器，不与 layer1b Z-order 功能耦合。

当前环境使用 clang + lld-link 额外交叉构建；最终 ASI 必须通过各自 `verify_build.py`。

## 13. 本轮静态/构建结论

封包前最终状态应满足：

- 两套 ASI 都是 Win32 PE32/i386 DLL；
- 非零入口；
- 导出 `InitializeASI`；
- Import Directory=0；
- INI、源码、脚本、Markdown 无 BOM；BAT UTF-8 无 BOM + CRLF；
- 中文运行日志检查通过；
- `Font.FixDPI` 先于 `Display.Enable` gate；
- layer1b 双向链字段、验证、节点移动、提升逻辑存在；
- test1~test7 菜单位移、鼠标反算、`self+0xA8` 修复、乾坤袋手工同步符号为 0；
- 外传 Steam 封版路径和历史失败实验防回归检查通过。

**尚未完成：**当前 `/mnt/data` 没有用户四套 ComeOn.exe 和 Steam ComeOn.dll，所以本轮新版 `verify_compatibility.py` 无法重新对真实游戏二进制跑绿。历史样本通过记录不能冒充本轮通过。

## 14. layer1b 实机验收清单

4. 装备、技能、物品三个主菜单其它内部按钮全部正常。
5. 乾坤袋/物品辅助界面逻辑正常。
6. 主 HUD 12 槽、HP/MP、悬停/状态信息、顶部按钮正常。

### 14.2 需要保留的日志

若仍有任何问题，提交 `DisplayFix.log` 中：

- `辅助GUI layer1b 已安装`；
- `辅助GUI Z顺序提升 对象=... vtable=... 矩形=... 类型=...`；

## 16. 下一步决策规则

- 如果 layer1b 让物品重叠按钮、技能连招关闭和左侧面板全部正常，同时 HUD/世界/快捷键零回归：该方向继续收敛，下一步只根据日志把“矩形相交通用候选”尽量替换成已闭合类/parent 证据，降低启发式范围。
