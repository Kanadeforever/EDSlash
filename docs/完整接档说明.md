# BladeSwordQOL v0.1-dev1 完整接档说明

## 1. 当前定位

`BladeSwordQOL v0.1-dev1` 是《刀剑封魔录》系列大修/QoL 项目的第一版统一架构基线。它把此前分开的本体 DisplayFix 与《刀剑封魔录外传：上古传说》DisplayFix 合并为 **一个 Win32/x86 ASI**：

```text
BladeSwordQOL.asi
BladeSwordQOL.ini
```

同一个 ASI 会先识别当前主程序属于本体还是外传，再只初始化匹配的 Profile 后端。当前正式功能模块只有 `DisplayFix`；下一阶段计划直接在同一 Runtime 上加入 `Controller` 手柄支持模块，不再创建独立手柄 ASI。

本版本的核心目标是“架构迁移与共享 Hook 基础设施”，不是重新设计已经实机闭合的 DisplayFix。原有本体/外传后端仍作为两个独立 C 翻译单元存在，以尽量保持运行逻辑等价；统一 Runtime 只负责唯一入口、游戏识别、模块注册、共享 Hook 所有权和事件总线。

## 2. 当前实机结论

### 2.1 本体 DisplayFix

已由用户实机确认：

- `layer1c` 解决了物品/技能重叠区域“看得见但点不到”的问题；
- `layer1c` 解决了技能连招编辑子菜单关闭按钮无法点击的问题；
- `layer1c` 能动态识别并延后绘制左侧独立装备/辅助面板；
- `layer1d` 进一步解决“装备面板仍打开时关闭物品主窗口，独立面板又被 HUD 压回下面”的生命周期问题；
- `v0.3.4-stripe1` 在 `BaseHeight=480 + 16:9` 下把旧 TargetWidth `854` 调整为 `856` 后，用户确认历史最右侧竖条消失。

因此统一版继承的当前本体显示基线是：**layer1d GUI/Input + AspectRatio 8 像素 TargetWidth 对齐**。

本轮统一工程另外补上了一个此前长期遗漏的小视觉反馈：主 HUD 居中后，用户实机确认属性/物品两个顶部圆形按钮功能正常，但缺少原版鼠标按下动画。`v0.1-dev1` 不手工伪造 pressed 状态，而是在已经存在的顶层 root picker Hook 中，仅当实时 child 矩形明确命中 `0x0B/0x0E` 时，把这一次 picker 返回值校正为主 HUD，让后续原版 `0x4B44D0 -> 0x4B44F0 -> HUD vtable+0x20` 自己完成按压动画。该修复尚待本轮统一 ASI 实机验收。

### 2.2 外传 DisplayFix

外传后端继承此前已确认的稳定资产：

- 动态宽屏、FRONTEND/GAMEPLAY 生命周期、HUD 居中、DPI 字体修复；
- Steam `ResJM.Lib` 多语言兜底；
- Steam `ComeOn.dll CreateWindowExA` class-atom guard；
- 官方 EDIT 子类化路径继续保留；
- layer1d 与 AspectRatio 8 像素对齐代码已与本体同步。

但本轮用户最近的 layer1c/layer1d/stripe1 实机主要测试的是本体，**不能把本体结果自动等价成外传实机通过**。统一 ASI 的外传 Profile 仍需要一次完整回归。

## 3. AspectRatio 8 像素规则

这条规则属于 `[Display] AspectRatio` 的统一宽度求值，不是 Auto 专项，也不是独立 StripeFix 模块。

流程固定为：

```text
取得比例
  ├─ AspectRatio=Auto：从桌面/输出取得比例
  └─ AspectRatio=W:H：使用用户手工比例
        ↓
理想宽度 = BaseHeight × W / H
        ↓
选择距离理想宽度最近的 8 像素倍数
        ↓
TargetWidth
```

`BaseHeight=480` 时已知样本：

| 比例 | 旧宽度 | 8 对齐宽度 | 旧版竖条状态 | 新版实机状态 |
|---|---:|---:|---|---|
| 16:9 | 854 | 856 | 有 | 已确认消失 |
| 32:9 | 1708 | 1704 | 有 | 尚未复测 |
| 8:9 | 428 | 424 | 有 | 尚未复测 |
| 40:9 | 2134 | 2136 | 有 | 尚未复测 |
| 24:9 | 1280 | 1280 | 无 | 天然对照组 |

当前证据高度支持“最终 Surface/横向路径需要 8 像素对齐”，但严格说目前只对 16:9 新算法完成了实机闭合；其它奇葩比例建议之后抽测一组即可。

## 4. 新统一架构

```text
docs/
source/
└─ BladeSwordQOL/
   ├─ build.bat
   ├─ src/
   │  ├─ Main.c
   │  ├─ Runtime/
   │  │  ├─ Runtime.c / Runtime.h
   │  │  ├─ GameProfile.c / GameProfile.h
   │  │  ├─ HookManager.c / HookManager.h
   │  │  ├─ EventBus.c / EventBus.h
   │  │  └─ ModuleRegistry.c / ModuleRegistry.h
   │  └─ Modules/
   │     └─ DisplayFix/
   │        ├─ DisplayFixModule.c / .h
   │        ├─ Backend_DaoJian.c
   │        └─ Backend_WaiZhuan.c
   ├─ template/
   └─ tools/
release/
├─ BladeSwordQOL.asi
└─ BladeSwordQOL.ini
```

### 4.1 唯一入口

整个项目只有 `source/BladeSwordQOL/src/Main.c` 可以定义：

- `DllMain`
- `InitializeASI`

两个 Profile 后端都不再拥有 DLL/ASI 入口。

### 4.2 GameProfile

Runtime 在访问任意 Profile 专用 IAT 地址之前，先直接读取主 EXE PE32 头：

- 本体：`SizeOfImage=0x00173000`，`AddressOfEntryPoint=0x0010F0EF`
- 外传：`SizeOfImage=0x001A5000`，`AddressOfEntryPoint=0x00127BCF`

匹配成功后才进入对应后端。后端内部仍继续执行原有内容签名验证，因此 PE 身份只是第一层保护，不取代深度验证。

### 4.3 ModuleRegistry

所有官方功能都是内部 Module，不再以“一个功能一个 ASI”发行。当前只有：

```text
DisplayFix
```

下一阶段会增加：

```text
Controller
```

之后 QoL、背包、掉落、自动拾取等都继续注册到同一个 ModuleRegistry。

`v0.1-dev1` 已加入模块级故障隔离：某一个可选模块初始化失败，只把该模块标记为未初始化，Registry 仍会继续尝试后续模块；不能因为 DisplayFix 某个签名失败就让未来的 Controller/QoL 整体失去加载机会。`ModuleRegistry_IsInitialized()` 可供后续模块查询前序模块是否真正成功。

### 4.4 HookManager / EventBus

`HookManager` 建立“一个物理游戏 Hook 只能有一个提供者”的硬规则。当前 DisplayFix 仍负责安装它已经实机验证过的物理 Hook，以避免本轮大范围重写；但这些公共入口已经登记到共享 Hook 管理体系。

Hook 声明还增加了初始化回滚：如果一个模块已经 Claim 了前几个共享 Hook、后面的 Claim 却发生冲突，必须通过 `HookManager_ReleaseOwned()` 把本模块尚未真正投入运行的 owner 槽全部清掉，不能留下“模块没启动但 Hook 被占住”的假状态。

当前已广播的第一批语义事件：

- `RUNTIME_EVENT_GAMEPLAY_ENTER`
- `RUNTIME_EVENT_GAMEPLAY_EXIT`
- `RUNTIME_EVENT_UI_DRAW_BEGIN`
- `RUNTIME_EVENT_UI_DRAW_END`

下一阶段手柄支持若需要这些生命周期，必须订阅 EventBus，不允许再次 Hook Strategy/UI Draw。

注意：**v0.1-dev1 是共享 Hook 基础设施的第一阶段，不代表所有 DisplayFix 物理 Hook 已经搬进 Runtime。** 当前采用“稳定后端继续装 Hook + Runtime 接收语义事件”的保守迁移方式；以后真正出现第二模块共享同一入口时，再把那个入口的物理安装器上提到 Runtime。

## 5. DisplayFix 稳定职责

统一版仍保持：

- 字体 DPI 修复与宽屏开关独立；
- 启动/标题/固定分辨率动画保持原版 FRONTEND 生命周期；
- Strategy 状态 3 才切 GAMEPLAY 宽屏；
- 返回前端时恢复原版 mode 4；
- Steam 环境延迟执行一次完整原版 JMM apply；
- 主 HUD 只在 GAMEPLAY 居中；
- 辅助 GUI 不改 X/Y、不改 child 坐标、不反算 `GetCursorPos`；
- layer1d 采用 HUD 后延迟 Draw + 单次顶层 input root 覆盖；
- 已确认独立辅助面板采用短生命周期跟踪；
- 世界点击穿透/顶部 0x0B/0x0E fallback 保留稳定实现；
- 主 HUD 居中后的 0x0B/0x0E 按压动画通过原版 root picker 路径恢复，不写 pressed 字段、不重新包装 `0x4B44F0`；
- `AuxiliaryUIAboveHUD=0` 只关闭辅助 GUI 图层；0x0B/0x0E 的按压 root 校正仍保留，因为它属于 `CenterMainHUD` 的输入视觉反馈兼容。

## 6. 外传 Steam 红线

这些行为已经由历史实机闭环，重构中禁止破坏：

1. `ResJM.Lib` 多语言后缀兜底必须保留；
2. 主 EXE `CreateFileA` IAT 不得被粗暴替换；
3. ComeOn.dll `CreateWindowExA` callback 必须识别合法 class atom；
4. 普通字符串 class 继续走官方逻辑；
5. 官方 `EDIT` HWND 记录与 `SetWindowLongA` 子类化继续保留；
6. 不恢复 test3~test9 的 DirectShow/影片实验；
7. Steam launcher 控制的开场动画不属于主 ASI 职责。

## 7. 已确认失败路线，禁止重复

### GUI/输入 test1~test7

- 把技能/物品/装备窗口整体搬进 4:3 安全区；
- 根据旧坐标反算 `GetCursorPos`；
- 手工补 `self+0xA8`；
- 包装含隐藏 ESI 语义的 `0x4B44F0`；
- 逐按钮修重叠区；
- layer1b 写 `manager+0x18/+0x1C` 与 `object+0x08/+0x0C` 重排顶层双向链。

layer1b 实机日志已经证明其双向链边界假设错误，运行时直接 fail-open 回退 layer1a，因此不能再从该方向继续。

### 分辨率/JMM历史失败

- 把隐藏 1024×768 分支当第三个用户菜单模式；
- 初始化阶段过早完整重放 JMM；
- 只广播顶层 UI `vtable+0x14` 尺寸；
- 用 HUD/world 对象生命周期猜 GAMEPLAY；
- 只改 profile 字节但不强制当前 live Surface 重建。

### 外传 Steam 历史失败

- 把所有问题归因于 delayed JMM；
- ActiveMovie watchdog；
- 在错误进程/实例里追 DirectShow；
- 带 relocation 的绝对地址运行时签名；
- 完全禁用官方 EDIT WndProc。

## 8. 当前阻塞项

1. **统一 ASI 本身尚未实机测试。** 虽然静态链接/构建通过，但必须分别在本体、外传至少启动一次确认 Profile 识别和后端选择正确。
2. 本体建议复测：16:9 宽屏、物品/装备/技能、关闭物品但保留装备面板、返回主菜单，并专门确认属性/物品两个顶部圆形按钮的原版按下动画已经恢复。
3. 外传需要完整回归：非 Steam（如可用）、Steam、多语言、OpenGL/cnc-ddraw、Strategy 进出、GUI。
4. 32:9/8:9/40:9 的 8 像素新宽度尚未逐个复测；不影响统一架构，但属于显示修复剩余验证。
5. 下一阶段 Controller 还未实现；只能在本版 Runtime/EventBus/HookManager 基础上继续。

## 9. 下一步

推荐顺序：

1. 用户实机验证 `BladeSwordQOL v0.1-dev1` 在本体能达到原 stripe1/layer1d 等价效果，并确认 0x0B/0x0E 顶部按钮按压动画恢复；
2. 同一 ASI 放进外传验证 Profile 自动识别和 Steam 红线；
3. 通过后将 v0.1-dev1 设为统一 Runtime 基线；
4. 直接新增 `Modules/Controller/`；
5. 先逆向并建立唯一 Input Frame 共享 Hook，再通过 EventBus/Runtime Input Service 给 Controller 与后续 QoL 共用；
6. 新模块不得直接修改已经登记的共享 Hook callsite/vtable。

## 10. 构建与发布规则

- 构建产物统一在 `release\`；
- release 严格只有 `BladeSwordQOL.asi` 与 `BladeSwordQOL.ini`；
- 所有文档只允许放在 `docs\`；
- 所有文档文件名使用简体中文；
- 代码文件名英文；
- 代码内部必须保留面向初学者的详细中文行内注释；
- BAT UTF-8 无 BOM + CRLF，首行 `chcp 65001 >nul`；
- Win32/x86、PE32、DLL、非零入口、`InitializeASI`、Import Directory=0；
- 每次修改文档必须遍历全部 docs 同步结论；
- 每个源码包和编译测试包都必须携带截至当前版本的完整接档信息。
