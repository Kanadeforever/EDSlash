# 设置界面文字维护说明

## 设置项目名称和说明

真实来源是source/src/Runtime/Config.c开头的fields描述表。项目名字是label，说明是description。界面和默认TOML说明使用同一份描述表。

B和N形式的项目，第四个参数是名字，第五个参数是说明；完整结构形式的项目也在table/key之后依次放名字和说明。例如HUD居中和辅助界面层级都在这张表里。七个世界键位使用K宏，名字在各K调用的第三个参数中，说明在K宏中按项目编号分别选择，WORLD_KEYS_HELP是七项共用的改键说明。防御/恢复百分比使用P宏，名字在各P调用中，说明根据项目编号选择。

后续只改名字与说明文字即可；配置table/key、编号、范围、默认值和枚举继续保持现值。名称建议简短，说明按“做什么—开启/关闭或大小的差别—什么时候生效”写。用玩家看得到的名字解释，例如生命条、背包、快捷栏，不用绘制帧、HUD层级、Runtime等实现名词。

## 窗口操作文字

source/src/Runtime/SettingsWindow.c包含三个页签名字、保存/关闭/说明按钮、数值调整提示、技能候选按钮与弹窗标题；候选说明常显，取消左右手选择。value_text负责设置值的界面文字，包括大写手柄键、自动拾取类别和模式名称；文件中的a/b/face等枚举仍保持原来的小写格式。

保存错误的具体原因由Config.c生成，例如重复键位、文件被外部修改和无效值；SettingsWindow.c负责把原因放进正中间窗口。修改这类文字时保留对应失败条件的含义。

## 技能名称和说明

技能名及技能说明读取原游戏数据，不在上述自定义项目说明中手写。SettingsWindow.c调用原姓名函数和技能页悬停说明函数，保留当前角色已学技能的实际内容。四版本的函数地址由source/tools/controller/profiles.json登记，通过generate_settings_profiles.py生成SettingsData.h。普通文案编辑不用改地址表或生成头文件。

## 配置模板与更新

source/config/EDSlash.toml是描述表生成的默认配置，不是界面文案加载文件。只改TOML注释不会改变游戏内说明。已有release/EDSlash.toml和debug/EDSlash.toml保留用户数值/绑定及注释，构建只补新增配置键。

修改Config.c或SettingsWindow.c后，运行source/build.bat重新生成发行和debug；两件来自同次优化链接。默认模板会重新生成，包里带上当前源码和docs即可独立继续编辑。自有文件保持UTF-8无BOM和CRLF。构建方法仍见source/readme.md，不另设构建入口。
