# EDSlash

> 为《刀剑封魔录》与《刀剑封魔录外传：上古传说》制作的现代化、显示兼容与 QOL 改进模组，提供针对游戏原生流程适配的手柄操控。

EDSlash 是一个面向这两款游戏 Windows 版的非官方开源项目。

项目希望在尽量保留原版规则、资源和操作逻辑的前提下，改善现代环境中的显示与游玩体验。显示修复、生活品质功能和手柄控制集成在一个 `EDSlash.asi` 中，共用配置、日志和运行时基础设施。

目前主要包括：

- 扩展世界可见范围的宽屏显示、主界面居中和字体 DPI 修复；
- 基于 SDL3 的手柄输入，以及针对战斗、调查、菜单和物品界面的专门适配；
- 快捷技能、连招切换、必杀准备、投掷、药品与方向闪避；
- 地面物品名称、分类自动拾取和拾取提示；
- 角色创建时的随机姓名，以及外传的随机生日；
- 游戏内模组设置、插件 TOML 配置与独立保存的角色技能绑定；
- 配套的逆向资料、验证工具和完整开发接档文档。

本项目不提供游戏本体、原版游戏可执行文件或受版权保护的原始游戏资源，请自行准备游戏。

**当前项目仍为开发版，尚不能视为两作、四个发行版本和全部流程均已完成实机验收。**

`main` 分支每次更新后，GitHub Actions 会自动构建、执行离线验证，并更新 [dev-auto 开发版](https://github.com/Kanadeforever/EDSlash/releases/tag/dev-auto)。也可以在 [Actions 页面](https://github.com/Kanadeforever/EDSlash/actions/workflows/build.yml) 手动运行构建；只有 `main` 的成功构建更新公开开发版，其它分支仅提供构建附件。

下载后保留 ZIP 的文件与目录结构安装，具体步骤见下文。自动构建只验证构建与离线行为，不代表实机验收完成。源码仓库中的 `release/` 为本地构建输出目录，不纳入 Git；源码构建方法见下文。

## 功能介绍

### 显示与平台兼容

显示模块在游戏世界中扩展可见范围，标题、主菜单和固定分辨率动画保留原版 4:3 流程。

主要提供：

- 自动或手动指定画面比例；
- 可配置的世界逻辑高度；
- 主 HUD 居中及辅助界面层级协调；
- 游戏字体创建链的局部 DPI 修复；
- 针对 Steam 版的资源和窗口兼容处理。

逻辑高度决定世界视野和绘制负担，并不等于最终输出分辨率。通常使用 480 或 600，再交给显示兼容层放大；直接提高到桌面分辨率可能明显增加老游戏的负担。

项目包含与 cnc-ddraw 配合使用的研究和实机记录。显示比例、字体、Steam 多语言资源以及 OpenGL 兼容的准确边界见 [显示与平台兼容说明](docs/文档/显示与平台兼容说明.md)。

### 手柄控制

手柄模块使用仓库内的完整 **SDL 3.4.16** 源码静态构建，输入处理按游戏状态分别适配。

当前实现覆盖世界移动、战斗动作、连招、技能快捷、投掷与药品、调查与 NPC 对话，以及标题、读档、任务日志、物品与交易等多类原生界面。

部分默认操作如下；完整组合键、适用场景和可改绑规则请查看对应文档。

| 输入 | 默认用途 |
|---|---|
| X / Y | 左手动作 / 右手普通技能或连招 |
| RT + 技能键 | 当前角色已绑定的快捷技能；未设置的位置不发动技能 |
| RB / LB + 槽位键 | 投掷 / 使用药品 |
| LT + Y / B / A / X | 切换第 1 / 2 / 3 / 4 套连招 |
| LT + RT + A / B / X / Y | 必杀准备，再次新按同键释放 |
| LT + RT + L3 / R3 | 分别展开左侧／右侧技能菜单，同一时间只展开一个 |
| 技能菜单内推动摇杆 | 默认左摇杆导航左侧、右摇杆导航右侧；可改为左摇杆或右摇杆导航全部 |
| BACK + START | 救援鼠标模式 |

手柄动作尽量交由游戏原版流程完成资格检查、消耗和执行。界面导航、世界键位改绑与菜单确认取消交换分别处理。

详细操作见 [手柄战斗与动作说明](docs/文档/手柄战斗与动作说明.md)、[手柄菜单与物品界面说明](docs/文档/手柄菜单与物品界面说明.md) 和 [世界调查与交互说明](docs/文档/世界调查与交互说明.md)。

### 生活品质改进

QOL 模块提供地面物品名称、分类自动拾取与成功提示。距离、容量、入包、音效和地面物品删除继续使用原版逻辑，自动拾取还会检查掉落动画和等待时间。

角色创建中可通过键盘 **F1** 或手柄 **Y** 更换随机姓名；新流程空名可自动填写，已有手工名称保留。外传同时提供随机生日，最终创建仍由玩家确认。

随机姓名当前写入链要求系统代码页为 936；不满足条件时保留原文，避免写入乱码。

详细说明见 [自动拾取与地面物品名称说明](docs/文档/自动拾取与地面物品名称说明.md) 和 [随机姓名功能与接入说明](docs/文档/随机姓名功能与接入说明.md)。

### 游戏内模组设置

设置入口包括：

- 原游戏设置页中的 **EDSlash 设置**；
- 手柄 **LT + RT + BACK**；
- 键盘物理反引号键。

设置窗口提供模组功能、按键与当前角色技能绑定页面，支持手柄和鼠标操作。手柄键位页可左右翻到第五个状态“鼠标救援模式”，查看鼠标控制和切换条件。**START 保存**，BACK 可恢复当前项或经确认恢复本页默认值；重置后仍需保存。

技能快捷键独立保存在 ASI 同目录的 `EDSlash.SkillContols.toml`（文件名按此拼写）。保持默认时不创建；首次保存自定义技能后才创建。按可选角色／职业编号分组，同职业的不同存档共用设置。更新时保留这个文件，发行包不会附带它。文件顶部区分 `DaoJian` 和 `WaiZhuan`；版本不匹配时旧文件会改名备份，已有备份不覆盖，当前游戏恢复未设置。旧主配置中的技能绑定会自动迁移，迁移前主文件保留为 `EDSlash.toml.skills-migration.bak`。

配置保存与实际生效分开处理：部分设置在下一输入或绘制边界应用，运动相关设置需等待输入释放和原动作结束，显示安装、逻辑高度、比例和字体修复需重启游戏。手工修改 TOML 后也需重启。

完整键位、配置范围和生效规则见 [统一配置与模组设置说明](docs/文档/统一配置与模组设置说明.md)。

## 安装与配置

1. 准备对应版本的游戏，先备份存档和现有模组配置。
2. 准备可在该游戏进程中加载 **32 位 ASI** 的加载器。EDSlash 本身是插件，具体搜索目录与启动方式由所使用的加载器决定。
3. 将发行 ZIP 解压到加载器实际扫描的目录，保留 `LICENSE.txt`、`第三方声明.txt` 和 `licenses/` 目录。
4. 停用旧独立 Controller 和与统一插件功能重叠的旧插件，避免重复修改同一处游戏逻辑。
5. 启动游戏后检查 `EDSlash.log`，确认当前版本识别和模块初始化情况，再按实机清单测试。

只安装一份 EDSlash：日常使用 `EDSlash.asi`。自动发行包不含 debug；需要排查问题时可在本地构建后，将正式件替换为本地产物 `release/debug/EDSlash_debug.asi`，两者不能同时加载。调试件仍使用 `EDSlash.toml` 和 `EDSlash.log`，配置放在 ASI 旁边。

**SDL 已静态链接，不需要另行放置 `SDL3.dll`。** 第三方加载器或显示兼容层的依赖仍由对应项目说明决定。

配置缺失时生成默认值；损坏配置不会被静默覆盖。构建更新发布配置时只补充缺失的段或键，保留已有数值、绑定和注释。

## 从源码构建

插件必须构建为 **Win32 / x86**，与游戏进程位数一致。

当前构建环境需要 Windows、Python 3.11 或以上、CMake 3.21 或以上、Ninja、Visual Studio／Build Tools 的 MSVC C++ 与 Windows SDK（支持 Win32 / x86） 和 UPX。

在仓库根目录执行：

```powershell
python source/tools/build.py
```

也可以双击 `source/build.bat`。命令行无需暂停时使用：

```bat
source\build.bat --no-pause
```

仅执行检查、不更新发行目录：

```powershell
python source/tools/build.py --checks-only
```

构建器通过 `vswhere` 和 `vcvarsall` 探测原生 MSVC 的 x86 编译环境；CMake、Ninja 和 UPX 使用当前环境中的工具，UPX 也可通过 `UPX_BIN` 指定。构建过程不会自动下载或安装依赖。

发行件与调试件来自同一次优化链接：发行件剥离符号并使用 UPX 压缩，调试件保留源码调试信息。构建会执行离线回归、PE 与依赖检查、配置校验和非游戏加载检查，通过后输出至 `release/`，验证摘要写入 `release/统一构建验证.json`。

公开源码不附带游戏 EXE。没有完整四份样本时，涉及真实 EXE 的复核会明确跳过，不影响源码构建，也不能据此宣称四样本检查通过。

工具探测、详细参数、SDL 构建选项和产物规则以 [source/readme.md](source/readme.md) 为准。

### 自动构建与打包

工作流位于 [.github/workflows/build.yml](.github/workflows/build.yml)。Windows runner 安装 Python、32 位 MinGW、CMake、Ninja 与 UPX，然后调用相同的 `source/tools/build.py`。SDL 直接编译仓库内 `thirdparty/SDL-release-3.4.16/`，不另取运行库或上游源码。

本地构建仍生成并验证发行与 debug 两件；自动打包使用明确文件清单，只收集正式 ASI、默认 TOML、项目许可证、独立第三方声明和各组件的许可证原件副本；许可证文件按原始字节复制。验证报告仅用于打包核对，源码、完整 SDL、文档和工具继续保留在仓库中。ZIP 完整性与散列检查在 runner 内完成，公开附件只有这一个 ZIP。

如需在本地生成相同结构的发行包，先完成正式构建，再执行：

```powershell
python source/tools/package_release.py --output .workspace/release/EDSlash-dev-auto.zip
```

打包会核对正式 ASI、默认配置与构建报告；源码变化或发布配置包含个人修改时会拒绝打包。构建失败不会进入发布任务，上一份开发版保留。

## 开发原则与参与方式

项目优先复用游戏原生动作、菜单和资源协议。公共运行时统一管理 Hook、输入阶段、配置和日志；业务模块维护自身职责，关键地址和签名不满足条件时拒绝对应能力。

欢迎提交问题报告、实机测试结果、逆向证据复核、文档修正和代码改进。修改核心 Hook 前请阅读对应技术文档与完整接档，保留已验证行为及必要的失败处理。

问题反馈请提交到 [Issues](https://github.com/Kanadeforever/EDSlash/issues)，尽量包含：

- 操作系统、游戏名称、Steam / 非 Steam 来源及 EXE 的 SHA-256；
- 使用的发行包、提交号或下载日期，以及发行件 / 调试件；
- 加载器、显示兼容层和其他模组；
- 对应 `EDSlash.toml`、启用日志时生成的 `EDSlash.log`；
- 角色、地图或菜单、复现步骤、预期结果与实际结果；
- 手柄问题所涉及的设备型号、按键与具体操作场景；
- 视觉或崩溃问题对应的截图、异常记录或转储（如有）。

请明确哪些结果来自静态检查、离线回放或真实游戏，避免把局部成功扩大为全部版本支持。
