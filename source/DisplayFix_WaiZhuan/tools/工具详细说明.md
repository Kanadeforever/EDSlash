# 工具详细说明

## verify_build.py

只读检查最终 `DisplayFix.asi`、INI、源码边界和仓库编码规范，不运行游戏也不改游戏文件。

当前检查：

- PE32 / i386；
- DLL 标志；
- 非零入口点；
- `InitializeASI` 导出；
- Import Directory=0；
- `DisplayFix.ini` UTF-8 无 BOM；
- 仓库文本 UTF-8 BOM=0；
- BAT 必须 UTF-8 无 BOM + CRLF；
- `build.bat` 禁止递归误选 ARM64 LLVM，并要求固定 x64 LLVM 回退；
- `Font.FixDPI` 必须在 `Display.Enable` 提前退出前独立执行；
- v0.2.0 必须继续存在 test4 的 `steam_create_file_a_shim` / `install_steam_resjm_language_shim`；
- 语言兜底仍只能改 CreateFileA 低层调用点，不能覆盖 `0x005511E4` IAT；
- v0.2.0 必须存在 `install_steam_createwindow_class_atom_guard` / `steam_createwindow_class_atom_guard`；只允许在 `RVA 0x2841` 前置 class-atom 判断，官方 EDIT WndProc 路径必须恢复；test1 的全 callback neutralize 和 test2 的 `RVA 0x2889` JNE->JMP 均不得保留；
- test3~test9 的 DirectShow aspect patch、ActiveMovie watchdog、MovieManager takeover、teardown bypass、worker quarantine 等历史失败入口不得回到当前源码。

这个验证器现在锁定的是“clean1 稳定主体 + test4 语言兜底 + CreateWindowExA class-atom guard”，防止 test1 过宽代码或 test3~test9 旧影片实验重新混入。

## verify_compatibility.py

对一个或多个外传 `ComeOn.exe` **以及 Steam `ComeOn.dll`** 做只读结构验证。验证依据是机器码内容、调用关系和 Hook/vtable 结构，不用整个 EXE SHA-256 白名单锁版本。

当前检查：

- 字体 DPI 原始/已修复上下文；
- 显示模式函数和三处分辨率逻辑；
- 同 mode + force=0 早退；
- 原版前端 mode 4；
- Strategy enter/exit callsite；
- JMM 选择器、UI 广播和资源路径链；
- 主 HUD 构造/vtable/layout；
- 顶部 0x0B / 0x0E 原版窗口分支；
- world press / global release 输入链；
- clean1/test4 Steam 多语言兜底所依赖的唯一 CreateFileA 调用上下文，并报告实际 VA；
- 对 Steam `ComeOn.dll` 验证：CreateFileA 官方 Hook 安装块、CreateWindowExA Hook 安装块、callback `RVA 0x2830/0x2841`、EDIT WndProc 子类化链，`RVA 0x2841` 的 lpClassName 读取/直接字符串解引用，以及 `RVA 0x2889` 原始 EDIT 子类化链。

它不会证明 OpenGL 实机稳定性；DLL 验证只说明 v0.2.0 的 `RVA 0x2841` class 解析路径和后续官方 EDIT 子类化结构仍匹配当前样本。

## verify_compatibility.bat

Windows 拖拽入口。把一个或多个 `ComeOn.exe` 拖到 BAT 上，会依次调用 Python 验证器。

BAT 同样必须 UTF-8 无 BOM + CRLF。

## FontFix_WaiZhuan

`source\FontFix_WaiZhuan\apply_dpi_font_fix.py` 与 `apply_fix.bat` 是独立 96 DPI 字体补丁器。它按机器码上下文识别字体 DPI CALL，可以脱离 DisplayFix.asi 使用。算法在 clean1、v0.2-test1、v0.2-test2 和 v0.2.0 都没有变化。


## v0.2.0 封版验证边界

`verify_build.py` 会确认正式源码仍然只保留已实机闭环的 class-atom guard，不允许 test1/test2 的大范围窗口隔离或 test3~test9 的影片实验重新进入运行路径。`verify_compatibility.py` 会继续检查 Steam ComeOn.dll 的 `RVA 0x2841` 原始 class 参数解析结构和后续官方 EDIT 子类化结构，确保正式修复只增加 API 参数语义保护。
