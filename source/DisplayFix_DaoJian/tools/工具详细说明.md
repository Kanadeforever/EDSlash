# 工具详细说明

## v0.3.2 日志中文化验证

- `verify_build.py` 新增运行时字符串检查：只分析 C 字符串字面量，历史注释中的旧英文日志不会被误判。
- 当前 ASI 必须包含中文日志等级 `[成功]/[信息]/[失败]/[运行]`，并且运行时字符串中不得再出现 `[OK]/[INFO]/[WARN]/[FAIL]/[RUNTIME]`。
- `build.bat` 还必须显式包含 `-finput-charset=UTF-8 -fexec-charset=UTF-8`，保证中文日志在不同 Windows 代码页下仍写出一致 UTF-8 字节。
- 本轮不新增 EXE/DLL 机器码兼容条件，原兼容验证范围全部继承上一正式版。


## v0.3.1 新增防回归检查

`verify_build.py` 现在额外检查 `initialize_display_fix()` 的配置顺序：必须先执行 `Font.FixDPI` 和 `apply_font_dpi_fix()`，之后才能进入 `Display.Enable=0` 的提前退出。这样以后重构时不会再次让“关闭宽屏”意外关闭字体修复。

本目录固定只放 DisplayFix 主工程的 `verify_` 工具与本说明；独立字体永久补丁仍放在 `source\FontFix_DaoJian\`。

## verify_build.py

只读验证构建成品和构建脚本：

- PE32 / i386；
- DLL 标志；
- 非零入口点；
- `InitializeASI` 导出；
- Import Directory=0；
- `DisplayFix.ini` UTF-8 **无 BOM**、固定 ASCII 首行和关键键；
- `build.bat` UTF-8 **无 BOM** + CRLF；
- 禁止 `where /r` 与 ARM64 LLVM；
- VS fallback 必须为 `VC\Tools\Llvm\x64\bin`；
- 所有有正文的 REM/echo 行末尾两个半角空格；
- 仓库 `source/docs/release` 中可编辑文本统一扫描，UTF-8 BOM 必须为 0。

## verify_compatibility.py

只读检查 ComeOn.exe 结构，不用整文件 SHA-256 白名单。v0.3.2 继续沿用 v0.3.1 / v0.3-test15 的验证集合；本轮日志中文化不新增机器码要求：

- 字体 DPI 原始/已永久修复两种状态；
- `0x00404D7A` 分辨率模式派发；
- `0x00404D30` 原版显示模式函数；
- **同 mode ID + force=0 的早退结构**；
- 两处分辨率映射 `0x00470C3E / 0x0047B0AB`；
- JMM 选择器 `0x004B363B`；
- Strategy 状态函数 `0x00404A00`；
- Strategy enter `0x00404A97 -> 0x00407000`；
- Strategy exit `0x00404A1E -> 0x00407040`；
- `0x0040700F -> 0x00404D30` 交叉关系以及 `6A 00` force 入口；
- **test15 新增：原版启动前端 `0x004053D8` 的 mode 4 应用，并要求其 CALL 同样指向 `0x00404D30`**；
- `0x004087A0 -> 0x004B35F0` 与资源根构造链；
- 主 HUD 构造/vtable、0x0B/0x0E 分支、`+0x58` 布局；
- world press 与 global release 输入链。

### test12 留下的逆向数据

world global/构造/析构地址已经记录进《逆向工程知识库.md》，但工具和 ASI不再把 world 是否非空作为 gameplay gate，因为用户实机证明主菜单也持有它。

## 本轮验证样本

v0.3.2 继续沿用 v0.3.1 已验证集合：当前永久 96-DPI ComeOn.exe、ComeOn480P、540P、720P、768P、900P、1080P 全部通过静态结构验证；test15 的 480 高两阶段生命周期仍是已实机通过的稳定基线。本轮另增加 FixDPI/Display.Enable 初始化顺序防回归。
