# 工具详细说明

本目录固定只放 DisplayFix 主项目的三个 `verify_` 工具和本说明。

## verify_build.py

只读检查构建后的 `DisplayFix.asi`、同目录 INI 和 `build.bat`，不运行 ASI。

检查：

- PE32 / i386；
- DLL 标志；
- 非零入口点；
- `InitializeASI` 导出；
- Import Directory=0；
- `DisplayFix.ini` 可解析、[Display] 前 BOM 保护行、关键键存在；
- `build.bat` 为 UTF-8 BOM + CRLF；
- 禁止 `where /r` / ARM64 LLVM；
- Visual Studio LLVM 回退必须是 `Llvmdin`；
- 所有有正文的 REM/echo 行末尾两个半角空格。

## verify_compatibility.py

只读检查新的 ComeOn.exe 是否保留 DisplayFix 所依赖的机器码/结构，不按整个 EXE SHA-256 白名单判断。

当前主要验证：

- 字体 DPI 原始/永久修复两种合法状态；
- 分辨率模式派发 `0x00404D7A`；
- 从该签名向前解析并验证原版显示模式函数 `0x00404D30`；
- 两处分辨率映射 `0x00470C3E / 0x0047B0AB`；
- JMM 选择器 `0x004B363B`；
- `0x004087A0 -> 0x004B35F0` JMM 包装关系；
- `0x004B35F0 -> 0x004EB9E0` 资源根构造、资源根指针解析；
- 主 HUD 构造/vtable；
- test11 新增：主 HUD vtable `+0x00` destructor 必须保持 `push esi / mov esi,ecx / call real-dtor` 已确认形状；
- 主 HUD `+0x24` 0x0B/0x0E 原版窗口分支；
- 主 HUD `+0x58 -> 0x004B2B90` 布局关系；
- 世界输入 `0x004060EB -> 0x00473F10`；
- 全局 release `0x00406086 -> 0x004B4560`。

test11 之所以新增 `0x00404D30` 与 HUD destructor 验证，是因为前端/gameplay profile 需要在 HUD 出现时安全重应用显示模式，并在 HUD 生命周期结束时恢复前端代码规则。

## verify_compatibility.bat

Windows 拖拽入口。可把一个或多个 EXE 拖到 BAT 上，逐个调用 `verify_compatibility.py`。

## 独立字体修复

```text
