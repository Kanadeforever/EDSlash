# 拾取提示验证工具

运行source/build.bat --checks-only完成MSVC编译后，在项目根执行ctest --test-dir .build/msvc -R test_notice --output-on-failure；也可直接运行.build/msvc/test_notice.exe。使用同一MSVC Win32工具链，不依赖固定本机路径。

统一构建将test_notice.c编译为.build/msvc/test_notice.exe，只运行自有测试进程，使用原版函数替身和有界内存读取。验证库存增长、金钱增长、未入包不提示、名称预复制、GBK安全截断、6条队列、5秒过期/时钟回绕、场景隔离和原版文字调用参数。成功提示宿主483项通过不代表游戏UI已实机。

如果参考资料中的两份非Steam基线存在，随后只读核对PickupNotice.c中各作五个原版入口的12字节签名；缺少基线时跳过样本检查并明确打印，源码构建不下载游戏。原始EXE不被修改。完整原版控制流证据可用Controller目录的trace_native_actions.py导出到docs，不可输出到参考资料。

新增生产源在source/src/Modules/QOL/PickupNotice.c/h，接入QOLModule和主build.bat；所有测试输出在对应.build子目录，不能清空共享release或其他模块的构建输出。

分帧定位回归test_autopickup.c纳入统一CTest，使用宿主VirtualAlloc连续登记表验证每帧1024槽/6144字节、完整唯一性、代数和切表失效，原动作22和过滤保持；不读写游戏进程。
