# 技能状态资源核对工具说明

audit_skill_states.py使用Python标准库，只读本体与外传各自的mb.fol，不启动或附加游戏，不修改原资源，不生成图片。用于完整复核各职业技能的等级记录、选择码、动作、效果、前置窗口、事件和显式后继。

在项目根目录执行，路径按实际安装位置替换：

```powershell
python source/tools/controller/audit_skill_states.py --base-fol "本体安装目录/mb.fol" --expansion-fol "外传安装目录/mb.fol"
```

默认输出.build/skill_state_audit，可用--output指定其它派生目录。输出禁止位于参考资料、archive或任一游戏输入目录内。反复执行会更新指定派生目录的同名文本文件，因此输出位置应专用于本工具。

工具读取前后核对源文件长度、修改时间以及两次完整SHA256，拒绝复制中变化的输入。所有FOL目录项检查边界，选定正文按原加密布局解码成UTF-8无BOM、CRLF文本。源内容不会写回。

输出内容：

- 原始派生/本体与原始派生/外传：七份技能相关文本，以及各自的资源来源与校验.json。
- 双作品职业技能状态审计.json：完整等级行、职业、组、窗口、动作字段、事件、Method／Effect可达图、循环／缺失引用、全部重复候选和按首条生效计算的有效图。

每条子命令保留八个整数：第1项是触发事件类型，第2项是触发参数，第3项才是操作码。不能把操作码4当成事件类型4，也不能把周期更新计数当真实毫秒。引用图递归处理code9到Method、code2到Effect，其他操作码隐含对象生成及外部脚本不在覆盖内。

原生样本按源行顺序插入且同编号已占用时拒绝覆盖，所以有效图取首条，原始重复仍完整保留。不可用字典取最后一条，也不可将两条内容合并成同一个生效动作。技能表同一ID也可能用于不同基础动作，工具按源行和选择码保存。

已核对输入应得到本体127行／79选择码、外传212行／122选择码；外传包含长老和老英雄。与文档基线散列不同的MOD或其它版本，应先核查运行程序、资源布局和加载策略，不把结构解析成功当作版本身份一致。资源特征可以重叠，不能直接当作整招的互斥类型，更不能替代全职业实机验证。
